# WP10 Website: configurator, previews, telemetry client, admin portal

Wave 1, after WP01 has merged (catalogue v2). The final run needs WP09 merged (API v1); until then develop against the
JSON shapes in MASTER-PLAN A1.9 and A10 and WP09's handoff. Next.js 15, React 19, TypeScript; no new runtime
dependencies.

## Why

The configurator and the generator disagree on what a valid project is (unticking leaves dependents on, missing
validation, a keyword list that does not match); previews drift from the template; catalogue keys index hand-written
maps, so a new style crashes the Look step; every keystroke re-renders the whole landing page; accessibility state is
missing; the admin shows eight all-time widgets under a "last 30 days" header (audit web-frontend). The overhaul adds
a platform picker (Android Native, Compose Multiplatform, Swift coming soon), new features (glass, architecture), and
much richer anonymous telemetry.

## Steps

1. **Structure** (A10.4): split `configurator.tsx` into `features/configurator/{state,resolve,validate,request}.ts`,
   `steps/*Step.tsx`, `useConfigurator.ts`; previews into `features/preview/`; admin into `features/admin/`; the landing
   page becomes server components with one client island; `/admin` gets `robots: noindex`.
2. **Catalogue**: the site imports the checked-in `lib/catalogue.json` (Vercel previews build without Python);
   `npm run catalogue` is a convenience that runs `python3 -m genkit.core.catalogue --write` from the generator; a
   runtime guard validates the shape of the live catalogue; styles, tokens, rules and fields come only from the
   catalogue (F2).
3. **Platform step** first: three cards from `/api/v1/targets` (or the checked-in catalogue): Android Native, Compose
   Multiplatform (showing its `status_note` while `status` is `beta`, and its "not in v1" list), Swift as a disabled
   "Coming soon" card. Switching platform swaps features, fields and styles and keeps
   compatible answers. The Build step asks for the architecture (Compact default, Modular) on Android.
4. **Correctness**: `resolveFeatures` closes over `requires` both ways (unticking removes dependents, with an undo
   hint; F1); preset derived from the resolved set (F35); `targetSdk ≥ minSdk` (F3); version name and hex validation
   (F4); reserved words and limits from `catalogue.rules` (F5, F6); `display_name` with Unicode (F33); a warning for
   `com.example.*` ids (F34); review falls back correctly when settings is off (F36); stale "done" cleared on edit (F38).
5. **Validation parity**: `validate.ts` runs every case in `generator/tests/fixtures/validation_cases.json` in a
   `node --test` test and must agree with Python on accept/reject and the error field.
6. **Previews** (F7–F9, F32, glass): theme from `catalogue.tokens` with the brand ramp ported from `brand.py` (golden
   test against 200 seeded colours produced by a Python helper); content scrolls under an absolutely positioned tab bar;
   push slides without dimming, tab switches are instant; scaffolded modules appear as tabs up to five; glass emulated
   with `backdrop-filter` only in the single live preview and as drawn glass in thumbnails; the Build step states
   "frosted (no blur) below Android 12" when glass is on; haptics switch reflects the Motion step (F37).
7. **Performance and a11y**: configurator state kept inside the island (no landing re-render per keystroke, F10);
   `next/font`, one stylesheet per chosen family and only the weights used (F8, F12); the live preview scaled to fit at
   360 px and sticky without an `overflow-hidden` ancestor (F13, F14); `aria-pressed`/`aria-checked`/radio semantics
   on every toggle-like control (F15); contrast tokens fixed (F16); `<dialog>` with focus trap and return (F24);
   `MotionConfig reducedMotion="user"` (F25); dead code and slop comments removed (F41, F42); `next lint` script removed.
8. **Draft and telemetry client** (A10.2, A10.4): the configuration is saved to `localStorage` on change and restored
   on the next visit, with a "Start over" action; one `track()` that batches to `/api/v1/events`; `session_id` (UUID
   v4) in `sessionStorage`; `returning` is true exactly when a saved draft existed at load (no other storage, no date,
   no identifier); UTM and referrer origin on `landed`; `step_viewed:<step>` on each step; the generate call sends
   `X-Session-Id`, `X-Config-Ms` (identity step to `generate_clicked`, capped at 2 h) and
   `X-Client: android-base-web/<build>` (A10.1), built by `request.ts` and tested against WP09's
   `generate_headers.json`; `window.onerror`/`unhandledrejection` → `/api/v1/client-error`; honest privacy
   copy (it names exactly what the browser stores: the session id in `sessionStorage` and the draft in
   `localStorage`) and a footer link to the privacy page (F17).
9. **Admin portal** (A10.3): global date range and filters, the nine panels with hand-rolled SVG small multiples (admin
   chunk only), paginated generations table with row details and CSV export, only 401 logs out (F26), mutations check
   `response.ok` and update locally (F27), server-side status filter for reports (F28), tracebacks expandable (F29),
   clearable notes, no orphan grid cell (F39).
10. **Copy**: remove "its own ripple", "nothing stored" and "Everything is MIT" claims that the overhaul makes false
    (F44, F17); every claim must match the catalogue and template.
