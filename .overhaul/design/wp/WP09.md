# WP09 Web API (Go), container and telemetry store

Wave 0 (independent of the templates). Go 1.27. The final integration test needs WP01 merged (real
`generate_headless.py` with `--target`); develop against the contract in MASTER-PLAN A1.8 with a stub until then.

## Why

One request can burn 30 s of CPU, 360 MB of RAM and 600 MB of `/tmp`; every timeout or abandoned download leaks the
generator's staging tree, including signing keys and plaintext passwords; internal generator failures are reported as
the user's fault and never reach the error list; telemetry writes sit on the response path; migrations have no version
table or lock; IPv6 visitors bypass the rate limit; cross-site "simple" POSTs run generations; UTF-8 truncation
breaks long non-ASCII reports; the Go toolchain is out of support; the request struct silently drops unknown fields,
which blocks three targets (audit web-api). The admin portal needs much richer anonymous telemetry.

## Steps

1. **Toolchain and dependencies**: `go 1.27` in `go.mod`, builder image `golang:1.27-alpine`, `pgx` and `x/*` updated,
   dead code removed (staticcheck U1000).
2. **Child process** (H2): explicit environment (`PATH`, `JAVA_HOME`, `HOME=TMPDIR=<workDir>`, `LANG=C.UTF-8`,
   `PYTHONUNBUFFERED=1`, `PYTHONIOENCODING=utf-8`, `PYTHONDONTWRITEBYTECODE=1`); the work directory is removed on every
   exit path. Test: a killed child leaves nothing outside `workDir`.
3. **Targets registry** (A10.1, M3, §6): `map[target]*Generator` with its own semaphore, timeout and cached catalogue;
   `ENABLE_TARGETS` (default `android,multiplatform`; multiplatform is served with the catalogue's `status = "beta"`
   and `status_note`, which `/api/v1/targets` returns too); `GET /api/v1/targets`, `GET /api/v1/catalogue` (computed once at
   boot from `python3 -m genkit.core.catalogue --json`, ETag + `no-cache`), `POST /api/v1/{target}/generate`; aliases
   `/api/options`, `/api/generate`, `/api/track` for one release.
4. **Opaque spec + precheck** (H1, M2, M3): the body is decoded only to check it (≤ 32 KB, depth ≤ 6, strings ≤ 256
   bytes and identifiers ≤ 120, no control characters, `feature_modules` ≤ 12, `features` ≤ 64, `languages` ≤ 10,
   `keystores` ≤ 4, `platform` equal to the route's target when present) before a semaphore slot is taken; the raw
   bytes go to Python unchanged (Python is authoritative and reports `ignored_fields`).
5. **Failure taxonomy** (H3, M4): parse the headless result; `invalid` → 400 with the message and field; `internal` →
   500 with a generic message and `RecordError(kind="generation", message, detail=traceback)`; record `outcome` ∈ `ok`,
   `invalid`, `internal_error`, `timeout`, `abandoned_queue`, `abandoned_running`, `download_interrupted`,
   `rate_limited`, plus `queue_ms`, `python_ms`, `stream_ms`, `zip_bytes`, `cold_start`, `generator_commit`.
   `generated` is recorded when the generator succeeds; `downloaded` only after `io.Copy` completes.
5a. **Session headers** (A10.1): read `X-Session-Id` (UUID v4, `fullmatch`; anything else ignored),
   `X-Config-Ms` (integer 0 … 7 200 000; otherwise ignored) and `X-Client` (≤ 64 printable ASCII) on the generate
   route, strip them before the child process (it gets only the spec on stdin), and store `session_id`, `config_ms`
   and `client` (`web` when `X-Client` names the site, `bot` by UA, otherwise `cli`) on `generations` and on the
   server events `generated`/`downloaded`/`download_interrupted`. Admin queries join a generation to its session's
   `landed` visit for geo, UTM and returning. Write `testdata/contract/generate_headers.json` (valid and invalid
   header sets with the stored values expected) and drive table tests from it; WP10 reads the same file.
6. **Telemetry** (A10.2): `POST /api/v1/events` accepting a small batch of closed-enum events with `session_id`;
   `landed` carries referrer origin, UTM (each ≤ 64), `returning` (a boolean; no first-seen date or bucket, A10.2),
   viewport bucket;
   server-side enrichment: country/region/city from `x-vercel-ip-country`, `x-vercel-ip-country-region`,
   `x-vercel-ip-city` (URL-decoded), UA → browser family, OS family, device class (`Sec-CH-UA-Mobile` when present),
   `client` ∈ web/cli/bot. No IP, no raw UA stored. Writes go through a bounded channel to one writer goroutine
   with a drop counter exposed in health (M1). Daily rollup upserted on write.
7. **Migrations** (M8): `schema_migrations(version, applied_at)`, every migration in a transaction under
   `pg_advisory_lock`, applied once; `0003_telemetry_v2.sql` (columns and `events` table of A10.2, `session_id`,
   `config_ms` and `client` on `generations`, sanitised `spec jsonb`, indexes on `(target, created_at)` and
   `(session_id)`), `0004_rollups.sql`. Existing 0001/0002 recorded as applied.
8. **Retention** (M9): an hourly goroutine deletes `requests` older than 30 days and `events`/`visits` older than 400
   days, and nulls `app_name`/`package_name` in generations older than 90 days.
9. **Security** (M7, M10, M11): `Content-Type: application/json` required (415); rate-limit and visitor keys from the
   IPv6 /64 or IPv4 address, with a configurable trusted-proxy policy (rightmost untrusted hop; Vercel and Caddy
   overwrite XFF, generic proxies append); UTF-8-safe truncation; rate limits on events, feedback and client errors.
10. **Admin API** (A10.3): `/api/v1/admin/{overview,funnel,series,adoption,failures,audience,durations,generations,
    generations.csv,errors,feedback,health}`, each with `from`, `to`, `target` and the filters (preset, outcome,
    country, device class, source); adoption left-joins the catalogue so unpicked features show 0 %; picked vs came
    with the preset from `preset_base`/`added`/`removed`; failure rate per feature on vs off and top failing pairs
    (n ≥ 5); cities only with ≥ 5 sessions in the window; CSV formula-safe (prefix `'` on `= + - @`), paginated with
    `before=<id>`; only a missing or wrong token returns 401.
11. **Container** (M12, M13): `python -m compileall` of the generator at build time; catalogue precomputed per target;
    the JRE stays only for keystore generation; `.dockerignore`/`.vercelignore` include `templates/` and exclude
    `**/DerivedData/`, `**/.build/`, `**/xcuserdata/`, `**/.swiftpm/`, `**/build/`, `**/.gradle/`,
    `**/kotlin-js-store/`; delete `web/deploy/`.
12. **Tests**: middleware (proxy policy, IPv6 /64, 415), precheck table tests, taxonomy mapping, migration runner
    (SQL statements and ordering, plus an integration test gated by `TEST_DATABASE_URL`), CSV escaping, UA classifier,
    geo header decoding, the events enum, the session-header contract fixture, and an integration test that runs the
    real generator for `android` and `multiplatform` when `GENERATOR_DIR` is set.
