# WP13 Verification matrix, CI and release

Wave 4, after every other package has merged. Python, Gradle (the heaviest: about two hours serialised for the matrix
alone), the phone (final gates), GitHub Actions. Lock budget: Gradle about 5 h, adb about 2.5 h. Pushing and merging
to `main` need the user's explicit approval at checkpoint 3 (they deploy).

## Why

The requirement is "test edge cases and all types of build options, lean to full, all combinations", and "merge to
main only when the full matrix is green". Today CI never builds the site's default preset, never runs the download
path users get, never builds the Firebase-off variants or a project with zero feature modules, and has no container
build or smoke test (audit web-api H4, M5; generator-python §6; template-build G1). Static checks cannot catch
unresolved symbols, KSP/Hilt graph errors, R8 or resource problems, so combinations must also be compiled.

## Steps

1. **Static matrix** (A12.2): extend `tests.consistency` to multiplatform and iOS checks; run the full set (every preset
   × architecture × target, every single feature on and off, pairwise, 40 seeded random subsets, hostile names, all
   languages). Fix what it finds.
2. **`tools/matrix.py`**: generates the 14 rows of A12.3 through `generate_headless.py` and unzips them (the path users
   get), runs each row's tasks through the Gradle lock, records time, result, the log path and, where the row builds
   `devRelease`, the arm64 APK size and total dex size against `tools/size_budgets.toml` (a breach fails the row) into
   `$O/matrix.md`. `--rows 3,4` reruns a subset; `--list-json` prints the 14 rows for CI; `--wide --list-json` prints
   the nightly wide matrix (every single feature on top of `lean`, every leave-one-out from `everything`,
   `standard`/`everything` modular with scaffolded modules, `design_style` × `motion_style` rotated so every pair
   appears at least once; about 70 rows of `assembleDevDebug testDevDebugUnitTest`).
3. **Run the matrix** locally (in the background, polling `$O/logs/matrix.log`), fix failures, rerun until all 14
   rows are green.
4. **Refresh the baseline profiles** on the final code: `:app:generateBaselineProfile` on `everything`, then
   `split_profile.py` into the checked-in `src/main/baseline-prof.txt` files (A5.1); rebuild row 6.
5. **Final device gates**, each one `perf.sh` invocation with `--gate`: `everything` (`--gate solid`, every
   scenario of §2), `standard` (`--gate standard`), `lean` (`--gate lean`), `everything-glass` with
   `glass.quality=Live` (`--gate glass_live`) and `Frosted` against `Solid` (`--gate glass_frosted_vs_solid`), three
   runs each; plus the Macrobenchmark journeys including `RapidBackBenchmark` and `GlassBenchmark`. Write
   `$P/summary.md` comparing with MASTER-PLAN §2 and with the WP04/WP05 numbers.
6. **Slop sweep**: `test_docs` phrase check over template code comments and docs; read every file touched by the
   overhaul for narrating comments, dead code and needless abstraction (Part D rules 4–9), fix in place. The per-merge
   reviews (A12.8) should have caught most of it; list what they missed in the handoff.
7. **CI** (A12.7), rewrite `.github/workflows/ci.yml`:
   - `generator`: unit tests, `python -m tests.consistency`, `python -m genkit.tokens --check`,
     `python -m genkit.core.catalogue --check`, `python tools/sync_check.py`.
   - `api`: Go 1.27, gofmt, vet, `go test -race`, staticcheck, govulncheck.
   - `frontend`: Node 24, `npm ci`, `tsc --noEmit`, `node --test`, `next build` (the catalogue is checked in).
   - `container`: `docker build` and `/app/server -selftest` (one zip per available target through the real binary).
   - `android-matrix`: the 14 rows from `tools/matrix.py --list-json`, generated through `generate_headless.py`, JDK 17,
     `gradle/actions/setup-gradle`, `fail-fast: false`, reports uploaded on failure, size budgets checked.
   - `android-matrix-wide`: `schedule` nightly and on the release pull request, rows from `--wide --list-json`,
     required before the merge to `main`.
   - `multiplatform-android`; `multiplatform-ios` (`macos-latest`): `brew install xcodegen`, link the framework,
     `xcodegen generate`, `xcodebuild build` for the simulator; **required** from the first release pull request.
   - `ios-swiftui` (`macos-latest`): XcodeGen + `xcodebuild build test`; not required while the target is
     "coming soon".
   - top-level `permissions: contents: read`, `concurrency` per ref with cancel-in-progress for pull requests;
     `deploy` needs every required job and smoke-tests the deployed URL (`/api/v1/targets`, one generation) before it
     reports success.
8. **`tools/check_versions.py`**: confirm it covers every template's catalogue and wrapper and the iOS tool versions,
   including `androidx.room3` and `io.github.kyant0`; run it and record outdated stable versions in the handoff
   (bump only with the user's go-ahead, since a bump re-opens the matrix).
9. **Release (checkpoint 3)**: ask the user before pushing `overhaul/multiplatform-v2` and opening a pull request;
   watch CI. When `multiplatform-ios` is green on the release commit, flip `templates/multiplatform/template.toml`
   `status` to `available` (drop `status_note`), run both `--write` commands and push that commit; if it is not green,
   the target ships as `beta` and the handoff says why. When every required job (including `android-matrix-wide`) is
   green, present the matrix, the wide-matrix run, the device summary and the CI links, and ask the user again before
   merging to `main` (which deploys). Never force-push.

## Acceptance

`$O/accept.sh` (`set -euo pipefail`, in the background, ends with `ACCEPT OK`):

```bash
cd $W/generator
python3 -m unittest discover -s tests -t .
python3 -m tests.consistency
python3 -m genkit.tokens --check
python3 -m genkit.core.catalogue --check
python3 $W/tools/sync_check.py
python3 $W/tools/matrix.py --all --out $O          # 14/14 green and every size within budget, summary in $O/matrix.md
cd $W/web/api && go test -race -count=1 ./...
cd $W/web/frontend && npx tsc --noEmit && node --test "features/**/*.test.ts" && npx next build
echo ACCEPT OK
```

The device gates of step 5 each exit non-zero on a failing row, so their logs are the proof; `$P/summary.md` links
them. CI (after the user approves the push): every required job green on the pull request, including the wide matrix.
