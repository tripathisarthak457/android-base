# WP05 Android liquid glass (optional `liquidglass`)

Wave 2: starts when WP03 (design system) and WP04 (shell and bar) have merged and checkpoint 1 has fixed the motion
values. Kotlin/Compose, Gradle, the phone (heavy). Lock budget: Gradle about 2 h, adb about 3.5 h. The feature is off
by default; with it off, nothing of Kyant may reach the app. Your final measurement runs after merging the
integration branch again once WP02-M3 has merged (large titles on every root change what the bar scrolls over).

## Why

The user wants liquid glass as an option, at high frame rates. PeriFlow's glass is architecturally right (one recorded
scene, chrome-only sampling, drawn content glass, frosted fallback) but GPU-bound on the Redmi: GPU p90 20 ms while
scrolling under the bar (budget 8.33 ms at 120 Hz), about eight offscreen passes per frame on every tab tap, the bar
rebuilt with its shaders on every return to a root, three full-screen background fills, fades over live backdrops,
and no quality tiers (audit periflow §3.4–3.5, device-baseline F15). Below API 31 Kyant draws an unblurred copy, so a
frosted fallback is mandatory (research §2.4).

## Steps

1. **Build wiring**: catalogue entries and the design-system dependency, both fenced; with the feature off, the
   template's `./gradlew :app:dependencies` must not mention `kyant`.
2. **`GlassStage.kt`**: `SceneBackdrop` (records the scene once per frame by reference: `recordScene` draws content
   into a `GraphicsLayer` and draws that layer; chrome samples it with `localPositionOf` offsets; periflow G14). The
   window background is painted into the recording instead of extra full-screen fills (G4). The stage exists only
   when the bar treatment is `Glass`. Chrome is never inside the recorded subtree (Kyant SIGSEGV rule). The stage box
   carries the test tag `glass_stage`, and dev builds log `perf.glass: tier=<Tier> stage=<true|false>` once at start, so
   `perf.sh` rejects a glass run on a build without a stage.
   **Kyant #100 first:** read the issue against the 2.0.1 source in `$OV/scratch/kyant-backdrop/` and write down what
   triggers the crash (several far-apart elements sharing one backdrop). The bar, its accessory and its trailing capsule
   are one chrome group at one end of the screen and share the backdrop; top-bar buttons do not sample by default
   (step 7).
3. **`GlassQuality.kt`** and **`GlassVerdictStore.kt`**: the A4.9 tier table as a pure function
   `glassQuality(inputs: GlassInputs): GlassQuality` (unit-tested), plus `rememberGlassQuality()` collecting the
   inputs: API level, `ActivityManager.isLowRamDevice`, power-save broadcast, thermal listener (API 29+), the app's
   `reduceTransparency` setting, and the FrameMetrics GPU verdict (periflow sketch in §3.6: background `HandlerThread`,
   two consecutive 120-frame windows over 15 % slow → bad, sticky for the session, persisted in a private
   `SharedPreferences` file keyed by `Build.FINGERPRINT` + version code). Never upgrades within a session.
   `LocalGlassQuality` is a static local. The dev extra `glass.quality=<Tier>` forces a tier.
4. **`GlassSurface.kt`**: drawn glass as a `Modifier.Node` (tint, rim gradient, sheen, outer-only shadow rasterised once
   per size or Compose 1.12 `dropShadow`; brushes built in `drawWithCache`; periflow G9, G10). Used for content glass
   and for chrome in `Frosted`.
5. **`LiquidLens.kt`**: the press/drag lens. One long-lived drag coroutine; values that track the finger are plain
   float state; springs only to settle; visibility thresholds on every animatable (G13). `effects` lambdas are
   top-level `val`s reading no state; press scale through `layerBlock`; `shadow = null`, `highlight = null` on the lens.
6. **`LiquidTabs(orientation)`**: one component for bar and rail (G15). The tab row is drawn once into a layer; the
   accent-tinted copy is that layer replayed with a `ColorFilter`, clipped to the lens path; at rest the selection is a
   drawn indicator and nothing samples the scene twice; while pressed or dragged the lens samples the scene plus the
   tinted tabs. The bar body has one static rim and a cached shadow outside `drawBackdrop`. Bar blur 10 dp + vibrancy;
   `lens(…)` only in `Live` and only on the lens element. `AppTabBar`'s `Glass` treatment delegates to it; hiding uses
   translation and `alpha = 0` only when fully hidden.
7. **Glass top-bar buttons** (capsule actions over content) are **drawn glass** in every tier by default (A4.9 rule 2).
   You may make them sample in `Live`/`LiveNoLens` only with their own exported backdrop and a `GlassBenchmark`
   journey with the bar and the top buttons on screen together (scroll, tab switches, lens drag) that the process
   survives on the phone; record the decision and its evidence either way.
8. **`Glass` design style**: the `Glass` entry in `tokens/styles.json` (`requires = ["liquidglass"]`), cards, chips
   and fields as drawn glass; `scrollEdgeFade` under a clear top bar on every API (G11).
9. **Settings**: "Reduce transparency" row (strings in every language) wired to the setting and to the tier policy.
10. **Catalog `CatalogGlass.kt`**: a stage over a scrolling high-contrast list, chrome glass, content glass, a forced
    tier switcher, the frame-time readout; reachable with `--es section Glass`.
11. **Benchmarks**: `GlassBenchmark` (scroll under the bar, a tab switch, a lens drag, and bar plus top-bar buttons on
    screen together) parameterised by forced tier; the profile journeys pass through glass screens so
    `com/kyant/backdrop` lands in the generated profile (the checked-in library profiles of `:core:designsystem` are
    refreshed with `split_profile.py`).
12. **Feature file** `liquidglass.toml` as in MASTER-PLAN A1.2 (owns, licence).
13. **Measure and iterate** on the phone (the custom ROM is API 37, so it exercises `Live`): `everything-glass`,
    `devBenchmarkRelease`, `perf.sh` with `glass.quality` forced to each tier, three runs each, `meminfo` included.
    Fix in this order until the `Live` gates hold: lens at rest, decorations off, recording scope, radii, shadows. If
    `Live` still misses the scroll budget after all seven rules are applied, apply the R4 fallback of A4.9 in order,
    measuring after each: blur 10 → 6 dp, then a half-resolution recorded backdrop, then a GPU verdict tuned so a
    device that cannot hold the budget demotes itself to `Frosted` within two seconds of scrolling. At most three
    measure → fix iterations per failing gate, then escalate with numbers and a trace (B.1).
14. **Checkpoint 2 recordings** (MASTER-PLAN B.5): `record.sh` videos and frame strips per tier of a tab tap, a lens
    drag, scrolling under the bar and the bar minimizing, with two or three blur/tint variants selectable through a
    dev extra, plus the per-tier tables. Save under `$P/cp2/` with an index; the orchestrator pauses for the user and
    you write the chosen variant into the tokens.

## Acceptance

Merge the integration branch (with WP02-M3 if it has merged) before the final runs. `$O/accept.sh`
(`set -euo pipefail`, in the background, ends with `ACCEPT OK`):

```bash
#!/usr/bin/env bash
set -euo pipefail
export ANDROID_HOME=$HOME/Android/Sdk
OV=/home/crazyhusir/Documents/projects/tools/.overhaul; W=$OV/wt/WP05; L=$OV/bin/locked; O=$OV/out/WP05; P=$OV/perf/WP05
cd $W/templates/android && $L gradle ./gradlew build --console=plain
$L gradle ./gradlew :core:designsystem:testDebugUnitTest --tests "*Glass*" --console=plain
cd $W/generator
python3 -m unittest discover -s tests -t .
python3 -m tests.consistency --quick
python3 -m genkit.tokens --check
python3 -m genkit.core.catalogue --check
for s in lean-glass everything-glass lean; do
  python3 create_project.py --spec tests/fixtures/v2/$s.json --set package_name=com.example.wp05.${s//-/} --out $O/$s --no-zip --force
done
(cd $O/lean-glass && $L gradle ./gradlew assembleDevDebug --console=plain)
# glass off leaves no Kyant dependency: the build must succeed AND the output must not mention kyant
(cd $O/lean && $L gradle ./gradlew :app:dependencies --configuration devReleaseRuntimeClasspath --console=plain) > $O/logs/deps.log 2>&1
grep -q 'BUILD SUCCESSFUL' $O/logs/deps.log
! grep -q kyant $O/logs/deps.log
cd $O/everything-glass && $L gradle ./gradlew :app:assembleDevBenchmarkRelease --console=plain
PKG=com.example.wp05.everythingglass.dev
$L adb tools/perf/perf.sh --package $PKG --variant devBenchmarkRelease --runs 3 --out $P/Solid --extra glass.quality=Solid tabs pushpop scroll_root idle meminfo   # reference for Frosted
$L adb tools/perf/perf.sh --package $PKG --variant devBenchmarkRelease --runs 3 --out $P/Live  --extra glass.quality=Live --gate glass_live \
  tabs pushpop pushpop_gesture rapid_back nav_stress restore scroll_root scroll_minimize idle coldstart meminfo coldstart_installed
$L adb tools/perf/perf.sh --package $PKG --variant devBenchmarkRelease --runs 3 --out $P/LiveNoLens --extra glass.quality=LiveNoLens tabs pushpop scroll_root idle meminfo
$L adb tools/perf/perf.sh --package $PKG --variant devBenchmarkRelease --runs 3 --out $P/Frosted --extra glass.quality=Frosted \
  --gate glass_frosted_vs_solid --baseline $P/Solid/summary.json tabs pushpop scroll_root idle meminfo
$L adb $L gradle ./gradlew :app:generateBaselineProfile --console=plain
grep -q "com/kyant/backdrop" app/src/main/generated/baselineProfiles/baseline-prof.txt
echo ACCEPT OK
```
