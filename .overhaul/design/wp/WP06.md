# WP06 Android data, network and platform services

Wave 1: starts when WP02-M1 (pure `:core:common`, `AppError`, MVI, `api/` packages) has merged; WP01 should be merged
too (feature TOMLs). Kotlin, Gradle (heavy), the phone (light: a devtools drag check and a sign-out check). Lock
budget: Gradle about 3 h, adb about 0.3 h.

**Publish early (within your first working session):** `$OV/handoff/WP06-early.md` with the name and exact snippet
format of the `database-entities` region (where scaffolded modules add an entity and a DAO to `:core:database`, and
how `AppDatabase` lists them). WP02-M2's scaffolder writes against it after you merge.

## Why

The audits found security and data-loss bugs and dead weight here: Ktor's bearer cache leaks one user's token into the
next session; a late refresh resurrects a signed-out session; a 408/429 on refresh signs the user out and deletes
offline writes; the replayer drops queued mutations on any 4xx; the WebSocket never connects; the network monitor
registers a system callback per request (Android caps an app at about 100) and refuses requests on unvalidated
networks; 204 bodies fail; three OkHttp clients; push never displays on Android 13+ and survives sign-out; the
analytics opt-out is cosmetic; Remote Config never fetches; an app-lock bypass; Play updates restart the app under the
user; the devtools badge cannot be dragged (and PeriFlow and VitFleet ship the same file); `push` drags in all of
Firebase; WorkManager has no workers; the widget initialises WorkManager and Room at every start for one line of text;
Room duplicates the OkHttp cache; the media module ships helpers nobody calls.

## Steps

0. **Room 3 spike** (first hour, risk R6): `androidx.room3` 3.0.3 with KSP and the `androidx.room3` Gradle plugin
   (`room { schemaDirectory("$projectDir/schemas") }`), `AndroidSQLiteDriver`; one entity, a `Flow` DAO, `@Upsert`,
   a Robolectric test. If it blocks (testing helpers, KSP), fall back to Room 2.8.5 on Android only and record why.
1. **`:core:network`** (A6.4):
   - `ConnectivityNetworkMonitor`: one shared `StateFlow` (`WhileSubscribed(5_000, replayExpirationMillis = 0)`),
     `NET_CAPABILITY_INTERNET`, never gates a request; `ACCESS_NETWORK_STATE` declared here. Port VitFleet's
     Robolectric test (one registration after 25 requests).
   - `NetworkClient`: body read once (`parseBody`: empty → `{}`, 204 fine), per-request timeout, `RawBody`, every
     failure mapped to `AppError` (Offline, Timeout, Http with `code`/`fieldErrors`/`retryAfterSeconds` parsed once by
     the DI-bound `ResponseUnwrapper`, Decode); header helpers set rather than append (B9); a User-Agent safe for
     non-ASCII app names (3.11); one shared `OkHttpClient` (pins applied once) for HTTP, sockets and images; logging
     only in debug builds with credential paths filtered; an app-version header.
   - Auth: VitFleet `SessionTokens` behind PeriFlow's `HttpSend` interceptor; `ktor-client-auth` removed (no token
     cache to leak); only a 401 from refresh ends the session; a refresh finishing after sign-out is dropped by session
     generation; idempotency keys on every mutation the queue may replay (B8).
   - `NetworkObserver` interface for recorders; `:core:network` no longer depends on `:core:devtools` (D5).
   - `websocket`: `install(WebSockets)`, VitFleet's `AppWebSocket` hardening (backoff grows, no debug kill, connect and
     disconnect races), `RealtimeLifecycle` (open while the app is in front, close 30 s after it leaves, reconnect
     with the new token after an account switch).
   - `appstatus`: `ApiSignals` (426 force update, 503 maintenance, configurable code mapping, optional server min
     version header) and `AppStatusGate` UI in `core/ui/.../appstatus/`, wired into `AppRoot`.
2. **`database`** on Room 3: `AppDatabase` at version 1 (no cargo-cult migration; the migration recipe goes to docs),
   entities and DAOs per domain package, `@Upsert`, `clearAllTables()` as a `SessionScopedStore`, a DAO test; a
   `generated` region where scaffolded modules add entities.
3. **`offlinequeue`** (new, requires network and database): the queue table, VitFleet's replayer (refusals kept with
   the server's answer, 401/408/426/429 momentary, growing retry timer, one pass at a time, owner scoping, max age and
   attempts), replayed by one `CoroutineWorker` with a `NetworkType.CONNECTED` constraint and on-demand WorkManager
   initialisation (`Configuration.Provider`; the startup initializer removed from the manifest). Tests port VitFleet's
   `QueuedRequestReplayerTest` and replace the template's data-loss assertion.
4. **Remove the Room HTTP cache**: `ResponseCache` GET caching and the saved-copy-first `stream()` go; GETs rely on
   the OkHttp cache. `offlinequeue.toml` carries `legacy = [{ key = "room", schema = 1 }]`; delete `room.toml`.
5. **Data modules** (`data/**`): `sample` offline-first under `<opt:sample&database>` (A6.3) and network-only
   otherwise; `feed` on `paging-common`; `search` recent searches in their own DataStore file per user; `profile`
   copies the picked avatar into app storage (F7; uses the trimmed compressor when `media` is on, otherwise no photo
   option); `auth` maps storage failures to `AppError.Storage`. Each with tests (mappers, repositories with fakes,
   the offline-first refresh path).
6. **`:core:datastore`**: one file per concern (settings, session tokens, per-feature stores) instead of a shared
   session file (F19); the Keystore key cached and created under a lock (infra §6); a token that cannot be decrypted
   means signed out; one clear per store; a cached synchronous read of the lock setting for `AppLockGate`.
7. **Session** (`app/session`): `SessionCoordinator.signOut()` single-flight; clears every `SessionScopedStore`
   (tokens, database, push registration, socket, in-flight shared GETs, flag overrides, analytics user), bumps the
   generation in `SessionController.state`; PeriFlow's "wipe when the signed-in uid changes" rule for guest-to-account
   upgrades; `CancellationException` never swallowed. Test: sign-out clears every bound store exactly once, even when
   called twice concurrently.
8. **Firebase split**: feature files `crashlytics`, `firebaseanalytics`, `remoteconfig` (each requires `firebase`,
   plus `analytics` or `flags`) with `legacy = [{ key = "firebase", schema = 1 }]`; `push` requires only `firebase`;
   `firebase` stays `implied_only` (google-services plugin, BoM 35, placeholder json). The Firebase convention plugin
   applies Crashlytics only with `crashlytics` and uploads mappings only with `-PcrashlyticsUpload=true`. Convert
   `firebase-off` to `opt-else` blocks in the analytics and flags DI modules and delete the variant directory.
9. **Analytics and flags**: the settings opt-out collected in `Application.onCreate` and applied to the tracker and the
   crash reporter (both get `setEnabled`); `AppLogger.e` becomes a breadcrumb, `recordException` only for unexpected
   errors; `FeatureFlags.observe(flag): Flow<T>`, `refresh()` at start, Remote Config real-time updates and a zero
   fetch interval in debug, thread-safe overrides shown in a devtools "Flags" tab.
10. **Push** (`:core:notification`, moved from `app/push`): `rememberNotificationPermission()` used by onboarding and
    settings; default tap intent; lock-screen-safe public version; register only when the installation id changes;
    channels created off the main thread; unregister on sign-out; pre-O code and the stand-in permission removed.
11. **Media** trimmed: photo picker, camera capture with a saveable URI (B30), one image compressor (writes to
    `cacheDir/uploads/`, FileProvider path `uploads/`, EXIF orientation including transpose/transverse,
    `ImageDecoder` target size on API 28+, CPU work on the default dispatcher); video transcoder, probe and the false
    capture-limit claims removed.
12. **Devtools** (the user's reported bug, infra §1): badge position accumulates from live state, clamped at placement
    (rotation-safe), offset read in the layout phase, 48 dp target, start inset from `WindowInsets.safeDrawing`,
    optional settle to the nearest edge; test tag `devtools_badge`; Back inside the panel returns to the list; sizes counted from the body for
    chunked/compressed responses (device-baseline F9); credentials redacted (Authorization, cookies, token fields);
    the Flags tab. Compose UI test: a swipe moves the badge by the swipe distance. PeriFlow ships the same file (WP11
    ports this fix) and so does VitFleet, which is out of scope: describe the fix as a patch in the handoff so the
    upgrade guide can name it.
13. **`:core:applock`** (moved from `app/lock`, `LockActivity` deleted): `AppLockGate { content }`, an overlay that
    starts locked when required, decided synchronously, driven by `ProcessLifecycleOwner`, PeriFlow's `justUnlocked`
    and own-action grace, lockout and error codes handled, prompt not restarted on recreation; `androidx.fragment`
    pinned for biometric (VitFleet B33). Test: the "Home on the lock screen, return within the grace window" bypass is
    closed.
14. **`:core:playstore`** (moved from `app/playstore`): `PlayStorePrompts()`: a downloaded flexible update shows a
    toast with "Restart" instead of restarting; a dismissed version is remembered; checked once per process; the
    review prompt counts launches once per process; the `ActivityResultLauncher` overload. Tests for the policy.
15. **Removals**: `widget` (sources, xml, manifest receiver, Glance dependencies, strings and translations; a recipe
    note for WP12), `workmanager` (feature file; WorkManager now arrives only with `offlinequeue`); notes in
    `removed.toml`.
16. **Sizes**: `devRelease` arm64 APK size and total dex size for `standard`, `everything` and
    `everything` without `offlinequeue`, before and after your changes; the `offlinequeue` row shows the dex cost of
    WorkManager's bundled Room 2 next to Room 3 (A5.1). The orchestrator turns these into `tools/size_budgets.toml`.

```bash
OV=/home/crazyhusir/Documents/projects/tools/.overhaul; W=$OV/wt/WP06; L=$OV/bin/locked; O=$OV/out/WP06; P=$OV/perf/WP06

  :core:devtools:testDebugUnitTest :core:applock:testDebugUnitTest :core:playstore:testDebugUnitTest :app:testDevDebugUnitTest --console=plain

  python3 create_project.py --spec tests/fixtures/v2/$s.json --set package_name=com.example.wp06.${s//-/} --out $O/$s --no-zip --force
  (cd $O/$s && $L gradle ./gradlew check assembleDevDebug --console=plain)
done
python3 create_project.py --spec tests/fixtures/v1/v1-firebase.json --out $O/v1fb --no-zip --force --json > $O/v1fb.json
grep -q "remoteconfig" $O/v1fb.json

# device: the devtools badge drags (everything has devtools; dev flavour)
cd $O/everything && $L gradle ./gradlew :app:assembleDevRelease --console=plain
$L adb python3 $O/badge_drag_check.py --serial 9a7c74f4 --package com.example.wp06.everything.dev \
  --apk app/build/outputs/apk/dev/release/app-dev-release.apk --out $P/badge
echo ACCEPT OK
```

`$O/badge_drag_check.py` (yours) installs the APK, `pm clear`s it, launches with `perf.fakeSession=true`, reads the
badge bounds from `uiautomator dump` (resource id `devtools_badge`), runs `input swipe` from the badge centre by
(-500, -800) px over 600 ms, dumps again, saves both dumps to `--out`, and exits 1 unless the centre moved by at least
80 % of the swipe on both axes (clamping at the screen edge counts as moved to the edge).
