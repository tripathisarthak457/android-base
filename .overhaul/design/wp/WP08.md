# WP08 SwiftUI template (hidden on the site, "coming soon")

Wave 1, after WP01 has merged. Swift and Python. No Gradle, no device, **no Swift compiler on this machine**: you
write the code, keep it simple and idiomatic, and prove what you can with the static checks of MASTER-PLAN A12.4. The
CI macOS job (WP13) compiles it later; until that is green the website shows the target as "coming soon".

## Why

The user wants a native SwiftUI generator with the same architecture quality as the Android one: SwiftUI with
`@Observable` MVI, iOS 17 minimum, XcodeGen, local Swift packages, iOS 26 glass behind `#available`. The module graph
mirrors Android's (data never depends on features, features never on each other) so a team that knows one template
knows the other, and the same design tokens produce the same look.

## Steps

1. **`project.yml`** (XcodeGen 2.46.0, keys per research §5.3): `name: BaseApp`; `options` (`bundleIdPrefix`,
   `deploymentTarget: {iOS: "17.0"}`, `createIntermediateGroups`); `packages` `Core` and `Features` (local paths);
   target `BaseApp` (`type: application`, sources `BaseApp` as `syncedFolder`, package product dependencies, `info`
   with `CFBundleDisplayName`, `UILaunchScreen` and **`CADisableMinimumFrameDurationOnPhone: true`** (without it custom
   SwiftUI and `CADisplayLink` animations are capped at 60 Hz on ProMotion iPhones), settings `PRODUCT_BUNDLE_IDENTIFIER: com.base.app`,
   `SWIFT_VERSION: "6.0"`, per-configuration `xcconfig` files `Config/Dev.xcconfig` and `Config/Prod.xcconfig`
   carrying `API_BASE_URL`); target `BaseAppTests` (`bundle.unit-test`); a scheme with both configurations.
2. **`Packages/Core/Package.swift`** (`swift-tools-version: 6.2`, `platforms: [.iOS(.v17)]`): products `AppCore`,
   `DesignSystem`, `Networking`, `Persistence`, `Navigation`; test targets per product.
   `swiftSettings: [.defaultIsolation(MainActor.self)]` goes **only on the UI targets** (`DesignSystem`, `Navigation`);
   `AppCore`, `Networking` and `Persistence` stay nonisolated, so JSON decoding and SwiftData work never run on the
   main actor and large payloads cannot hitch the UI.
   - `AppCore`: `AppResult`/`AppError` (offline, timeout, http with code and field errors, decode, storage,
     unexpected), `LoadState`, `TaskBag` (`latest(_ key:debounce:operation:)` cancels the previous task under the key;
     `exclusive(_ key:operation:)` ignores a new one while one runs; `cancel(_:)`; `cancelAll()`), `AppClock`, `Log`.
   - `DesignSystem`: `Tokens/DesignTokens.swift` (emitted; never edited by hand), `AppTheme` through `Environment`
     (colours resolved per colour scheme), springs from the same `(response, bounce)` pairs
     (`.spring(duration:bounce:)`), press styles (`ScalePressStyle`, `DimPressStyle`, `HighlightRowStyle` as
     `ButtonStyle`s, A4.1 mapping), haptics through `sensoryFeedback` per the A4.2 table (none on plain taps),
     components: `AppButton`, `AppSection`/`AppRow` (inset-grouped `List` styled by tokens), `AppTextField`,
     `AppToast` (queued, swipe to dismiss), `AppStateView` (`ContentUnavailableView`), `AppSkeleton` (redacted plus
     one shared shimmer, off with Reduce Motion), sheets with `presentationDetents`, `Glass/AppGlass.swift`
     (`appGlass(in:)`: `glassEffect` inside a shared `GlassEffectContainer` on iOS 26, `.ultraThinMaterial` below,
     solid when Reduce Transparency is on).
   - `Networking`: `APIClient` (async/await over an injected `URLSession`, JSON decoding in `@concurrent` functions
     off the main actor, `AppError` mapping),
     `Endpoint`, `NetworkMonitor` (one shared `NWPathMonitor` exposed as an `AsyncStream`/observable state; never gates
     requests).
   - `Persistence`: `SettingsRepository` (nonisolated, `UserDefaults`-backed, current values plus an `AsyncStream` of
     changes that UI stores observe), `ModelContainerFactory` and a `@ModelActor` per data domain for SwiftData work
     (`database`).
   - `Navigation`: `Router` (`@Observable`, `path` per tab, `push`, `pop`, `popToRoot`), `TabShell` (`TabView`
     bound to a selection that detects reselect and pops to root), `DeepLinks` (`onOpenURL` → router).
3. **`Packages/Features/Package.swift`**: per feature a `<X>Data` target (repository protocol + default implementation
   + DTOs; nonisolated) and a `<X>Feature` target (views, stores, routes, `Resources/Localizable.xcstrings`;
   `defaultIsolation(MainActor.self)`); `SampleData`,
   `SampleFeature` (list/detail, offline-first with SwiftData when `database` is on), `SettingsFeature`,
   `OnboardingFeature`; test targets with Swift Testing.
4. **Stores** exactly in the A8.2 shape: `@MainActor @Observable final class`, `private(set) var state`, `send(_:)`
   never `await`s, work through `TaskBag`, navigation through the router. No `ObservableObject`, no `@Published`.
5. **App target**: `BaseAppApp.swift` (`@main`, builds the environment: API client, stores' factories, router),
   `AppRoot.swift` (onboarding gate, then `TabShell`), `AppTabs.swift` with the `shell-tabs` region.
6. **Generator target** (`targets/ios`): `template.toml` (`status = "coming_soon"`, identity `BaseApp`,
   `com.base.app`, `baseapp`; regions `shell-tabs`, `feature-products`, `feature-targets`, `app-dependencies`),
   `features/*.toml` for the v1 set (A8.3: network, sample, settings, onboarding, database, language, liquidglass),
   `presets.toml`, validation (`ios.bundle_id` reverse-DNS with `-` allowed and `_` refused, deployment target ≥ 17.0,
   Swift keywords refused for module names, `display_name`), scaffolding of `feature_modules` into `<Name>Data` and
   `<Name>Feature` targets with sources, tests and an `.xcstrings` file, translations written as String Catalog JSON
   (no markers in JSON), token emission through `swift.py`.
7. **Static checks** (`generator/tests/test_target_ios.py`, A12.4): for every preset and a scaffolded spec: no markers
   or identity tokens left; `project.yml` parsed with PyYAML when available (skip with a message otherwise) and
   checked for targets, packages, deployment target, bundle id, synced folder; `Package.swift` tokenised into targets
   and dependencies and checked against the graph rules (Feature → its Data, Core products; never Feature → Feature;
   Data never → Feature); every `import` in a target's sources is a declared dependency or a system framework
   (`SwiftUI`, `Foundation`, `Observation`, `SwiftData`, `Network`, `OSLog`, `Testing`); balanced delimiters per file
   (string- and comment-aware); forbidden patterns (`ObservableObject`, `@Published`, `try!`, `DispatchQueue.main.async`
   in stores, `print(`); every `.xcstrings` is valid JSON with the shipped languages; **isolation**: in
   `Package.swift` only UI targets carry `defaultIsolation(MainActor.self)`, and no source file of `Networking`,
   `Persistence` or any `<X>Data` target contains `@MainActor`; `Info.plist`/`project.yml` set
   `CADisableMinimumFrameDurationOnPhone` to true.
8. Optional, **only with the user's permission** (the orchestrator asks; it pulls a Docker image):
   `docker run --rm -v "$PWD":/w -w /w swift:6.2 swiftc -parse $(find . -name '*.swift')` on a generated project, for
   a syntax check. Record the result either way.

## Acceptance

`$O/accept.sh` (`set -euo pipefail`, ends with `ACCEPT OK`):

```bash
cd $W/generator
python3 -m unittest tests.test_target_ios -v
python3 -m unittest discover -s tests -t .
python3 -m genkit.tokens --check
python3 -m genkit.core.catalogue --check
for s in ios-lean ios-standard ios-everything ios-modules; do   # your fixtures: platform "ios"
  python3 create_project.py --spec tests/fixtures/v2/$s.json --out $O/$s --no-zip --force
done
python3 generate_headless.py --target ios $O/ios.zip < tests/fixtures/v2/ios-standard.json \
  | python3 -c 'import json,sys; assert json.load(sys.stdin)["ok"]'
grep -q 'CADisableMinimumFrameDurationOnPhone' $O/ios-standard/BaseApp/Info.plist $O/ios-standard/project.yml
! grep -rn '@MainActor' $O/ios-everything/Packages/Core/Sources/Networking $O/ios-everything/Packages/Core/Sources/Persistence
echo ACCEPT OK
```

(The `grep -q` with two files passes when either carries the key, which matches whichever of `Info.plist` or
`project.yml` `info.properties` you choose to own it; `test_target_ios.py` asserts the exact place.)
