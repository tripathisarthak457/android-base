# WP04 Android navigation, shell and performance harness

Waves 0 → 1. Phase 1 (harness and baseline) starts right after WP00; phase 2's edits in `feature/**` and the depth-4
baseline start after **WP02-M1** has merged (M1 rewrites every ViewModel, moves keys and adds the "Related" rows and
tags you need); work inside `core/navigation`, the shell and the bar can start before. Kotlin/Compose, Gradle (heavy),
the phone (heavy). Lock budget: Gradle about 4 h, adb about 5 h. This package fixes the user's first complaint, so it
measures before it changes anything and proves every fix on the device with machine-checked gates.

## Why

Measured on the Redmi Note 10 Pro (audit device-baseline): every tab switch recomposes the whole destination tab
(21–52 ms first frame, 1–5 dropped vsyncs) and double-exposes two full screens in a delayed cross-fade; the bar moves
on another axis and clock during push and pop (over the incoming page on push, springing up over the outgoing page on
a Back-key pop, rising into an empty strip after a gesture pop); root screens are clipped above a reserved strip;
every pop composes the root from scratch (F5: 11.5 then 18.3 ms over the first two frames, already speed-profile
compiled); the spring leaves a slow sliver; predictive back scrubs a spring and a gesture during a push retargets the
transition (audit template-navigation RC1–RC8). The user also reports glitches when pressing Back quickly while a pop
is animating. Sheets and modals rendered inside a tab would appear under a persistent bar. The benchmark module cannot
run at all (flavours), so none of this was ever measured by the template (catalog-benchmark B1–B7).

## Steps

### Phase 1: harness and baseline (no behaviour changes yet)

1. **Benchmark module** (catalog-benchmark B1–B11): `missingDimensionStrategy("environment", "dev")`, target
   application id read from the app's config instead of hard-coded, minSdk 28, SDK levels from the catalogue,
   unused dependencies removed. In `app/build.gradle.kts`, inside the existing `<opt:baselineprofile>` block (renamed
   to `performance` in step 23): `baselineProfile { mergeIntoMain = true; saveInSrc = true;
   automaticGenerationDuringBuild = false }`.
2. **Dev launch options** (`app/src/dev/kotlin/.../perf/DevLaunchOptions.kt`): a Hilt `@IntoSet` `LaunchHook`
   contributed only by the `dev` source set (main code iterates a `@Multibinds` set, empty in other flavours) that
   reads the extras `perf.skipOnboarding`, `perf.fakeSession` (marks onboarding done, writes a synthetic session
   through the session store API) and `perf.screenResponse=<seconds>` (overrides the screen spring's response for
   checkpoint recordings) before the gates decide. A second dev-only hook logs the `ShellState` dump after every
   applied command (`perf.shell: tab=… stacks=… presented=…`, A3.4a). WP05 adds `glass.quality` the same way.
3. **Journeys** (`benchmark/.../Journeys.kt`): `startToShell()`, `tapTab(i)`, `openFirstRow()`, `openRelated()`
   (`related_row`, from WP02-M1), `presentSheet()`, `pressBackBurst(n)` (`device.executeShellCommand("input keyevent "
   + "4 ".repeat(n))`), `edgeSwipeBack()`, `flingPrimaryList()`. Every step waits for a resource id and fails with a
   message when it is missing (no silent `?: return`; catalog-benchmark B4).
4. **Benchmarks** (A12.5): `StartupBenchmark` (COLD, WARM × `None`, `Partial`), `TabSwitchBenchmark`,
   `PushPopBenchmark`, `PredictiveBackBenchmark`, `RapidBackBenchmark` (asserts the final screen), `ScrollBenchmark`,
   all with `FrameTimingMetric`; `BaselineProfileGenerator` with a startup rule (`includeInStartupProfile = true`) and
   a journeys rule (tabs, push/pop, sheet, scroll) whose steps assert.
5. **`tools/perf/`** exactly as MASTER-PLAN A12.5: `perf.sh` (the CLI there: `--package`, `--apk`/`--variant`,
   `--runs`, `--out`, `--extra`, `--gate`, `--baseline`, `--seed`, `--serial`; install, `pm clear`, warm-up pass and
   scenarios in one invocation; `summary.md` and `summary.json`), every scenario of A12.5 including `nav_stress`,
   `restore`, `scroll_minimize`, `meminfo` and `coldstart_installed`; `parse_gfx.py`, `parse_framestats.py`,
   `check_nav_log.py`, `gates.toml` (columns `solid`, `lean`, `standard`, `smoke`; WP05 adds the glass columns, WP07
   the `cmp_android*` columns; `--gates <file>` reads another file of the same format), `record.sh`, `split_profile.py`. `tools/perf/test_perf.py` tests the parsers and
   the gate checker against the raw dumps in `$OV/scratch/device/` (a known janky run must fail `--gate solid`, a
   clean one must pass).
6. **Baseline on the device** before any navigation change. Generate `everything` from the current tree
   (`tests/spec_full.json` plus `devtools` if WP01's v2 fixtures do not exist yet) with
   `--set package_name=com.example.wp04.base`, build `devBenchmarkRelease`, and run (in the background):
   ```bash
   $L adb tools/perf/perf.sh --package com.example.wp04.base.dev --variant devBenchmarkRelease --runs 3 --out $P/baseline \
     tabs tab1 pushpop pushpop_gesture rapid_back scroll_root idle coldstart meminfo
   $L adb tools/perf/record.sh com.example.wp04.base.dev rapid_back $P/baseline/frames/rapid_back
   ```
   Also measure `standard` and `lean` (`--variant devRelease`; `tabs pushpop coldstart`) into `$P/baseline-standard`
   and `$P/baseline-lean`. If WP02-M1 has not merged, `rapid_back` uses the deepest stack the tree offers; repeat it at
   depth 4 (through `related_row`) once M1 has merged. Describe the rapid-Back glitch from the frames in the handoff
   (blank frame, snap, double exposure, bar jump, lost or duplicated pop) before fixing it (risk R3).

### Phase 2: the navigation rewrite

7. Bump Navigation 3 to 1.2.0 and add `navigationevent` 1.2.0; build and run the existing tests first (risk R1).
8. `AppNavigator` per Activity, commands applied only while STARTED (VitFleet B11); `ShellState.apply(command,
   rootKeys)` (a root key selects its tab, VitFleet P8), `handleBack()`, `sessionGeneration`, `select()` clears focus,
   and a **presentation stack** next to the tab stacks; keys registered with `presentation = Sheet(detents) | Cover`
   route there (A3.9).
9. `AppShell`: **one** `TabbedNavHost` call site; width class switches only chrome and paddings; rail mode
   `clipToBounds()`; a `ShellChrome` seam (plain `Box` today; WP05 adds the glass stage behind
   `<opt:liquidglass>`).
10. `KeptTabs` v2 exactly as A3.2 (port `TabLifecycle` and `TabBackDispatcher`), `LocalTabVisible` provided, opened set
    keyed by session generation. If an unmeasured child fails, fall back to measure-without-place and record why.
11. **Warm-pop spike (A3.10), first task after KeptTabs, timebox one working day.** Read the Navigation 3 1.2.0 source
    for how entry content is rendered across scenes (movable content or not) and write the finding down. Build option
    A (`KeepUnderScene`); measure pop first frame with `perf.sh pushpop` (3 runs). If A fails because the composition
    does not move, try option B (`StackScene`) inside the same day. Apply the decision rule of A3.10; if neither meets
    it, apply the fallback set and carry the numbers to checkpoint 1. Record the outcome either way.
12. `TabbedNavHost`: one `NavDisplay` per kept tab, entry decorators and scene strategies remembered once,
    `ListDetailScene` with `equals` and no transition when only the scene changed (a resize; A3.4a), every entry with
    an opaque background, `CoverScrim` (draw-phase scrim and leading-edge shadow, A3.3), transitions as A3.3 (private
    `spring(1f, 685f, IntOffset.VisibilityThreshold)` until WP03's `AppTheme.springs.screen` exists; if WP03 merged
    first, use it; honour `perf.screenResponse` in dev builds), `predictivePop` duration = the screen spring's settle
    time (record whether 1.2.0 can finish a released gesture on a spring), reduce motion → no transition. Delete
    `tabSwitch`, `TAB_ENTER_SCALE`, `outgoingDim`, the `Fade` style.
13. `BackGate` (A3.4), one per tab host and one for the presentation host, and **`NavGuard`** for every row of A3.4a:
    push dedupe by key and drop while `moving`, programmatic commands deferred to settle, tab tap during motion
    commits the leaving tab's transition and leaves it idle, reselect as one animated multi-pop (scroll to top at the
    root), Back ignored during the identity crossfade, no exit from queued presses, savers for every stack and the
    presentation stack (process death). Motion reported from `LocalNavAnimatedContentScope`.
14. **Presentation host and layering contract (A3.9)**: `PresentationHost` (composed only while something is presented
    or its exit runs; its Back handler wins while non-empty; `SheetScene` from WP03 as its sheet strategy, `modal()`
    for covers), the z-order of A3.9, `LocalTabBarVisible` in `Chrome.kt`, the bar hidden while the IME is visible,
    `LocalBottomChrome` written only by the shell (bar + accessory settled height; the IME inset while the keyboard
    is up), the shell API through which `AppBottomActionBar` reports its height. `ChromeLayeringTest` covers every
    case listed in A3.9.
15. **Bar** (A4.8, A3.5): `AppTabBar` with the full signature of A4.8 (`labels`, `minimize`, `trailingAction`,
    `accessory`), replacing `AppBottomBar` and `AppNavigationRail`; persistent at every depth; `BarAnchor` + `followRoot`
    for `FullScreenKey` destinations and `ShellConfig(hideBarOnPush)`, with the cover scrim drawn over the travelling
    bar; minimize driven by a nested-scroll connection read only in layout and draw, insets written on settle; the
    indicator in the `barIndicator` role (WP03 adds it; use a private colour until it lands) with its position read in
    `offset { }` and colours as `ColorProducer`; items with `indication = null`, `Selection` haptic once WP03's
    haptics exist; filled/outlined icon pairs (ask WP03 through the orchestrator for the filled glyphs; outlined
    meanwhile); resource ids `tab_<i>` and `tab_trailing_action`. `AppFloatingToolbar` shares the bar's surface code.
    The reserved strip is gone; root lists use `chromeContentPadding()` (after M1).
16. **Entry** (A3.6): `StartupViewModel` holds the splash until settings and the token store are read (WP03 adds the
    bounded font preload to the same hold); identity `Onboarding | SignedOut | SignedIn(generation)` with a single
    200 ms crossfade; no `navigator.resetTo()` on auth or onboarding completion; sign-out drops kept tabs through the
    generation.
17. **Deep links** (A3.6): `singleTop`, `onNewIntent` → `PendingDeepLink.hold`, ignore launches from history, no re-hold
    on recreation, taken once after the gates and only when the target host is not moving; links to presented keys
    select the owning tab, then present; `DeepLinkRoute` multibound per feature (the central resolver goes).
18. **System bars and splash** follow the in-app theme (VitFleet B27); `themes.xml` updated.
19. Catalog `CatalogNavigation.kt`: push, pop, cover, sheet and predictive back with the real specs (catalog C9), and
    every bar variant of A4.8 (treatments × label modes, minimize, trailing action, accessory, badges, rail) plus
    `AppFloatingToolbar`.
20. Tests (Robolectric Compose where UI is involved): `KeptTabsTest` (only the active tab measured, hidden lifecycle
    CREATED, hidden back dispatcher disabled, generation change drops tabs), `KeepUnderTest` (if option A or B is
    adopted: the covered entry is composed, unmeasured, lifecycle CREATED, and is not recomposed from scratch by a pop),
    `BackGateTest`, `RapidBackTest` (A3.4), `NavGuardTest` (every row of A3.4a), `ChromeLayeringTest` (A3.9),
    `RestoreTest` (stacks and the presentation stack survive recreation with a saved state), `ShellStateTest` additions
    (root routing, presentation routing), `AppNavigatorTest`, `PendingDeepLinkTest`, `LinkEntryManifestTest`,
    `NavKeyRegistrationTest` (every key registered once and round-trips through `NavKeySerialization`),
    `SharedDestinationsTest` (in `:app`: each shared key registered once, by the owner named by its folder),
    `AppDestinationsTest` (tab identity hash-stable).
21. **Checkpoint 1 recordings** (MASTER-PLAN B.5): one `devBenchmarkRelease` APK, `record.sh` videos and frame strips of
    push and Back-key pop at `perf.screenResponse` 0.24, 0.30 and 0.36, a tab switch, a gesture pop, the bar variants,
    a sheet over a tab root and a cover over a pushed screen; plus the current solid-gate table and the spike outcome.
    Save under `$P/cp1/` with an index; the orchestrator combines it with WP03's and pauses for the user.

### Phase 3: prove it on the device

22. Merge the integration branch (WP01 and WP02-M1 at least; WP03 if merged). Generate `everything`, `standard` and
    `lean` with unique ids, build (`devBenchmarkRelease` for `everything`, `devRelease` for the others), and run the
    gates three runs each: `--gate solid` on `everything` (every scenario), `--gate standard` and `--gate lean` on the
    others (their rows of §2). Iterate until they hold, at most three measure → fix iterations per failing gate, then
    escalate (B.1). Record frame strips of a tab switch, a push, a Back-key pop, a gesture pop, a rapid-Back burst and
    the two layering cases; check them for double exposure, blank frames, bar motion and slivers.
23. **Baseline profiles**: generate with `:app:generateBaselineProfile`, check the shell (`core/navigation/`) and at
    least one feature screen class are present, then `split_profile.py` writes the checked-in
    `src/main/baseline-prof.txt` of `:core:navigation`, `:core:designsystem`, `:core:ui` and `:app` (startup rules),
    which every preset ships. Verify in a generated project that the rules were renamed (`grep -c 'Lcom/example/'`).
24. Once WP01 has merged (the feature TOMLs exist only from then): create `features/performance.toml`
    (`legacy = ["baselineprofile"]`, owns `benchmark` and `tools/perf` but **not** the checked-in profiles,
    description that says exactly what ships), delete `baselineprofile.toml`, rename the `<opt:baselineprofile>`
    markers to `<opt:performance>` (benchmark, app build file, the settings include), make `deeplink.toml`'s
    description match the new behaviour, and run both `--write` commands (MASTER-PLAN A9.2).

```bash

set -euo pipefail

OV=/home/crazyhusir/Documents/projects/tools/.overhaul; W=$OV/wt/WP04; L=$OV/bin/locked; O=$OV/out/WP04; P=$OV/perf/WP04
```
