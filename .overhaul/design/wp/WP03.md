# WP03 Android design system and catalog

Waves 0 → 1, two phases, one merge at the end. Kotlin/Compose, Gradle (heavy), the phone (light: catalog screenshots,
checkpoint 1 recordings), Python (token emitters and the look applier, phase B). Lock budget: Gradle about 4 h, adb
about 0.5 h.

Two waits are built in: the call-site sweep across `feature/**` runs only after WP02-M1 has merged (M1 rewrites every
ViewModel and moves keys, so a sweep before it would conflict on every file), and phase B writes the motion values the
user picks at checkpoint 1 (MASTER-PLAN B.5).

## Why

The user dislikes the grey flash on every touch: it is a global 9 % overlay (`AppIndication` as `LocalIndication`),
and filled buttons stack three effects (audit designsystem §1). Haptics buzz on every tap. Motion is two systems that
do not meet (§4). The floating bar is an opaque card with an invisible selection pill (§2; WP04 owns the bar). Real
functional bugs sit in the wheel picker, slider, pull-to-refresh, currency field, sheet, tooltip, swipe actions, top
bar and dark skeleton (§6). Accessibility misses targets, contrast and semantics (§8). 2,681 lines of components are
catalog-only weight (§11). The catalog ignores the project's style and cannot show what it claims (catalog C1–C14).
The generator patches the look with regexes that can silently stop matching; tokens fix that (MASTER-PLAN A9).

## Phase A (wave 0, no tokens needed)

Build the design system first (steps 1–3 and 5–9 inside `core/designsystem` and `catalog`). The migration of call
sites in `feature/**`, `core/ui` and `app/**` (typography renames, `pressable` instead of `clickable`, removed APIs)
is one scripted, re-runnable commit made **after WP02-M1 has merged**: keep the script in
`$O/scripts/sweep_callsites.py` (old → new mapping tables from A4.1 and A4.4), run it on the merged tree, read every
diff, fix what the script cannot, and re-run it after each later merge of the integration branch.

1. **Feedback** (A4.1): `foundation/Pressable.kt` with `PressFeedback`, `Modifier.pressable(...)`, `PressEffectNode`
   (port PeriFlow's `PressBounceNode`: `Modifier.Node` + `LayoutModifierNode`, animatable read only in
   `placeWithLayer`, "finish the dip" on quick taps, one under-damped release spring with bounce proportional to
   travel), `NoIndication`, `RowHighlight` (instant on, 220 ms fade out, `highlight` colour), `minimumTouchTarget()`
   (layout modifier reserving 48 dp and centring content; also expands the hit area, VitFleet B19).
   `AppTheme` provides `LocalIndication provides NoIndication`. Replace `appClickable`, `AppClickableSurface`'s
   `pressScale` + overlay, `bounceClick` and every implicit `selectable`/`toggleable` indication with explicit
   `pressable(feedback = …)` per the A4.1 table. A checkbox, radio or switch with no callback no longer eats its
   row's taps (B20). WP02-M2's `verifyCodeRules` will reject a bare `.clickable(` in features, so leave none behind.
2. **Haptics** (A4.2): `AppHaptic { Selection, ToggleOn, ToggleOff, Threshold, Confirm, Reject, LongPress }`,
   silent by default, `LocalHapticsEnabled` from the theme; remove the default `HapticEffect.Tap`.
3. **Motion** (A4.3): `AppSprings` (precomputed per motion style, held by `AppTheme`, exposed as `AppTheme.springs`)
   with `press`, `release`, `selection`, `screen`, `sheet`, `layout`, `emphasis`, fades, stagger, press values,
   navigation values. Phase A takes the numbers from the plan as Kotlin constants in `AppMotion.kt`; phase B replaces
   them with `DesignTokens`. Remove `sheet()` misuse, `pressPop()`, `tracking()`; spatial moves become springs (sheet
   dismiss, snackbar/toast, accordion, month slide); stagger in dp. `ReduceMotion` becomes one observed `State`
   (`ContentObserver` on `ANIMATOR_DURATION_SCALE`) provided by `AppTheme`. Migrate every caller, including
   `core/navigation`'s transitions if WP04 has merged (otherwise WP04 keeps its private spring and you migrate it
   when you merge after it).
4. **Typography** (A4.4): the role scale; voices change weights only; fonts download exactly the weights the voices
   use; remove the `includeFontPadding` suppression. Migrate every usage with the old → new mapping in A4.4 through
   the sweep script (after WP02-M1). **Font loading without reflow** (A4.4, `googlefonts`): `preloaded_fonts`
   manifest meta-data and font-certificate resources for the chosen families and weights; `StartupViewModel` holds
   the splash until `FontFamily.Resolver.preload` completes, bounded at 150 ms; `AppTheme` uses the downloadable
   family only if the preload finished in time, else the platform family for the whole process. Test: with a resolver
   that never completes, the theme picks the platform family and nothing recomposes when the font arrives later.
5. **Colours** (A4.5): add the roles (`backgroundGrouped`, `surfaceGrouped`, `surfaceElevated`, `fill`, `separator`,
   `accentContent`, `highlight`, `scrim`, `focusRing` actually used, `shadow`, `barIndicator`), compute `onAccent` and
   friends in Kotlin from luminance, remove hard-coded `Color.White` foregrounds, destructive as red-on-tint, visible
   dark skeleton. Extend `PaletteContrastTest` (text 4.5:1 on every background, non-text 3:1, `accentContent` on
   surfaces, every style and theme) and add the bar rule of A4.8: `barIndicator` ≥ 3:1 against every bar treatment's
   surface, or, for a style with `indicator = Subtle`, `accentContent` ≥ 4.5:1 on the bar surface.
6. **Components** (A4.7): build the core set (including `AppAvatarGroup`), the four optional groups (packages
   `component/pickers`, `component/fields`, `component/data`, `component/collections`, each owned by its feature TOML so
   it disappears when off; `collections` = `AppCarousel`, `AppReorderableList`, `AppImageViewer` as specified in A4.7),
   the foundation pieces, and the deletions. **Layering (A3.9):** `AppOverlayHost` + `LocalOverlayHost`, installed by
   `AppTheme` at the window root, with layer 4 (alerts, HUD, `AppLoadingOverlay` blocking input for the whole
   window) and layer 5 (the `AppToast` queue laid out above `LocalBottomChrome`); `AppTheme` also provides the
   window's `LocalBottomChrome` holder. `AppAlert(visible = …)` and friends called from a screen render through the
   host, never inside the screen. `AppScaffold` provides a fresh `LocalTopChrome` holder that its top bar writes;
   `ChromeInsetsTest` composes two scaffolds with different top bars at once and asserts each keeps its own value and
   neither recomposes the other. `AppBottomActionBar` asserts in debug builds that `LocalTabBarVisible` (WP04 adds it
   to `Chrome.kt`) is false, and writes its settled height through the shell API when it is the settled top entry. Fix every bug in audit designsystem §6 and infra §2.1–2.2 with a test each where the
   behaviour is testable on the JVM (Robolectric Compose UI tests): wheel picker stale collector, stepped slider slow
   drag and touch-to-scroll, pull-to-refresh stale state and per-delta launches (VitFleet version), currency caret,
   sheet Back and double dismiss, swipe-actions open-row tap and RTL, top-bar title overlap (title in the Row with
   `weight(1f)`), timeline connector, loading overlay that really blocks input, toast lifecycle and duplicates.
   No coroutine launch per pointer event anywhere (A11.3 rule 5); every animated value read in layout or draw.
7. **Sheets end to end** (A3.7): `AppSheet` + `AppSheetState` (detents, nested scroll hand-off, IME insets, close
   button, idempotent `dismiss(onGone)` guarded by a `MutatorMutex`, `dismissing` flag, content measured once at the
   large detent and only re-placed, pinned footer reading `LocalSheetVisibleHeight` in its own `layout {}`,
   rubber-band past large) and `SheetScene` (Navigation 3 `OverlayScene`; Back disabled while dismissing; linear
   predictive dismiss). The scene is the sheet strategy of WP04's shell-level `PresentationHost` (A3.9), not of the
   tab hosts; agree the `presentation = Sheet(detents)` metadata shape with WP04 through the orchestrator early.
   `AppActionSheet` builds on the same presentation; `AppMenu` uses a `Popup`. Tests: double Back during a dismiss
   pops once; a drag frame does not remeasure content.
8. **Accessibility** (A4.6): all items, with Compose semantics tests for text fields, toggle rows, touch-target sizes.
9. **Catalog**: opens in the project's style (through the public `AppTheme.defaults`; `DesignTokens` stays internal
   to `:core:designsystem`), Feel section respects the chosen mode and style (C1), every public component and token shown
   (C3, C4), `AppLoadingOverlay` over the page (C5), insets (C6), no window-background flash (C7), RTL masonry (C8),
   environment bar with theme, style, motion, RTL, font scale and reduce motion (C10), duplication removed (C11),
   build leftovers removed (C12), `--es section <Name>` deep link, a live frame-time readout on the catalog activity
   only (JankStats, catalog dependency only). Sections for the optional groups exist only when the feature is on.
   `generator/tests/test_catalog_coverage.py`: every public `@Composable fun App*` in the design system appears in
   some catalog section (C13).
10. **Checkpoint 1 recordings** (MASTER-PLAN B.5): from a catalog release build on the phone, `record.sh` videos and
    frame strips of press states (filled, tinted, plain buttons; rows; cards), the switch (tap and drag), the
    segmented control (tap and drag), a sheet moving between detents, and the toast. Use the `record.sh` in WP04's
    worktree read-only (`$OV/wt/WP04/templates/android/tools/perf/record.sh`) or `$OV/scratch/device/rec_full.sh`.
    Save under `$P/cp1/` with a one-page index (`$P/cp1/README.md`) that names the spring values used; the orchestrator
    combines it with WP04's set for the user.

## Phase B (wave 1, after WP01 merged)

1. `git merge overhaul/multiplatform-v2`.
2. Write the values the user picked at checkpoint 1 (screen response, press, release, selection, sheet springs) and
   the values you settled on in phase A into `tokens/*.json`; extend the emitter if you need a field.
   `python3 -m genkit.tokens --write` emits
   `core/designsystem/src/main/kotlin/com/base/app/core/designsystem/theme/tokens/DesignTokens.kt`; make `AppTheme`,
   `AppSprings`, `AppTypography`, `AppColors`, `AppDesignStyle`, `AppMetrics`, `AppFonts` read it. No literal token
   value remains in those files.
3. Generator: `targets/android/look.py` emits tokens for the spec (brand ramps, style, motion, haptics, fonts) and the
   regex appliers are deleted. `AppRoot`'s `AppTheme(...)` call becomes `AppTheme { … }` (defaults from the tokens):
   change that call site (touch-for-compile in a WP04 file) only together with deleting `apply_feel`.
4. `googlefonts-off` becomes an `opt-else` block in `AppFonts.kt`; delete `generator/variants/googlefonts-off`.
5. `web.py` emits the full resolved tokens into the catalogue (`tokens` object) for the website. After any token or
   emitter change run both `python3 -m genkit.tokens --write` and `python3 -m genkit.core.catalogue --write` and
   commit every emitted file (MASTER-PLAN A9.2); on a merge conflict in an emitted file, re-run both instead of
   resolving by hand. `AppTheme.defaults` (public) exposes design style, motion style, haptics and fonts.
5a. Feature TOMLs (they exist only from WP01): create `pickers.toml`, `formfields.toml`, `datadisplay.toml`,
    `collections.toml` (group "Design", off by default, each owning its component package and its catalog section
    file), and update
    `googlefonts.toml` and `catalog.toml` so their descriptions say exactly what ships now. Run
    `python3 -m tests.consistency --quick` with each group on alone and all off.
6. Merge integration again and do the touch-for-compile sweep for every renamed API (feature screens, `core/ui`,
   `app`, `core/devtools`, navigation transitions), in one commit.

`ACCEPT OK`:

```bash
#!/usr/bin/env bash
set -euo pipefail
export ANDROID_HOME=$HOME/Android/Sdk
OV=/home/crazyhusir/Documents/projects/tools/.overhaul; W=$OV/wt/WP03; L=$OV/bin/locked; O=$OV/out/WP03
cd $W/templates/android && $L gradle ./gradlew build --console=plain
$L gradle ./gradlew :core:designsystem:testDebugUnitTest --console=plain    # contrast (incl. bar indicator), press, wheel, slider, refresh, sheet, a11y, ChromeInsetsTest, overlay host, font fallback
cd $W/generator
python3 -m unittest discover -s tests -t .
python3 -m genkit.tokens --check
python3 -m genkit.core.catalogue --check
python3 -m unittest tests.test_catalog_coverage
cd $W/templates/android
! grep -rn "composed {" core/designsystem core/ui catalog --include=*.kt
! grep -rn "material.ripple\|material3.ripple\|LocalIndication provides AppIndication" --include=*.kt .
! grep -rn "HapticEffect.Tap\|haptic: HapticEffect? = " core/designsystem --include=*.kt
! grep -rn "\.clickable(" feature core/ui --include=*.kt
# a generated project with a custom look carries it through tokens, not regexes (fixture yours: package
# com.example.wp03.look, design_style Editorial, motion_style Calm, accent #8E3B46, font "Plus Jakarta Sans", catalog on)
cd $W/generator && python3 create_project.py --spec tests/fixtures/v2/custom-look.json --out $O/look --no-zip --force
TOK=$(find $O/look/core/designsystem -name DesignTokens.kt -path '*theme/tokens*')

grep -A20 'object Defaults' "$TOK" | grep -q 'Calm'
(cd $O/look && $L gradle ./gradlew :app:assembleDevDebug :catalog:assembleRelease --console=plain)
echo ACCEPT OK
```

Then, on the device (one lock hold per command): install the catalog release APK of `$O/look`, save screenshots of
every section in light, dark and 2.0× font scale to `$P/catalog/<section>-<light|dark|2x>.png` (drive sections with the
`section` extra), and list them in the handoff. Check on the phone that buttons scale, text buttons dim, rows highlight,
nothing flashes grey, tabs and segments give a selection tick only, and text does not swap fonts after the first frame.
