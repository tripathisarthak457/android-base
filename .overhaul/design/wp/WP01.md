# WP01 Generator engine v2, spec v2, catalogue v2, token pipeline

Wave 0, starts right after WP00. Python 3.12, standard library only (PyYAML may be used by tests and skipped when
absent; never by the generator). No Gradle build is required: your safety net is a byte-level comparison of
generated projects before and after.

## Why

`genkit/render.py` is an 800-line module mixing the marker engine, renaming, copying, colour science, keystores, zip
and regex "appliers" tied to Android file paths; `spec.py` mixes the platform table, the feature catalogue, presets
and validation. Two new templates (Compose Multiplatform, SwiftUI) need the same engine, and the audits found real
bugs in exactly these places: double renaming breaks names that contain a template token, `--icon` writes broken XML,
validation accepts Kotlin keywords and rejects valid packages, `$` accepts trailing newlines, silent no-op appliers,
internal errors reported as user errors, temp trees leaking secrets.

### 1. Engine split (`genkit/core`, `genkit/brand.py`, `genkit/targets`)

Create the modules of MASTER-PLAN A1.1 and move code, behaviour first, then fix:

- `core/markers.py`: the A1.5 grammar. Syntax table by extension; block, inline, `opt-else`, `generated` points and
  regions; `EXPR` with `|`, `&`, `!`; every error raises `TemplateError(path, line, message)`. Keep the old inline
  `<opt:!x>CODE` form (it is the A1.5 inline form with `!x`). Region names are checked against the **emitted** file
  set (a supplied region whose file was removed by `owns` or a marker block is fine); `[regions] required` is checked
  only against the full template.
- `core/rename.py`: `IdentityRenamer` (A1.6). One compiled alternation, longest token first, per-token boundaries
  exactly as the A1.6 table: `snake` treats `_` as a separator (so `base_app_default`, `base_app_urgent`,
  `base_app_silent`, `base_app_promotions` and `base_app_datastore_key` rename, `database_app` does not), and `path`
  also matches after a JVM descriptor `L` (`Lcom/base/app/…;` in baseline-profile rules). Applied to template lines and
  template paths exactly once.
- `core/copy.py`, `core/package.py` (deterministic zip: sorted entries, fixed timestamp, mode bits for `gradlew` and
  `tools/perf/*.sh`, one root folder), `core/record.py` (always writes v2), `core/headless.py`, `core/catalogue.py`,
  `core/translations.py`, `core/prompts.py` (validate each answer immediately, audit 4.7), `core/pipeline.py`.
- `brand.py`: the colour science from `render.py:587-804`, with `Rgb` and constants defined before use and
  `colorsys` imported at module level. `prompts.describe_brand_colours` imports public names only.
- `targets/__init__.py` with `REGISTRY`; `targets/android/`: `target.py` (validation of `android.*` fields, identity,
  regions), `settings.py` (fills `app-config`, `app-name`, `launcher-background`, `supported-locales`), `tabs.py`
  (today's tab emission, moved), `scaffold.py` (today's scaffolder, moved; WP02 rewrites it), `modes.py` (a stub that
  raises `SpecError("modular is not available yet")` until WP02 implements it), `icons.py` (monochrome regex fixed with
  `\g<1>…\g<2>`), `keystores.py` (PKCS12 single password with a warning, ISO-8859-1 + `\uXXXX` properties,
  `-storepass:env` instead of argv), `look.py` (the legacy `apply_fonts`, `apply_feel`, `apply_accent`,
  `_apply_on_brand`, each now counting substitutions and raising `RenderError` when an expected one did not happen),
  `variants.py` (today's overlay, unchanged; WP03 and WP06 retire it).
- Delete `render.py`, `readme.py` and `catalogue.py`'s `GROUPS`/`HEADLINES` once nothing imports them.

### 2. Manifest (`core/manifest.py`) and the Android catalogue files

- `templates/android/template.toml` exactly as MASTER-PLAN A1.2 shows (identity, regions, files, groups).
- `templates/android/features/<key>.toml`: one per **current** feature (36), same key, title, description, default,
  requires, owned paths (`owns`), `implied_only`, plus `group` and `headline` moved from `catalogue.py`, and `legacy`
  keys where today's `LEGACY_FEATURES` maps to them. A `legacy` entry is either a string (that key means this
  feature in any spec) or `{ key = "…", schema = 1 }` (only when upgrading a spec of that schema). Several features
  may list the same versioned key, which is how WP06 maps a v1 `firebase` to `crashlytics` + `firebaseanalytics` +
  `remoteconfig` while `firebase` stays a v2 key (the implied base). Do not add or remove features: the owning packages do that
  (A5.1 owner column), each adding its own file and its `legacy` keys.
- `templates/android/removed.toml`: `key = "note"` for removed keys (start with today's removed ones:
  `fastlane`, `architecturetests`, `screenshottests`). Packages that remove features append to it. It is listed in
  `[files] template_only`, so it never ships in a generated project.
- `template.toml` `[target] status` accepts `available | beta | coming_soon | hidden`; `beta` requires a
  `status_note`, and both appear in the catalogue.
- `implied_only = true` only for `firebase` (A1.4); `analytics` and `forms` are ordinary features pulled in through
  `requires`.
- `templates/android/presets.toml`: today's three presets 1:1, with `everything = { all = true }` meaning every
  non-implied feature (so new features join it automatically).
- `resolve_features`, presets, upgrade of legacy keys all read the manifest. A feature's `owns` path that does not
  exist in the template is an error at load time.

### 3. Spec v2 (`core/spec.py`)

Implement A1.3: the model, `upgrade()` for v1 (flat Android fields → `android`, `platform = "android"`,
`architecture = "compact"`), legacy keys through the manifest, notes for every change, unknown top-level fields an
error in v2, `display_name`, limits (`MAX_FEATURE_MODULES = 12`, lengths, segments, languages ≤ 10, keystores ≤ 4),
`fullmatch` everywhere, Kotlin hard and soft keywords + Java reserved words for package segments and module names
(Swift keywords live in `targets/ios`), `java`/`javax`/`kotlin` first segments refused, Pascal-name collisions
between modules refused. `architecture = "modular"` validates but `modes.py` refuses it until WP02.

### 4. Headless contract and CLI

- `generate_headless.py --target <t> OUT.zip < spec.json` per A1.8: exactly one JSON object on stdout, exit 0/2/1,
  `kind` invalid/internal, traceback in `detail` for internal failures only, 32 KB stdin cap, `elapsed_ms`,
  `zip_bytes`, `resolved_features`, `notes`, `warnings`, `ignored_fields`, `generator_commit`. Staging under
  `$TMPDIR` (the API points it at its work directory).
- `create_project.py`: `--target` (default android), `--json` prints only JSON, `--out` semantics fixed (A1.7),
  `--force` deletes only that path, `--dry-run --json` as A1.10, and `--set key=value` (repeatable; dotted keys such
  as `android.min_sdk`; values parsed as JSON when they parse, else strings) applied after loading and before
  validation. Every package uses `--set package_name=com.example.<wp>.<name>` for device builds (Part D 14c), so
  test it. `add_feature.py` appends the tab last and writes translations for every shipped language.

### 5. Catalogue v2

`python3 -m genkit.core.catalogue --json` per A1.9, for every registered target (only android exists now; the
registry tolerates missing templates for multiplatform/ios by omitting them). `rules` carries every limit and regex
the website must enforce; `tokens` carries the resolved tokens from step 6. `--write` writes
`web/frontend/lib/catalogue.json` (sorted keys, two-space indent, trailing newline) and `--check` compares a fresh
emission with it, ignoring `generator_commit`; `test_catalogue` runs `--check`. Commit the emitted file.

### 6. Tokens

- Create `tokens/{foundation,typography,motion,palette,styles}.json` per A9.1. Port today's values from
  `templates/android/core/designsystem/.../theme/{Palette,AppColors,AppDesignStyle,StyleTones,AppMetrics,AppMotion,AppTypography}.kt`
  where they exist, and add the new A4.3 springs, A4.4 type roles and A4.5 roles with the plan's values (WP03 tunes
  them later; you own the schema).
- `genkit/tokens/{__init__,kotlin,swift,web,__main__}.py`: load, validate, resolve against a spec (brand ramps from
  `brand.py`), emit. Kotlin output shape: `internal object DesignTokens` with nested objects `Spacing`, `Radii`,
  `Sizes`, `Type` (one entry per role with size, line height, tracking, weight per voice), `Motion` (per motion style:
  each spring as stiffness + dampingRatio precomputed, fades, stagger, press values, navigation values), `Palette`
  (ramps and roles per theme as `Color(0xAARRGGBB)`), `Styles` (per design style), `Defaults` (design style,
  motion style, haptics, font names: the spec's choices). Swift output mirrors it with `enum DesignTokens`.
- `python3 -m genkit.tokens --check` compares every checked-in emitted file with a fresh emission and lists
  differences; `--write` rewrites them. Today no checked-in copy exists yet (WP03 adds the Android one), so `--check`
  passes with zero files and a test covers emitter output with snapshot strings.

### 7. Translations and README

- Split `generator/translations/<lang>.json` (one nested object per language, keyed by module res path) into
  `generator/translations/android/<lang>/<module-slug>.json`, one flat `name → text` file per module per language
  (`app.json`, `core-ui.json`, `feature-settings.json`, …; the slug is the module path with `/` → `-`). Seven
  packages add or remove strings; with one file per module each edits only its own modules' files, and a new key
  never changes a line another package touched. `core/translations.py` reads the split layout; a test asserts the
  split is lossless against the old files.
- Convert `genkit/readme.py`'s text into `templates/android/README.md` with `<!-- <opt:x> -->` blocks and
  `<!-- <generated:name> -->` regions for computed values (app name, commands, enabled features). Output must equal
  today's generated README for the baseline specs.

### 9. Golden comparison (acceptance safety net)

Regenerate every baseline spec into `$O/after/` and compare with `$O/before/` by script, not by eye. Write
`$O/golden-allow.txt`: one line per allowed difference, `<spec>/<relative path><TAB><reason>` (globs allowed), covering
`generator-spec.json` (v2 shape and commit), files affected by the bug fixes (hostile names now correct, snake tokens
such as `base_app_default` now renamed, icons XML valid, keystore properties encoding), and whitespace-only changes
next to removed blocks (A1.5 collapse rule). `$O/golden_check.py` runs `diff -rq`, fails on any differing or
missing path not matched by the allow-list, and for whitespace-only entries verifies with `diff -w` that only
whitespace changed. Copy the allow-list into the handoff.

### 10. Repository tools

when they land; its group table includes `androidx.room3` and `io.github.kyant0`. WP13 extends it if a template adds
another source of versions.

## Acceptance

`$O/accept.sh`, run in the background with its log in `$O/logs/accept.log` (MASTER-PLAN §0); it must end with
`ACCEPT OK`:

```bash
#!/usr/bin/env bash
set -euo pipefail
OV=D:/projects/tools/.overhaul; W=$OV/wt/WP01; O=$OV/out/WP01
cd $W/generator
python3 -m unittest discover -s tests -t .                       # all pass; PyYAML-dependent tests may skip
python3 -m tests.consistency --quick                              # presets × compact, singles, pairwise: clean
python3 -m genkit.tokens --check
python3 -m genkit.core.catalogue --check                          # the checked-in website copy is current
python3 -m genkit.core.catalogue --json | python3 -m json.tool > /dev/null
for f in tests/fixtures/v1/*.json; do python3 create_project.py --spec $f --out $O/v1/$(basename $f .json) --no-zip --force; done
python3 generate_headless.py --target android $O/p.zip < tests/fixtures/v2/standard.json \
  | python3 -c 'import json,sys; d=json.load(sys.stdin); assert d["ok"] and d["zip_bytes"]>0'
set +e; echo '{"schema":2,"platform":"android","app_name":"x"}' | python3 generate_headless.py --target android $O/bad.zip > $O/bad.json; rc=$?; set -e
test $rc -eq 2
python3 -c 'import json,sys; d=json.load(open(sys.argv[1])); assert d["kind"]=="invalid"' $O/bad.json
python3 create_project.py --spec tests/fixtures/v2/standard.json --set package_name=com.example.wp01.std --dry-run --json \
  | python3 -c 'import json,sys; json.load(sys.stdin)'
test ! -e genkit/render.py && test ! -e genkit/readme.py
! grep -rnE "import (render|readme)|from \.+(render|readme) " genkit     # grep, not a build: a plain negation is safe
python3 $O/golden_check.py $O/before $O/after $O/golden-allow.txt
echo ACCEPT OK
```

Optional but recommended (in the background): one Gradle build of the `standard` output to prove nothing structural
changed: `cd $O/after/standard && $L gradle ./gradlew :app:assembleDevDebug --console=plain`.
