# WP07 Compose Multiplatform template (Android + iOS)

Phase A in wave 2 (after WP01, WP02-M1 **and WP04** have merged: WP04's merge frees a Gradle slot and gives you the
finished shell to port). Phase B in wave 3 (after WP03 and WP05 have merged and checkpoint 2 has fixed the glass
variant). Phase C (deep links and auth) right after phase B. Kotlin Multiplatform, Gradle (heavy), the phone (light,
phase B). Lock budget: Gradle about 6 h (A 2.5, B 2.0, C 1.5), adb about 1 h. No Mac: the iOS half is written,
statically checked here, and compiled by the CI macOS job (WP13); the site shows the target as "Beta: iOS unverified"
until that job is green on the release commit.

## Why

The user wants a Compose Multiplatform generator for Android and iOS with the same architecture and design-system
quality as the Android one. AGP 9 forbids applying the Android application or library plugin together with KMP, so the
app is its own module and libraries use `com.android.kotlin.multiplatform.library` (research §4.2). The template must
reuse what the overhaul builds for Android (pure `:core:common`, MVI, shell design, design system, glass tiers)
rather than invent a second style, and must stay identical to it after the overhaul, which is what the sync check is
for.

## Phase A: foundation (wave 2)

1. **Build**: `settings.gradle.kts` (type-safe project accessors), root build with plugin aliases `apply false`,
   `gradle.properties` with the **same** `org.gradle.jvmargs` and Kotlin daemon args as the Android template (one
   shared daemon), the same Gradle wrapper version, `kotlin.native.enableKlibsCrossCompilation=true` (keep only if it
   works on Linux). Catalogue (stable only): Kotlin and AGP as the Android template, CMP plugin 1.12.1, compose
   resources 1.12.1, JetBrains `navigation3-ui` 1.1.2, JetBrains `lifecycle-viewmodel-compose` and
   `lifecycle-viewmodel-navigation3` 2.11.0, `androidx.navigationevent` 1.2.0, Koin BOM 4.2.2, Ktor 3.6.0 (okhttp,
   darwin), kotlinx serialization 1.11.0, coroutines 1.11.0, DataStore preferences-core 1.2.1, Room 3 3.0.3 +
   `sqlite-bundled`, Coil 3.6.3 (`coil-compose`, `coil-network-ktor3`), KSP 2.3.12. Pin the androidx Navigation 3
   version that `androidApp` resolves (check `./gradlew :androidApp:dependencies`), so the JetBrains artefacts never
   pair with an unverified androidx version.
2. **build-logic** (A7.1): `KmpLibraryConventionPlugin` (`kotlin { android { namespace; compileSdk; minSdk;
   withHostTest {} } ; iosArm64(); iosSimulatorArm64() }`, the `android {}` DSL, not the deprecated `androidLibrary {}`;
   verify the extension type against AGP 9.4.1, risk R9), `KmpComposeConventionPlugin` (catalogue coordinates, not the
   deprecated `compose.*` aliases), `KmpFeatureConventionPlugin`, `KmpDataConventionPlugin`,
   `AndroidApplicationConventionPlugin`, `ModuleGraph` with the compact rules of A2.4 and the pure-module check.
3. **Modules** (A7.1): `core/common` (copy the Android `:core:common` sources into `commonMain` unchanged; if a file
   needs a change to be common, the Android one was not pure: report it), `core/mvi` (same `MviViewModel` source),
   `core/designsystem` (phase A: theme from the emitted `commonMain` `DesignTokens.kt`, and only the components the
   reference screens need: text, button, section/row, text field on `TextFieldState`, state view, a basic tab bar),
   `core/ui` (MviScreen, MessageHost, `UiText` over compose resources), `core/navigation` (the merged Android shell
   ported per A3.2–A3.4a and A3.9: KeptTabs v2, slide-only transitions with the draw-phase scrim, BackGate per host,
   `NavGuard`, presentation host, one tab host; polymorphic `SavedStateConfiguration` for keys; iOS back gesture through
   `navigationevent`; the A3.10 outcome if it ports to 1.1.2), `core/network` (`NetworkClient` and `AppError` mapping
   like Android; `NetworkMonitor` expect/actual: `ConnectivityManager` / `NWPathMonitor`), `core/datastore` (path
   expect/actual), `core/database` (`database`: Room 3, `BundledSQLiteDriver`,
   `kspAndroid`/`kspIosArm64`/`kspIosSimulatorArm64`), `core/testing`, `data/sample`, `feature/sample`
   (offline-first with `database`), `feature/settings`, `feature/onboarding`, `shared` (umbrella, static framework
   `Shared`, `App.kt`, `di/AppModules.kt`, `iosMain/MainViewController.kt`), `androidApp` (flavours dev/prod,
   `AppEnvironment` from BuildConfig, `MainActivity`, `Application` starting Koin), `iosApp` (`project.yml` per A7.1
   with the pre-build script and `ENABLE_USER_SCRIPT_SANDBOXING = NO`, `BaseAppApp.swift` hosting
   `MainViewController()`, `Info.plist` with **`CADisableMinimumFrameDurationOnPhone = true`** (Compose renders at
   60 Hz on ProMotion iPhones without it), asset catalogue, `Config/{Dev,Prod}.xcconfig` with `API_BASE_URL`).
4. **List what cannot port to JetBrains navigation3-ui 1.1.2** (mid-flight predictive back during a push, anything
   else WP04's handoff relies on) and what the template does instead (`BackGate` holds gestures during pushes).
5. **DI**: Koin classic DSL modules per module; `KoinModulesTest` (Android host test) calls `verify()` on the app's
   module list; `koinViewModel()` in navigation entries.
6. **Sync check** (A7.2): `templates/multiplatform/sync.toml` lists every copied pair (Android path ↔ `commonMain`
   path) with its allowed differences (named `expect`/`actual` seams, resource access lines, files that are
   Android-only), each with a reason; `tools/sync_check.py` normalises imports and fails on any other difference;
   `generator/tests/test_sync.py` runs it. Phase A covers `core/common`, `core/mvi` and the shell; phase B adds the
   design system and glass.
7. **Generator target** (`targets/multiplatform`): `template.toml` (`status = "beta"`, `status_note = "Beta: the iOS
   app is not yet verified on a Mac"`; identity: `com.base.app`, `com/base/app`, `BaseApp`, `baseapp`; regions
   `app-config`, `ios-config`, `settings-includes-data`, `settings-includes-feature`, `shell-tabs`, `koin-modules`),
   `features/*.toml` for the v1 set (A7.3), `presets.toml` (lean: network, coil; standard: lean + sample, settings,
   onboarding, database, language; everything: all), validation of `android.*` and `ios.*` (bundle id default from the
   package with `_` → `-`, deployment target ≥ 15.0), architecture `compact` only, translations into
   `composeResources/values-<q>/strings.xml`, token emission into `commonMain` through `kotlin_common.py`, scaffolding
   of `feature_modules` (KMP data + feature modules in the A2.3 shape, registered in Koin and the shell). Run both
   `--write` commands and commit the emitted files.
8. **Tests**: `generator/tests/test_target_multiplatform.py`: every preset generates; no markers or identity tokens left;
   settings includes ↔ directories; every Koin module referenced exists; `project.yml` parsed (PyYAML when present)
   with the right bundle id, target name and pre-build script; `Info.plist` has
   `CADisableMinimumFrameDurationOnPhone` set to true; scaffolded modules present in settings, Koin and tabs; the
   catalogue shows `status = "beta"` with its note. The shell tests (`KeptTabsTest`, `BackGateTest`, `RapidBackTest`,
   `NavGuardTest`, `ChromeLayeringTest`) ported to `commonTest` and run as Android host tests.

## Phase B: design system, shell parity and glass (wave 3)

1. `git merge overhaul/multiplatform-v2` (brings WP03, WP05, WP02-M3 and the checkpoint values).
2. Port the overhauled Android design system to `commonMain`: `Pressable` (Modifier.Node is common), springs,
   typography, colour roles, the core component set of A4.7, `AppTabBar` with the A4.8 behaviours,
   `AppFloatingToolbar`, `Chrome.kt`, `AppOverlayHost`, sheets with `SheetScene`. Haptics and reduce motion as
   expect/actual (iOS `UIImpactFeedbackGenerator`/`UISelectionFeedbackGenerator`, `UIAccessibility.isReduceMotionEnabled`).
   Optional groups stay Android-only in v1 (state it in the handoff and on the platform card list).
3. Reconcile the shell with WP04's merged implementation (KeptTabs, BackGate, NavGuard, CoverScrim, BarAnchor,
   presentation host, entry identity): same behaviour, `commonMain` APIs. Extend `sync.toml` to the design system and
   glass; `sync_check.py` must pass.
4. Glass (`liquidglass`): Kyant 2.0.1 KMP, `GlassStage`, tiers with expect/actual inputs (Android as WP05; iOS reduce
   transparency, low power mode, thermal state), `GlassSurface`, `LiquidLens`, `LiquidTabs`, the checkpoint 2 variant;
   **iOS defaults to `Frosted`**, `GlassPolicy.liveOnIos = false` until a device check (risk R5).
5. Copy `tools/perf/` from the Android template (it works for `androidApp` with `--variant devRelease`), add the
   dev-flavour launch extras (`perf.skipOnboarding`, `perf.fakeSession`, `glass.quality`, the `perf.shell` and
   `perf.glass` log lines) to `androidApp/src/dev` the way WP04 and WP05 did, and add the `cmp_android` column to
   `gates.toml`: the §2 solid column (Android CMP renders through the same Jetpack Compose; no looser numbers), minus
   the rows that need the benchmark module, and `cmp_android_glass`: the §2 glass `Live` rows for tabs, push/pop,
   scroll, idle and PSS.
6. Measure on the phone; at most three measure → fix iterations per failing gate, then escalate (B.1).

## Phase C: deep links and auth (wave 3, after phase B)

1. `deeplink`: the Navigation 3 KMP deep-link API, Android intent filters in `androidApp`, an iOS URL scheme in
   `project.yml`/`Info.plist` routed through `MainViewController`, the held-once `PendingDeepLink` rule, a link to a
   presented key selecting its tab first. Tests: the Android `PendingDeepLinkTest` ported to `commonTest`.
2. `auth`: sign-in and sign-up screens and ViewModels from the Android template (text-field contract of A6.1),
   `SessionTokens`, and secure token storage as `expect`/`actual` (Android: Keystore-encrypted DataStore; iOS:
   Keychain through `Security` framework calls). Tests: the token store contract in `commonTest` against a fake, the
   Android `actual` in a host test; the iOS `actual` passes the static checks and compiles in CI.
3. Update `features/*.toml`, the presets, the "not in v1" list in the generated README and the catalogue (run both
   `--write` commands).

Phase C acceptance: generate `mp-everything` with both features and build `:androidApp:assembleDevDebug check`;
`test_target_multiplatform` covers both features; `sync_check.py` passes.
