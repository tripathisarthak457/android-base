# WP12 Docs for agents and people

Wave 3. Android and repository docs start once WP02 (all milestones), WP03, WP04, WP05, WP06 and WP14 have merged and
the checkpoint values are in the tokens; the multiplatform and iOS docs follow WP07 (phases B and C) and WP08.
Markdown, plus one Python test and one agent-run acceptance. Gradle only to check that documented tasks exist and to
build the fresh agent's result. Lock budget: Gradle about 0.7 h.

## Why

Agents build what the docs tell them. Today's `AGENTS.md` files are good on code quality but say nothing about motion,
performance, press feedback, glass, chrome insets or how to measure smoothness, and the generated project's only run
instruction is a debug install (device-baseline F7: debug is 10× jankier). The user wants every file an agent reads,
in the repo and in every generated project, to lead to polished, smooth apps, and the project documented perfectly.

## Acceptance

`$O/accept.sh` (`set -euo pipefail`, in the background, ends with `ACCEPT OK`):

```bash
cd $W/generator && python3 -m unittest tests.test_docs -v && python3 -m unittest discover -s tests -t .
python3 create_project.py --spec tests/fixtures/v2/everything.json --out $O/everything --no-zip --force
(cd $O/everything && $L gradle ./gradlew tasks --all --console=plain) > $O/tasks.txt
bash tests/docs_tasks.sh $O/everything $O/tasks.txt
echo ACCEPT OK
```

Then run every command in the generated `AGENTS.md` "Build and verify" section once on `$O/everything` and paste the
outcome in the handoff.

**Fresh-agent run (MASTER-PLAN A12.6).** The orchestrator starts an agent with no other context, gives it only a
generated `standard` project (`$O/fresh/standard`, a git repo) and the task "add an `orders` feature with a list and a
detail screen, a setting that filters it, and a sheet to create an order". Its result must pass `./gradlew check`
(including `verifyCodeRules` and the module guards) and a Part D review by a second fresh agent. For each failure,
find the doc gap that allowed it, fix the docs, regenerate, and repeat until one run passes cleanly. The handoff
records each run's failures and the doc change that addressed it.
