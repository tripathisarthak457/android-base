## 0. Decisions this research supports (TL;DR)

1. **Versions:** the template is close to current. It is behind on **Navigation3 1.1.7 → 1.2.0** (stable 2026-09-23),
   Kotlin 2.4.20 → 2.4.21, WorkManager 2.11.2 → 2.12.0, Paging 3.5.1 → 3.5.2, core-ktx 1.19.0 → 1.19.1,
   Kover 0.9.9 → 0.9.11, **Firebase BoM 34.19.0 → 35.0.0** (major release; minSdk 24, so template minSdk 26 is fine), and
   the Gradle wrapper 9.7.1 → 9.8.1. **Room 3.0.3** (`androidx.room3`, KMP and coroutines only, stable 2026-07-01) is a
   new artifact group that `check_versions.py` cannot see.
2. **Liquid glass:** use **Kyant backdrop 2.0.1** (`io.github.kyant0:backdrop`, plus `shapes` 1.2.1). It has been
   Kotlin Multiplatform since 2.0.0 (android, desktop JVM, iosArm64, iosSimulatorArm64, macosArm64, js, wasmJs). Blur
   and vibrancy need **API 31+**. Lens refraction and the highlight shader need **API 33+**. **Below API 31 it draws an
   unblurred copy of the background**, so a frosted fallback is required (template minSdk is 26). For high FPS:
   - Record one `LayerBackdrop` per screen stage.
   - Use real glass only on floating chrome. Draw content-level glass instead of sampling.
   - Keep the `effects {}` lambda **static**. It is snapshot-observed, so every state it reads rebuilds the RenderEffect chain.
   - Animate press feedback through `layerBlock` (layer properties only).
   - Pass `shadow = null` and `highlight = null` wherever they are not seen.
   - **Haze 2.0.1** is the alternative. Its `haze-glass` is still `@ExperimentalHazeApi`, but it has the better fallback
     story and benchmarks.
3. **Transitions:** the template's push **fades the whole outgoing screen with alpha**. Under
   `CompositingStrategy.Auto`, alpha below 1 forces a **full-screen offscreen buffer** for the whole transition
   **[source]**. The fade also runs on a 250 ms tween against a spring slide. Replace it with:
   - an iOS-style parallax: incoming slides 100%, outgoing slides about 30%;
   - a draw-phase scrim (one `drawRect`, no offscreen layer);
   - one spring for every animated property. iOS `Spring(duration: d, bounce: b)` maps to Compose
     `spring(stiffness = (2π/d)², dampingRatio = 1 − b)`.
   
   Tabs should switch **without a slide**: instantly as on iOS, or with a very short crossfade.
4. **No ripple:** Compose's foundation layer has no ripple. Ripple comes only from material's `LocalIndication`. The
   template already supplies its own `IndicationNodeFactory` through `LocalIndication`, which is the right mechanism.
   iOS-like press feedback means opacity or scale, animated with springs.
5. **Compose Multiplatform generator (2026 layout):**
   - Modules: `shared` (KMP library, umbrella framework), `androidApp` (separate module, which **AGP 9 requires**),
     `iosApp` (Xcode project, preferably generated by XcodeGen), optional `desktopApp`.
   - Plugin `com.android.kotlin.multiplatform.library` with the `kotlin { android { … } }` DSL. `androidLibrary {}` is
     deprecated since AGP 9.1.0-alpha09.
   - Libraries: JetBrains `navigation3-ui` 1.1.2, `lifecycle-viewmodel-compose` 2.11.0, Koin 4.2.2 (plus its compiler
     plugin 1.2.1) or Metro 1.4.5, Room 3.0.3 or Room 2.8.5 KMP, Ktor 3.6.0, DataStore 1.2.1, Coil 3.6.3.
   - KSP 2.3.10+ **deprecates `ksp(...)` in KMP projects**. Use target-specific configurations.
6. **SwiftUI generator:**
   - Use `@Observable` (iOS 17+), `NavigationStack(path:)`, local Swift packages, XcodeGen 2.46.0 `project.yml`
     (supports `syncedFolder` sources and local `packages`), and Swift Testing.
   - Liquid Glass APIs (`glassEffect`, `GlassEffectContainer`, `.buttonStyle(.glass)`) are **iOS 26+**.
     `UIDesignRequiresCompatibility` is **ignored when building for iOS 27+** **[docs]**.

### 2.3 Cost model, from the 2.0.1 source

What each `drawBackdrop(...)` node does per frame (`DrawBackdropModifier.kt`, `HighlightModifier.kt`,
`ShadowModifier.kt`, `InnerShadowModifier.kt`):

1. **Lays out its content into an offscreen, clipped layer.** `placeWithLayer { clip = true; shape = …;
   compositingStrategy = CompositingStrategy.Offscreen }`. Every glass element has its own offscreen buffer.
2. **Records the sampled backdrop into its own `GraphicsLayer`.** The node's `graphicsLayer.renderEffect` is the effect
   chain (ColorFilter, then Blur, then RuntimeShader). The GPU runs that RenderEffect over the glass area every frame
   the source content changes. Cost scales with **glass area × number of glass nodes × blur radius**.
3. **`highlight` (on by default)** adds a second `GraphicsLayer`. It is re-recorded on every draw
   (`shouldAutoInvalidate = false`) with a stroked outline, a `BlurMaskFilter`, and on API 33+ an AGSL shader.
4. **`shadow` (on by default)** adds a third layer, using **`CompositingStrategy.Offscreen`** and a `BlurMaskFilter`. It
   is re-recorded every draw.
5. **`innerShadow`** adds an offscreen layer with a `BlurEffect`. That `BlurEffect` is recreated whenever its radius
   changes, so animating the radius allocates a new one every frame.
6. **`effects {}` is snapshot-observed.**
   - `onAttach`/`update` call `observeReads { updateEffects() }`, and `onObservedReadsChanged()` calls it again.
   - Any state read inside `effects` (for example `drag.pressProgress`) **rebuilds the whole RenderEffect chain and sets
     the AGSL uniforms on every change**, which means every animation frame.
   - Size and density changes also rebuild it.
7. **`DrawBackdropElement.equals` compares the lambdas** (`shape`, `effects`, `highlight`, `shadow`, …).
   - If a non-composable `Modifier` extension builds new lambdas on each call, every recomposition calls `update()`,
     which runs `invalidateDrawCache()` and rebuilds the effects again.
   - Inside a `@Composable` function the Compose compiler (strong skipping) memoises lambdas, so this is avoided.
     Top-level `val` lambdas avoid it too.
8. **`layerBackdrop(source)`** draws its content and then **records `drawContent()` a second time into the backdrop's
   `GraphicsLayer`** on every draw.
   - Child RenderNodes are only referenced, so recording is cheap.
   - Any animation inside the recorded subtree (aura gradients, shimmer, Lottie, progress spinners) re-triggers blur and
     refraction for **every** glass node sampling it, every frame.
   - Haze's guide gives the same advice: "keep unrelated animation outside captured source subtrees".
9. `ShapeProvider` caches the `Outline` until the shape object changes (by `equals`), the size, the layout direction or
   the density. `Capsule()` and `RoundedRectangle()` implement value equality, so `shape = { Capsule() }` is cache-safe.
10. `RoundedCornerStyle.Continuous` (the default, iOS-like squircle) produces `Outline.Generic` (a `Path`). `Circular`
    produces `Outline.Rounded`. Clipping a layer to a generic path is costlier than a round rect, and the platform clips
    view outlines to arbitrary paths only from API 33 **(uncertain: recalled from platform docs, not re-verified)**. For
    many small glass controls, prefer `Circular` or Compose shapes. Keep `Continuous` for large chrome.

### 2.4 Known issues and gotchas

- **API < 31:** `updateEffects()` returns early, so `drawBackdrop` **still draws the sampled backdrop, sharp and
  unblurred**. The glass looks invisible and text over it becomes unreadable. You must branch on
  `isRenderEffectSupported()` and draw a frosted fallback. PeriFlow does this in `Glass.kt:149`. The template's minSdk is
  26 (`build-logic/.../AppConfig.kt:13`), so API 26–30 devices need the fallback.
- **API 31–32:** blur and vibrancy work. `lens()` is a no-op. The `Highlight.Default` shader falls back to a plain
  stroke.
- **`lens()` throws `UnsupportedOperationException`** ("Only RoundedRectangularShape or CornerBasedShape is supported in
  lens effects") when the shape is neither type. This only happens on API 33+, where the shader path runs, so testing on
  API 31–32 hides the crash.
- **Recording cycle crash:** `Fatal signal 11 (SIGSEGV) … (RenderThread)` when a node both samples a backdrop and is
  inside that backdrop's recorded subtree. A typical case is putting `layerBackdrop()` after `drawBackdrop()` on the
  same node. Fix with `exportedBackdrop` [docs: Glass Bottom Sheet tutorial and FAQ]. Rule: **chrome that samples the
  scene must not live inside the scene's `layerBackdrop` subtree.** PeriFlow's `GlassStage` (`Glass.kt:76-96`) gets
  this right.
- GitHub issues, all **open** as of today:
  - #100: crash when several far-apart elements share one backdrop (2026-05-13).
  - #91: wrong sampling position inside `Popup` or other separate windows (2026-03-07). Use the fallback in
    dialogs and popups.
  - #116: flicker on physical iOS devices only (2026-07-29). Matters for a CMP generator.
  - #115: CMP 1.12.0-beta02 support.
- `LayerBackdrop.drawBackdrop` computes the offset with `localPositionOf` and falls back to `positionInWindow` inside a
  `try/catch`. The source carries the comment `// TODO: outer transformations lead to wrong position calculation`.
  Avoid scaling or rotating ancestors of glass chrome.

### 2.5 Performance rules for the generator's optional `liquidglass` feature

Distilled from §2.3 and §2.4, Kyant's tutorials, Apple's Liquid Glass guidance ("Limit the use of Liquid Glass effects
onscreen at the same time"), and Haze's performance guide:

1. **One recorded scene per stage.**
   - `rememberLayerBackdrop { drawRect(background); drawContent() }` on the screen-content box.
   - Floating chrome (tab bar, compact top bar, FAB) sits **outside** that box.
   - Paint the background into the backdrop (Kyant's Glass Bottom Bar tutorial, step 2) so blur edges never sample
     transparent pixels.
2. **Real (sampling) glass only on floating chrome.**
   - Content-level "glass" (cards, chips, buttons over a static gradient) should be drawn: translucent fill, rim
     gradient, sheen.
   - PeriFlow measured that a live backdrop under every card "cost a blur pass each per frame (measured: two in three
     frames missed on a mid-range phone)" (`Glass.kt:139-145`).
3. **Static `effects`.**
   - Declare the effect lambda as a top-level `val`, or build it in a `@Composable` function and read no state in it.
   - Never animate blur radius or lens values per frame.
   - Animate press feedback through `layerBlock` (`scaleX`/`scaleY`/`translationX`, RenderNode properties only) and
     surface alpha in `onDrawSurface` (draw phase).
4. **Opt out of what you don't see.** `shadow = null` unless the element floats. `highlight = null` on small or
   secondary glass. No `innerShadow` at rest.
5. **Small radii.** 8–12 dp blur on chrome. Combined with `vibrancy()` and a 40–60% tint, the result reads as glass
   without a large kernel.
6. **Keep animation out of the recorded subtree** where possible (see §2.3, point 8). Ambient "aura" animation in
   particular should sit **behind** the recorded scene (or be static) rather than inside it.
7. **Fallback ladder:** API ≥ 33 full glass. 31–32 blur and vibrancy without lens. < 31, or no stage (dialog, popup
   window), a frosted tint with the same rim and shadow. Also add a "reduce transparency" switch (Haze 2 has
   `LocalGlassAccessibilitySettings` for this; Apple added a system-wide Liquid Glass opacity slider in iOS 27 per
   third-party coverage **(uncertain)**).
8. Use Compose UI 1.12's **`Modifier.dropShadow(shape, Shadow)`** and **`Modifier.innerShadow(shape, Shadow)`**. They
   need no graphicsLayer, and `ShadowContext` caches the shadow painters **[source ui 1.12.1 `draw/Shadow.kt`,
   `graphics/shadow/ShadowContext.kt`]**. Use them for content-level glass shadows instead of hand-rolled
   `setShadowLayer` code.

### 2.7 Haze 2.0.1 as the alternative

- Modules: `haze` (core: state, source capture, effect orchestration), `haze-blur` (blur extracted in 2.0),
  `haze-blur-materials`, `haze-glass`, `haze-utils`, plus `haze-blur-material3` and `haze-glass-material3`.
- Platforms: Android, JVM desktop, iOS, macOS, js, wasm. `iosX64` and `macosX64` were dropped in 2.0. Minimums:
  Kotlin 2.4.20, CMP 1.12.1, Compose 1.12.1 [CHANGELOG].
- API:
  - `rememberHazeState()`, `Modifier.hazeSource(state)`.
  - `Modifier.hazeBlur(input = HazeInput.Backdrop(state) | Sources(state) | Content, style = HazeMaterials.thin(),
    performanceMode = HazePerformanceMode.Default, expandLayerBounds = true)`.
  - `Modifier.hazeGlass(input, style = GlassStyle…)` is annotated **`@ExperimentalHazeApi`** [source 2.0.1 `HazeGlass.kt`].
- Android blur ladder [docs `blur/platforms.md`]:
  - **API 33+** is optimal (RenderEffect).
  - **API 31–32** works. Progressive blur draws several passes.
  - **API ≤ 30** is disabled by default. The fallback is a **scrim**. Optional RenderScript blur is "quite slow" and
    "a frame (or more) behind".
- Glass ladder [docs `effects/glass.md`]:
  - API 33+ has full refraction, depth blur and chromatic aberration.
  - API 31–32 loses refraction and dispersion.
  - Below 31 is simplified, keeping tint, rim, ambient and specular.
  - Built-in styles `GlassStyle.regular` and `.clear`; `regular` was calibrated against iOS 27 light.
  - `LocalGlassAccessibilitySettings` (reduceTransparency, increaseContrast, showBorders).
  - Experimental native Android 17 QPR2 backdrop via `HazeFeatureFlags.isPlatformBackdropEnabled`.
- Benchmarks [docs `benchmark-results.md`], Pixel 8a, Android 17, 60 Hz. Values are CPU P90 / P90 frame overrun, where
  negative means spare time:
  - blur about 4.6 / −6.9 ms;
  - glass 3.9–4.5 / −9.8 to −10.1 ms.
  - The authors warn that run order alone moved per-pass P90s by more than 2 ms.

**When to pick which**

| Need | Pick |
|---|---|
| Apple-like liquid glass with lens refraction, highlights and interactive bars (what the user built in PeriFlow) | **Kyant backdrop**. Small, low-level, proven in PeriFlow. You write the fallback yourself |
| Frosted blur for top or bottom bars, progressive blur under headers, robust fallbacks, accessibility toggles, measured perf modes | **Haze `haze-blur`** (stable) |
| Glass with an official fallback ladder and a11y, accepting an experimental API | Haze `haze-glass` (`@ExperimentalHazeApi`) |

Ship **one** of them per generated app, never both. Both are KMP, so the same choice carries to the CMP generator. On
iOS, prefer native SwiftUI glass in the SwiftUI generator.

## 3. Compose animation performance and Navigation 3 transitions

### 3.1 Phase-deferred state reads [docs: performance/bestpractices]

- Read fast-changing state in the **layout** or **draw** phase through lambda modifiers: `offset { }`,
  `graphicsLayer { }`, `drawBehind { }`, `layout { }`. Composition is then skipped entirely. Pass `() -> T` providers
  down instead of values.
- `derivedStateOf` for thresholds (for example `firstVisibleItemIndex > 0`). Stable `key`s in lazy lists. Never write
  state that was already read in the same composition.

### 3.2 Modifier.Node over `composed` [docs: custom-modifiers]

- Docs: "`composed {}` is no longer recommended due to performance concerns. `Modifier.Node` was designed from the ground
  up to be far more performant". Composable modifier factories are **never skipped**.
- `ModifierNodeElement` needs correct `equals`/`hashCode` (use a data class), or the node is updated every recomposition.
- `shouldAutoInvalidate = false` plus `invalidateDraw()` and `invalidateMeasurement()` give fine-grained invalidation.
- `ObserverModifierNode.observeReads {}` observes state outside the draw and layout scopes.
- The template currently has **zero** `composed {` call sites (grep). PeriFlow's `Glass.kt:137` has one.

### 3.3 What the built-in enter/exit transitions cost **[source animation 1.12.1 `EnterExitTransition.kt`]**

- **Slides** are applied in the placement block: `placeable.placeWithLayer(offset.x + …, offset.y + …, 0f, layerBlock)`.
  The slide value is read inside the placement lambda, so each frame only **re-places**. No remeasure, no recomposition.
  Cheap.
- **Fade and scale** run through the `graphicsLayer` block, which only changes layer properties.
- **But alpha below 1 is not free.** `CompositingStrategy.Auto` doc **[source ui-graphics 1.12.1]**: "whenever an alpha
  value less than 1.0f is provided … a compositing layer is created automatically to first render the contents fully
  opaque, then draw this offscreen buffer to the destination". A `fadeIn`/`fadeOut` on a whole screen therefore costs a
  **full-screen offscreen buffer for the entire transition**, and one per screen if both fade.
  `CompositingStrategy.ModulateAlpha` avoids the buffer but is only correct when the content has no overlap, which a
  screen always has.
- During an `AnimatedContent` transition both screens are composed, laid out and drawn. In practice the most expensive
  frame is the **first frame of the incoming screen** (its first composition), not the animation itself. Keep screen
  first frames light: lazy lists, deferred loading, baseline profiles. The template already has the baselineprofile
  plugin.
- `SharedTransitionLayout` / `SharedTransitionScope` is a `LookaheadScope`, so every layout pass inside it also runs a
  lookahead pass. Wrap `NavDisplay` in it (and pass `sharedTransitionScope`) only when shared elements are actually
  used. Docs: prefer `ResizeMode.scaleToBounds()`, `skipToLookaheadSize()`, consistent modifier order, and remove
  invisible shared elements after the transition.

### 3.4 Navigation 3 transition API (1.2.0) **[source navigation3-ui 1.2.0]**

```kotlin
@Composable fun <T : Any> NavDisplay(
    entries: List<NavEntry<T>>,                       // or backStack: List<T> + entryDecorators + entryProvider
    modifier: Modifier = Modifier,
    contentAlignment: Alignment = Alignment.TopStart,
    sceneStrategies: List<SceneStrategy<T>> = listOf(SinglePaneSceneStrategy()),
    sceneDecoratorStrategies: List<SceneDecoratorStrategy<T>> = emptyList(),   // new in 1.1
    sharedTransitionScope: SharedTransitionScope? = null,
    sizeTransform: SizeTransform? = null,
    transitionSpec: AnimatedContentTransitionScope<Scene<T>>.() -> ContentTransform = defaultTransitionSpec(),
    popTransitionSpec: AnimatedContentTransitionScope<Scene<T>>.() -> ContentTransform = defaultPopTransitionSpec(),
    predictivePopTransitionSpec: AnimatedContentTransitionScope<Scene<T>>.(@NavigationEvent.SwipeEdge Int) -> ContentTransform =
        defaultPredictivePopTransitionSpec(),
    onBack: () -> Unit,
)
```

- **Defaults on Android:**
  - push and pop are a **700 ms** tween fade (`DEFAULT_TRANSITION_DURATION_MILLISECOND = 700`);
  - predictive pop is `fadeIn(spring(1f, 1600f))` with `scaleOut(0.7f)`.
  - Always override all three.
- **Priority:** transitioning `NavEntry.metadata`, then the current `Scene.metadata`, then the `NavDisplay` defaults.
  `Scene.metadata` defaults to `entries.lastOrNull()?.metadata`, so a custom `Scene` (the template's `ListDetailScene`)
  forwards entry metadata unless it overrides it.
- **Per-entry metadata, two equivalent forms:**
  - map helpers `NavDisplay.transitionSpec { }`, `NavDisplay.popTransitionSpec { }` and
    `NavDisplay.predictivePopTransitionSpec { }`, which return `Map<String, Any>`. These are **not deprecated** in
    1.2.0. The template uses them in `AppNavHost.kt:185-187`.
  - the type-safe DSL `metadata { put(NavDisplay.TransitionKey) { … }; put(NavDisplay.PopTransitionKey) { … };
    put(NavDisplay.PredictivePopTransitionKey) { edge -> … } }`.
- **z-order:** push puts the target at `initialZIndex + 1`. Pop and predictive back put it at `initialZIndex − 1`, so
  the **outgoing screen stays on top** during pop, which matches iOS.
- **`isPop` logic:**
  - a different **first** element counts as "entire stack replaced" and is **not** a pop, so it animates as a forward
    push;
  - a larger stack is a push;
  - otherwise it compares the stacks to find the point where they diverge.
  - Consequence: switching tabs by swapping the root of a single back stack animates as a push. The template avoids this
    by giving each tab its own `NavDisplay` inside `AnimatedContent` (`AppNavHost.kt:99-106`).
- **Lifecycle:** each scene is capped at `STARTED` until `transition.currentState == targetState` (settled), and only
  then goes to `RESUMED`. Long-settling springs delay `RESUMED`.
- **Predictive back:**
  - `LaunchedEffect(previousScene, progress) { transitionState.seekTo(progress, previousScene) }`. On release it
    animates the remaining fraction with `tween(remainingDuration)`, computed from `transition.totalDurationNanos`.
  - 1.2.0 adds "predictive back mid-flight during forward animations", `NavigationBackHandler`, and
    `rememberNavigationEventState`.
- `LocalNavAnimatedContentScope` exposes the entry's `AnimatedContentScope`, giving `transition`, `animateEnterExit`
  and `sharedElement` scope, for per-entry effects such as the scrim below.
- **Other 1.2.0 changes worth knowing when bumping from 1.1.7:**
  - `NavEntry.contentKey` now defaults to `key.toString()` combined with `key::class.toString()`. Saved state keyed by
    `contentKey` changes once on upgrade.
  - New KMP deep-link API (`DeepLinkRequest`, `DeepLinkMatcher`, `UriDeepLinkMatcher`, `BackStackMatcher`).
  - New `ResultEventBus` / `ResultEffect` for passing results between entries.

### 3.5 iOS-like push and pop, cheaply

Facts about iOS:

- `UINavigationController` slides the pushed view in and the previous view out, with a back swipe gesture. Apple
  documents the behaviour, not the numbers.
- The commonly cited look (outgoing view moves about 30% with a dim, incoming view has an edge shadow) is
  **approximate**. Tune it by eye.
- Spring conversion is documented precisely in Apple's `Spring` type: `Spring(duration: 0.5, bounce: 0.3)` gives
  `mass 1.0, stiffness 157.9, damping 17.6` [docs]. So **stiffness = (2π / duration)²** and
  **dampingRatio = 1 − bounce**, which maps directly onto Compose's `spring(dampingRatio, stiffness)` (mass 1).

| iOS spring | Compose equivalent | Settle 1080 px → 1 px (simulated) |
|---|---|---|
| `.smooth` (0.5 s, bounce 0) | `spring(1f, 157.9f)` | ≈ 0.76 s |
| `.snappy` (0.5 s, bounce 0.15) | `spring(0.85f, 157.9f)` | ≈ 0.73 s |
| `.bouncy` (0.5 s, bounce 0.3) | `spring(0.7f, 157.9f)` | ≈ 0.85 s |
| duration 0.4, bounce 0 | `spring(1f, 246.7f)` | ≈ 0.62 s |
| duration 0.35, bounce 0 | `spring(1f, 322.3f)` | ≈ 0.55 s |
| Compose `StiffnessMediumLow` (400), critically damped | ≈ iOS duration 0.314 | ≈ 0.50 s |

Recommended recipe:

- **Push:** incoming slides in from the trailing edge by 100%. Outgoing slides toward leading by 30%. **Both use the
  same spring** (for example `spring(1f, 320f)`).
- **Pop:** the mirror image.
- **No alpha on the screens.** Dim the covered screen with a scrim drawn in the **draw phase** of the *top* screen,
  outside its own bounds:

```kotlin
@Composable
fun Modifier.coverScrim(maxAlpha: Float = 0.12f, color: Color = Color.Black): Modifier {
    val transition = LocalNavAnimatedContentScope.current.transition
    // 1 when this entry is fully on screen, 0 when it is off screen (PreEnter or PostExit).
    val covered = transition.animateFloat(transitionSpec = { spring(1f, 320f) }, label = "cover") {
        if (it == EnterExitState.Visible) 1f else 0f
    }
    val rtl = LocalLayoutDirection.current == LayoutDirection.Rtl
    return drawBehind {
        if (!transition.isRunning) return@drawBehind
        // The strip beside this screen on its leading side is exactly the screen it covers. For the lower
        // screen that strip is off screen, so only the top screen's scrim is ever visible.
        drawRect(color, topLeft = Offset(if (rtl) size.width else -size.width, 0f), size = size,
                 alpha = maxAlpha * covered.value)
    }
}
```

This is one `drawRect` per frame, read in the draw phase, with no offscreen buffer. It works for predictive back
because the transition is seeked. Things to verify on a device:

- No ancestor clips the entry: `NavDisplay`'s `sizeTransform = null` and the enter/exit layer `clip = false` by default.
- Every entry draws an **opaque background**. Without one the two screens show through each other. The template adds a
  background only when `inset > 0` (`AppNavHost.kt:155-163`).

**Predictive back:** use the same pop spec for `predictivePopTransitionSpec`, whatever the edge, because iOS content
always moves toward trailing on pop. The template targets SDK 37. From targetSdk 36,
`android:enableOnBackInvokedCallback` defaults to `true`, `onBackPressed` is not called, and intercepting `KEYCODE_BACK`
is unsupported [docs].

**Tab switch:**

- iOS `UITabBarController` and SwiftUI `TabView` switch **instantly**.
- The cheapest and most iOS-like choice is `EnterTransition.None togetherWith ExitTransition.None`, or skipping
  `AnimatedContent` and composing only the selected tab with a `SaveableStateHolder`.
- If an animation is wanted, use a ≤ 150 ms crossfade on the incoming tab only (one offscreen buffer).
- The template's `tabSwitch` (`NavTransitions.kt:105-113`) fades and scales the incoming tab after a 90 ms delay and
  fades the outgoing one. That means two full-screen alpha layers, and a delayed start that reads as lag.

### 3.6 Removing ripple and iOS-like press states

- `foundation` defines `val LocalIndication = compositionLocalOf<Indication> { DefaultDebugIndication }` **[source]**.
  Ripple exists only because Material provides it. `clickable`, `selectable`, `toggleable` and `combinedClickable`
  without an explicit `indication` read `LocalIndication.current`.
- So **app-wide no-ripple means providing your own `IndicationNodeFactory` at the theme root**, which the template does
  in `AppTheme.kt:66-87` with `AppIndication.kt:18`.
- `IndicationNodeFactory`:
  - `create(interactionSource): DelegatableNode`, with `equals`/`hashCode` overridden;
  - `Indication.rememberUpdatedInstance` is `DeprecationLevel.ERROR`.
  - Google's documented scale-on-press sample is a `DrawModifierNode` that runs `Animatable.animateTo(0.9f, spring())`
    on `PressInteraction.Press` and calls `scale(...) { drawContent() }`.
- `clickable(interactionSource = null, indication = …)` creates the interaction source lazily. Cheaper for lists.
- iOS-like feedback:
  - text and icon buttons dim while pressed;
  - cards scale to about 0.97;
  - glass controls scale **up** (Kyant's tabs use 78/56 while pressed);
  - all on springs, with no ripple.
  - Exact iOS alphas and scales are undocumented. **(uncertain: tune by eye)**
- Scroll edge: `LocalOverscrollFactory` (foundation, public) controls the stretch overscroll. Provide `null` to disable
  it, or a custom `OverscrollFactory`/`OverscrollEffect` for an iOS-style rubber band.

### 3.7 Related upcoming deprecations (Compose foundation 1.13.0-alpha03)

- `BasicTextField(value, onValueChange)` overloads are deprecated in favour of `TextFieldState`.
- `VisualTransformation` is deprecated in favour of `OutputTransformation`.
- `LazyListPrefetchStrategy` is deprecated in favour of `LazyLayoutCacheWindow`.
- Template call sites:
  - `core/designsystem/.../input/AppTextField.kt:127` (`BasicTextField(value = …, onValueChange = …)`)
  - `AppOtpField.kt:98` (with `TextFieldValue`)
  - `AppFieldVariants.kt:63` (`PasswordVisualTransformation`). `BasicSecureTextField` is the replacement for password
    fields.
- Not urgent while the template is on 1.12, but the overhaul should not create more of these call sites.

## 4. Compose Multiplatform architecture in 2026

### 4.1 Official structure

From the KMP wizard and JetBrains' blog post (2026-05):

- **`shared`**: the KMP library with all shared code (logic, data and, optionally, Compose UI). It is the iOS

- Reference projects named by JetBrains: kotlinconf-app, KMP-App-Template, RSS Reader. Kyant's own catalogue uses

### 5.1 Platform facts

- **Observation:** `@Observable` (macro, iOS 17+). Use `@State` to own an observable model, `.environment(model)`,
  `@Environment(Model.self)`, `@Bindable` for bindings, and `@ObservationIgnored`. Views update only for properties
  their `body` reads. `ObservableObject` updates on any `@Published` change [docs].
- **Xcode 27:** `@State` becomes a macro, so a class stored in `@State` is initialised **once** per view lifetime
  (lazily). `ContentBuilder` unifies the builders [docs: SwiftUI updates, June 2026].
- **Navigation:** `NavigationStack(path: $path)` with `.navigationDestination(for: Route.self)` (iOS 16+). Keep `path`
  in an `@Observable` router per tab.
- **Tabs:** `TabView { Tab("…", systemImage: "…") { … } }`, `.tabBarMinimizeBehavior(.onScrollDown)` (iOS 26), the
  search role (`Tab(role: .search)`) (iOS 26), and the `prominent` tab role (iOS 27).

### 5.2 Liquid Glass (iOS 26+) [docs]

```swift
Text("Hello").padding().glassEffect()                                  // Glass.regular in a Capsule by default
Text("Hello").padding().glassEffect(in: .rect(cornerRadius: 16))
Text("Hello").padding().glassEffect(.regular.tint(.orange).interactive())
GlassEffectContainer(spacing: 40) { HStack(spacing: 40) { … .glassEffect().glassEffectID("pencil", in: ns) } }
.glassEffectUnion(id: "group", namespace: ns)
.glassEffectTransition(.matchedGeometry | .materialize)
Button("Go") { }.buttonStyle(.glass)        // and .glassProminent
```

- `Glass` variants: `.regular`, `.clear`, `.identity`. Modifiers: `.tint(_:)`, `.interactive(_:)`.
- Related APIs: `ToolbarSpacer`, `scrollEdgeEffectStyle(_:for:)`, `backgroundExtensionEffect()` ("apply with
  discretion… performance").
- **Performance:** "Use `GlassEffectContainer` when applying Liquid Glass effects on multiple views to achieve the best
  rendering performance". "Creating too many Liquid Glass effect containers and applying too many effects to views
  outside of containers can degrade performance. Limit the use of Liquid Glass effects onscreen at the same time." Apply
  `glassEffect` **after** the other appearance modifiers.
- Standard bars, tab bars, sheets and toolbars adopt Liquid Glass automatically when built with the 26+ SDK.
  `UIDesignRequiresCompatibility` (temporary opt-out) is **ignored when building for iOS 27 or later** [docs].
- For a deployment target below 26, gate with `if #available(iOS 26, *)` and fall back to `.background(.ultraThinMaterial, in: shape)`.

### 5.3 Modular layout and project generation

- Thin app target plus **local Swift packages**: `Packages/Core` (Models, Networking, Persistence, DesignSystem) and
  `Packages/Features` (one library product per feature). Each package's targets declare dependencies explicitly.
- SwiftPM 6.2+ adds `swiftSettings: [.defaultIsolation(MainActor.self)]` (SE-0466, "PackageDescription 6.2") for
  "approachable concurrency". Combine it with `@concurrent` for explicit background work [docs: Swift 6.2].
- Swift 6.4 adds `anyAppleOS` availability, `@diagnose`, async `defer`, and Swift Testing ↔ XCTest interoperability.
- **XcodeGen 2.46.0 `project.yml`** (keys verified against `Docs/ProjectSpec.md`):

```yaml
name: TrailNotes
options:
  bundleIdPrefix: com.example
  deploymentTarget: { iOS: "17.0" }
  createIntermediateGroups: true
packages:
  Core:     { path: Packages/Core }        # local package (directory with Package.swift)
  Features: { path: Packages/Features }
targets:
  TrailNotes:
    type: application
    platform: iOS
    sources:
      - path: App
        type: syncedFolder                # Xcode 16 buildable folder (XcodeGen ≥ 2.44)
    dependencies:
      - package: Core
        product: DesignSystem
      - package: Features
        product: FeedFeature
    info:
      path: App/Info.plist
      properties: { UILaunchScreen: {} }
    settings:
      base: { PRODUCT_BUNDLE_IDENTIFIER: com.example.trailnotes, SWIFT_VERSION: "6.0" }
  TrailNotesTests:
    type: bundle.unit-test
    platform: iOS
    sources: [Tests]
    dependencies: [{ target: TrailNotes }]
```

- XcodeGen also supports `.xcstrings` String Catalogs (2.44), test plans (`testPlans` with `defaultPlan`), `.icon`
  folders for Icon Composer (2.45.1), and remote packages (`url` + `from`/`exactVersion`).
- **Swift Testing** (Swift 6.0, Xcode 16+): `@Test`, `#expect`, `#require`, `@Suite`, parameterised
  `@Test(arguments:)`, traits and tags, in-process parallelism, attachments and exit tests (6.2).
