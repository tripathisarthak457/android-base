## Blocking

1. `generator/genkit/targets/ios/scaffold.py`:192: Scaffolded feature modules are not adaptive. <Name>RootView is a NavigationStack with NavigationLink(value: <Name>Route.detail(item)) at every width (lines 192-237, 312-362), so on an iPad or in a wide window the list fills the screen and each item is pushed full-screen. This breaks ADAPTIVE-PLAN §14.2 (list-detail is a NavigationSplitView with a ContentUnavailableView placeholder) and requirement 23 (canonical list-detail). It also breaks the template's own AGENTS.md:102-103 and the Android scaffolder's parity (NavPane.List/Detail, AD-25). The route carries the whole item, so AppModel.open() setting router.selection for a scaffolded tab does nothing: baseapp://orders/42 opens the tab but never the item. The 'iPad #Preview exists' check passes without proving anything adaptive.
   Fix: Emit the SampleRootView pattern. Use NavigationSplitView with List(selection:) bound to router.selection (id as String), an AppStateView placeholder, and a detail column that loads by id (a <Name>DetailStore with repository.item(id:)), plus a NavigationStack(path: $router.path) inside it. Carry ids in routes, not items. Add a test_target_ios assertion that every scaffolded <Name>RootView uses NavigationSplitView and reads router.selection.
2. `templates/ios/Packages/Features/Sources/SampleFeature/SampleRootView.swift`:19: `@State private var compactColumn = NavigationSplitViewColumn.sidebar` is passed as preferredCompactColumn (line 51), but nothing in the app writes it. On iPhone the binding decides which column is on top when the split view is collapsed. (1) Reselect after viewing an item: the system set it to .detail on tap, and AppModel.reselect → popToRoot clears selection but leaves .detail, so the phone shows the 'Nothing selected' placeholder instead of the list. (2) A deep link sets router.selection but leaves .sidebar, so the item is not opened on iPhone. Router.selection's docs promise 'Nil shows the list on a phone'. AppModelTests only checks router state, so neither case is caught. PLAUSIBLE: no compiler or simulator here; confirm on the CI simulator.
   Fix: Drop the preferredCompactColumn binding so the list selection drives the collapsed split view, or derive it: `.detail` when router.selection != nil, `.sidebar` when nil, kept in step with onChange of router.selection. Add the scenario (reselect after opening an item, and a deep link on an iPhone destination) to the WP13 simulator checks.
3. `templates/ios/AGENTS.md`:143: AGENTS.md has no feature markers, so every generated project gets the full text, including APIs and files the preset did not ship. Verified in out/WP08: ios-lean/AGENTS.md:143 tells agents to use `.appGlass(in:)` inside `AppGlassGroup`, but Foundation/Glass is not shipped without liquidglass, so agent code fails to compile. ios-modules/AGENTS.md:37, 95 and 103 point at SampleListStore.swift, SampleListStore.refresh() and 'SampleRootView is the reference', which do not exist without sample. Lines 28 and 50 describe Database (SwiftData) and the @ModelActor without database. This is the same failure STANDARDS-PLAN §4.5 forbids, and it defeats requirements 15 and 25.
   Fix: Wrap the feature-specific rows and sentences in <opt:liquidglass>, <opt:sample> and <opt:database> markers with neutral <opt-else> wording. A scaffolded module can be the reference when sample is off. Add a test_target_ios check that every backticked type or file named in a generated AGENTS.md exists in that project.
4. `templates/ios/Packages/Features/Sources/SampleFeature/List/SampleListStore.swift`:89: The store's reconnect behaviour has no test. followConnectivity (lines 89-100) reloads after a .failed(.offline) load once connectivity returns, and nothing exercises it. The store takes the concrete NetworkMonitor (line 31), so a test cannot drive connectivity. SampleListStoreTests.makeStore (Tests/SampleFeatureTests/List/SampleListStoreTests.swift:67) therefore starts a live NWPathMonitor, and the store tests depend on the host's real network state. This breaks T-1 (test events to state) and T-6.
   Fix: Inject the stream rather than the monitor, for example `connectivity: @escaping @Sendable () -> AsyncStream<Bool>` with `monitor.updates` passed from SampleRootView. No protocol is needed. Add tests that a failed offline load is reloaded when the stream yields online, that isOnline follows the stream, and that a second .appeared does not subscribe twice.
5. `generator/genkit/targets/ios/target.py`:176: `create_project.py --icon` is silently ignored for iOS. IosTarget.finish never reads context.icon_source, while the Android target derives icons from it (targets/android/target.py:142-143). A user who passes an icon gets the template's placeholder AppIcon.png with no warning.
   Fix: In finish, when context.icon_source is set, either write it as Assets.xcassets/AppIcon.appiconset/AppIcon.png (square, at least 1024 px, no alpha) or return a warning that iOS icons are not derived yet. Add a test either way.
6. `generator/create_project.py`:66: WP01-owned files were changed in substance inside the feature commit 9200d90. create_project.py gained new behaviour: --target now defaults to the spec's platform (lines 66, 173-185), and the iOS 'Next' lines were added (352). tests/test_manifest.py:81 now skips non-Gradle templates, and tests/test_spec.py was also touched. Part D 2 and B.1 allow only mechanical touch-for-compile edits outside owned paths, in a separate 'Update call sites for …' commit, with anything substantive routed through the orchestrator. The handoff lists these touches but does not record them as an approved deviation.
   Fix: Move these edits into their own commit and record the CLI inference under Deviations with the orchestrator's sign-off. WP08's accept.sh depends on it, since it runs --spec without --target. Alternatively, have WP01 land the change and use --target ios in accept.sh until then. Correct the test_manifest.py comment, which claims test_target_ios replaces the orphaned-test check per feature: it checks folder/target parity, not test → main source.

## Non-blocking

- templates/ios/Packages/Core/Sources/Networking/Client/APIClient.swift:29-33,76-77: a cancelled request (URLError.cancelled or CancellationError) becomes .unexpected, which AppError documents as 'a bug'. The stores guard on Task.isCancelled, but DefaultSampleRepository still falls back to the database on a cancelled request, and any caller without the guard shows 'Something Went Wrong'. Give cancellation its own handling.
- templates/ios/Packages/Features/Sources/SampleData/DefaultSampleRepository.swift:55-59: with database on, a failed forceRefresh (an HTTP 500 too, not only offline) returns the saved list as .success. A failed pull to refresh is then silent, and SampleListStore's 'Could not refresh.' toast (SampleListStore.swift:79-83) can never fire. Fall back only when the call was not forced, or return the failure together with the stale list.
- features/database.toml: with database on and sample off (the ios-modules fixture), ModelContainerFactory ships but nothing calls it, because AppServices builds the container only under sample&database and scaffolded modules ignore database. Either scaffold a @ModelActor-backed repository, set requires = ["sample"], or warn.
- Unused imports, against Part D 9: BaseApp/AppServices.swift:1 and :7 import AppCore and OSLog unconditionally but use them only under <opt:sample&database>, so they are unused in lean, standard and modules. SampleRootView.swift:1 imports AppCore and uses nothing from it.
- Raw values in features, against AGENTS.md:110 ('never a raw … size'): OnboardingView.swift:75 (72), SampleDetailView.swift:37 (280/320/412 inline). ToastHost.swift:77 repeats AppLayout.formMaxWidth as a literal 480.
- AppButtonStyle.swift:69-71 duplicates the ScalePressStyle and DimPressStyle logic. Its .plain kind dims on the press/release springs, while .dimPress dims instantly and eases out, so plain buttons get two different feedbacks. `case .plain: .clear` at line 113 is unreachable after the early return at 105-107.
- NetworkMonitor.swift:38-45 and SettingsRepository.swift:33-37 register the continuation and then yield a snapshot outside the lock. A change made in between can arrive before the stale snapshot, so the consumer ends on a stale value. Yield under the lock, or read the snapshot after registering, inside the same critical section.
- Features/Package.swift:14-15 and SampleAPI.swift:13: under NonisolatedNonsendingByDefault, repository code, including the DTO → domain mapping (string trimming per item), runs on the calling store's actor, which is main. Only decode is @concurrent. Make mapping-heavy repository methods @concurrent, or move the mapping into the @concurrent decode step, so the template shows the pattern AGENTS.md:48-49 prescribes.
- A8.2 and AGENTS.md:62-77 show stores navigating through the Router, but no store in the template or the scaffolder holds a Router; navigation happens in views through selection bindings and NavigationLink. Either demonstrate store → router.push once, or change the AGENTS.md example.
- Nothing in the template reads \.appWindowWidth, so measuresWindowWidth() has no consumer and no screen demonstrates branching on the width class (for example a grid column count).
- target.py:120-122 refuses only Swift keywords as tab cases. Module names such as id, title, root, all_cases, raw_value or system_image become AppTab cases that collide with the enum's own members or with CaseIterable/RawRepresentable members.
- AppTextField.swift:19 keeps @FocusState private, so a form cannot move focus to the next field. The error text is also not associated with the field for VoiceOver; add it as an accessibilityHint or value.
- ScaffoldedFeature tests and SampleListStoreTests/SampleDetailStoreTests poll wall-clock time with Task.sleep in settle(), and the helper is repeated three times. Where a task handle is available, await it, as refresh() already allows.
- PreviewSampleRepository.swift and SampleListStore.preview() are compiled into the release SampleFeature target, and preview() starts a real NWPathMonitor on every call.
- swift.py:79-90 repeats _color's hex parsing (115-120). emit() reads load() for the motion descriptions (line 50) instead of the resolved tokens it was given.
- Lean AppWindow.swift:9-10 still says 'the walkthrough on the first run' when onboarding is off; put that clause behind <opt:onboarding>.
- HTTPFailure.retryAfter and TaskBag.isRunning have no caller in the template; they are speculative API (Part D 6), though both are tested.
- The scaffolded <Name>Item is Decodable and lives in API/ (scaffold.py:116-128), so the wire format becomes the module's public model; the comment acknowledges this (A-4/A-6).
- ViolationsTest proves only ObservableObject and print( from the forbidden-pattern table; try!, @Published, AnyView, UIScreen.main and DispatchQueue.main.async have no failing fixture.
- AppModelTests.swift:7 builds a full AppServices per test: a live NWPathMonitor and, under database, an on-disk SwiftData store at the default location, shared with the host app.
