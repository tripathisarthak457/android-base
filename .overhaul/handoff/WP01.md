## Public APIs added, changed, removed (signatures)

### Target protocol (`genkit/core/target.py`) as implemented

```python
class Target(Protocol):
    key: str; template_dir: Path; manifest: TemplateManifest
    def vocabulary(self) -> Vocabulary                       # design styles (+ required features), motion styles, taken module names
    def validate(self, spec: Spec) -> list[str]               # raises SpecError(field); returns warnings
    def identity(self, spec: Spec) -> dict[str, str]          # values for template.toml's `to` format strings
    def regions(self, spec: Spec) -> dict[str, list[str] | None]   # None keeps a region's default lines; [] removes
    def overlays(self, spec: Spec) -> dict[str, Path]         # template-relative path → replacement file (variants)
    def transform(self, project: Path, spec: Spec) -> list[str]    # structural steps, final text (scaffold; modular later)
    def finish(self, project: Path, spec: Spec, context: BuildContext) -> list[str]  # look, translations, keystores, icons
    def outline(self, spec: Spec) -> dict[str, list[str]]     # {"modules": [...], "tabs": [...]} for --dry-run
    def catalogue(self) -> dict[str, Any]                     # {"defaults", "fields", "architectures", "reserved_module_names", "rules"}
    def environment(self) -> dict[str, Any]                   # live catalogue only, e.g. {"keytool": true}
```

A new target is a package `genkit/targets/<key>/` exposing `TARGET`, plus `templates/<key>/` with
the four manifest files; `REGISTRY` picks it up when both exist. `BuildContext(icon_source,
summary)`; `RenderError` for build failures that are not the user's input.

### Pipeline (`genkit/core/pipeline.py`)

```python
read_spec(raw, target, overrides: list[tuple[str, Any]] | None = None) -> tuple[Parsed, list[str]]
build(spec, target, destination, *, zip_output=True, icon_source=None, git_init=False, commit=None,
      replace=False) -> Generated
plan(parsed, target, warnings) -> {"enabled","disabled","removed_paths","modules","tabs","notes","warnings"}
Parsed(spec, notes, ignored_fields, requested)        Generated(destination, project_name, warnings, summary)
```

Without `replace`, `build` deletes nothing: a directory destination must not exist, and an existing
zip file is overwritten. The finished zip or directory is first written into a temporary directory
beside the destination (`.<name>.*`, removed on any failure) and renamed over it; with `replace=True`
the old destination (file, directory or symlink, never followed) is deleted only at that point, so a
failed build keeps the previous project. Order: render template (markers → rename →
regions, paths renamed, hollow `.kt` dropped, empty dirs pruned) → `transform` → `finish` → record →
git → zip/move.

### Schema-1 upgrade and spec rules

- No `schema` → schema 1: unknown top-level fields are dropped into `ignored_fields`; the ten
  Android fields move under `android`; `platform = "android"`, `architecture = "compact"`; one note.
- Schema 2: unknown top-level or block fields are a `SpecError`; flat Android fields are accepted
  as shorthand and moved, with a note; `platform` defaults to the target; `null` means absent.
- `generator` (the record's stamp) is ignored on read, so a project's `generator-spec.json` is a

### `--set` rules

`--set KEY=VALUE`, repeatable, applied after the upgrade and before validation. The value is parsed
as JSON when it parses (`28`, `true`, `["network"]`, `{"dev": "…"}`) and taken as a string
otherwise (`com.example.wp05.everything`). Dotted keys reach into blocks (`android.min_sdk`); a
flat Android key (`min_sdk`) means `android.min_sdk`. An unknown key fails validation like any
unknown field. Device builds: `--set package_name=com.example.<wp>.<name>`.

## Template manifest (TOML schema)

`template.toml`: `[target] key, title, status (available|beta|coming_soon|hidden), status_note
(required for beta), summary`; `[identity] tokens = [{from, to, boundary}]` (`to` formats
`{package}`, `{package_path}`, `{pascal}`, `{snake}`, `{lower}`; boundary dotted|path|prefix|snake);
`[regions] required = [...]`; `[files] template_only, binary_suffixes, executable (globs on the
output path), syntax (optional: name or suffix → "//", "#", "<!-- -->", "markdown", "none")`;
`[groups] order = [...]`. Unknown tables or keys fail at load.

`features/<key>.toml` (one full example, `templates/android/features/firebase.toml`):

```toml
key = "firebase"                       # must equal the file name
title = "Firebase"
headline = "Analytics, Crashlytics and Remote Config"   # must differ from the title
description = """
Analytics, Crashlytics and Remote Config in one switch: …"""   # whitespace-normalised
group = "Observability"                # one of template.toml [groups] order
default = false
requires = ["analytics", "flags"]      # closed transitively; cycles fail at load
implied_only = true                    # hidden from wizard and website; only firebase today
owns = [                               # removed when off; {pkg_path} = com/base/app; must exist
  "app/google-services.json",
  "core/analytics/src/main/kotlin/{pkg_path}/core/analytics/FirebaseAnalyticsTracker.kt",
]
legacy = ["analytics-firebase", "crashlytics", "flags-remote"]
# optional: licence = { name = "…", spdx = "…", url = "…" }, platforms = ["android", …]
```

`legacy` entries: `"key"` (that key means this feature in any spec; may not be a current key) or
`{ key = "firebase", schema = 1 }` (only when upgrading a spec of that schema; may be a current key).
Upgrading follows chains (`analytics-firebase` → `firebase` → whatever `{key="firebase",schema=1}`
lists), notes "'x' is now 'y'." or "'x' is now part of 'y'." (several old keys folded into one).

`presets.toml`: top-level `default = "standard"`; tables `[lean]`, `[standard]` (features listed),
`[everything]` with `all = true` (every non-implied feature, so new features join it).
`removed.toml`: `key = "note"`; a key cannot be both removed and current.

### Adding, removing or renaming a feature (other packages)

1. Code behind markers in the template; files it owns listed in `owns`.
2. `templates/android/features/<key>.toml` (fields above). Old keys that now mean it go in its
   `legacy`; a v1 key that splits into several features is listed as `{key, schema = 1}` in each.
3. Removing: delete the TOML and its code, append `key = "'key' was removed; see …"` to `removed.toml`.
4. **Re-adding a removed key** (WP02 for `ci`, and `staticanalysis` as `formatting`'s legacy key):
   delete its line from `removed.toml` first, or the manifest refuses to load (a current feature, or a
   legacy key without a schema, cannot also be removed). A legacy key limited to an older schema,
   `{ key = "staticanalysis", schema = 1 }`, may keep its removal note, which later schemas then get. Today's
   `removed.toml` holds `fastlane`, `architecturetests`, `screenshottests`, `staticanalysis`, `ci`.
5. New strings: add to `generator/translations/android/<lang>/<module-slug>.json` for every language.
6. Run `python3 -m genkit.core.catalogue --write` and commit `web/frontend/lib/catalogue.json`.
7. `python3 -m tests.consistency --quick` must stay clean (see known issues below).

## Marker engine v2 (as built)

A1.5 grammar exactly, with these details: comment syntax by suffix/name (`.kt .kts .java .swift
.gradle .aidl` → `//`; `.toml .properties .yml .yaml .pro .sh .cfg .gitignore .gitattributes`,
`Podfile`-style names → `#`; `.xml .html .plist .storyboard .xib` → `<!-- -->`; `.md` →
`<!-- -->` without collapse; `.json .xcstrings` → markers forbidden). Inline form: `// <opt:x>code`
(rest emitted verbatim, so its indentation is the code's own), XML `<!-- <opt:x> -->code`. Else
lines `//~ code`, `#~ code`, `<!--~ code -->`; `//~` alone is a blank line. Generated: a point is
a marker with no matching end before the next marker; a region's default lines must hold no other
marker. Regions: None keeps the defaults (still renamed: they are template text), [] removes them;
generated lines are never renamed. Errors (all `TemplateError` with `file:line`): unbalanced or
mismatched block, unknown feature key, a marker sharing a line with code (including inside an
inline marker's code), opt-else not directly after its block, a plain line inside opt-else,
any marker inside opt-else, an emitted `generated` name the target does not supply, a stray end,
markers in JSON. `check_regions`: a target may supply only names in `[regions] required`, and every
required name must be in the full template. Collapse: only at seams (where lines were removed,
including marker lines and empty generated points): a blank run there is cut to one line, dropped
after `{` or before `}`; Markdown is never collapsed. Line endings pass through (CRLF stays CRLF).

## Deviations from MASTER-PLAN, with evidence

1. **Soft keywords are not refused** (A1.3 says "Kotlin hard and soft keywords"). Soft and
   modifier keywords (`value`, `data`, `get`, `field`, `by`, …) are identifiers wherever a package
   segment or module name appears in generated code; refusing them repeats the audit's 4.1 bug
   class (`com.global.bank` refused). Refused: Kotlin hard keywords, Java reserved words, `true`,
   `false`, `null`, `_`. `rules.reserved_words` exports exactly these.
2. **More regions than A1.2 lists.** `app-config` alone cannot hold the flavour URLs or the
   version without moving logic or prose into Python, and the allowed edits were "markers around
   existing default values only". Per-line regions keep every comment in the template:
   `app-version`, eight `api-url-*`/`socket-url-*` (None keeps a flavour's placeholder, which a
   one-region-per-flavour design could not do without duplicating the defaults), `deeplink-strings`
   (old code rewrote the deep-link strings by regex), and eight `readme-*`.
3. **Catalog label and launcher colour stay on a strict legacy applier** (`look.apply_catalog_identity`):
   `catalog/**` is WP03's and was not in WP01's allowed edits. WP03 can add `catalog-name` /
   `catalog-launcher-background` regions and delete the applier.
4. **Markdown is never collapsed**: required for "README output must equal today's" (the old
   README had double blank lines that any seam rule would cut). Markdown renders the same either way.
5. **Catalogue `languages` is per target**, not top-level (each target has its own translation
   set); `environment` (keytool) exists only in `--json`, never in the checked-in copy, because it
   differs per machine. `rules.template_module_names` is a per-target object
   (`{"android": [...]}`), not the flat list A1.9 shows, because each target's template ships
   different modules. Each target's own rules still merge into the one flat `rules` table A1.9
   shows; a target giving an existing rule a different value raises (`_rules`), so a second
   target has to name its rules apart.
6. **`identity()` returns the values** for the `to` format strings declared in `template.toml`
   instead of (token, replacement, boundary) tuples: the tokens and boundaries live in the manifest.
7. **Protocol additions**: `vocabulary()`, `overlays()` (variants until WP06 retires them),
   `outline()` (dry run), `catalogue()`, `environment()`.
8. **Descriptor boundary**: A1.6's `(?<=[^\w]L)|(?<=^L)` misses real baseline-profile lines,
   which carry flags (`HSPLcom/base/app/…`). The path boundary also accepts up to three H/S/P flags
   before `L` (`xLcom/base/app` still does not rename). Matching is a literal alternation with the
   boundary checked per match, which is what made generation ~4× faster than nested lookbehinds.
9. **Translation losslessness** is proven by a one-off check and the golden comparison, not a
   permanent unit test: a test pinned to frozen copies of the old files would fail every time a
   package rewords a translation. The permanent tests are completeness, staleness and placeholders.
10. **Groups** follow A1.2's seven names; today's six were mapped: Data → Networking and data;
    auth, googlesignin, profile, applock → Sign-in and account; media, push → Platform; firebase,
    analytics, flags, devtools → Observability; composemetrics, leakcanary, coverage,
    depsanalysis, baselineprofile → Build and quality. Group captions are gone (A1.9 has key/title).
11. **`firebase` is implied-only now** (A1.4); until WP06 adds crashlytics/firebaseanalytics/
    remoteconfig, the wizard and website reach it only through `push`.
12. **`snake_name` is unchanged** for all-caps names (`NASA Tracker` → `n_a_s_a_tracker`): it names
    the Keystore alias, and a regenerated or upgraded app with a different alias cannot decrypt
    what it stored.
13. **`--out` in zip mode must end in `.zip`** (A1.7 says it is the zip path; refusing a path
    without the suffix avoids writing a zip named like a directory).
14. **accept.sh regenerates `after/`** before the golden check, so the check always compares the
    committed tree. It also puts each `test` on its own line and replaces `! grep …` with
    `if grep …; then exit 1; fi`: bash's `set -e` ignores a command negated with `!`, so the WP's
    form could never fail the script (Part D 14b).
15. **`add_feature.py --tab` places a new tab after the existing module tabs, before profile and
    settings**, not "last" as A1.10 and the WP say. That is where generation puts module tabs
    (audit 4.4): appending after settings would leave profile/settings mid-bar and differ from a
    freshly generated project with the same modules. The start destination (first tab) never moves.
16. **`--json` requires `--out` when generating** (A1.10 only says `--json` prints only JSON): the
    alternative is a save-location prompt, which a run promising machine output cannot answer.
17. **`--set key=null` removes the field** (null means absent in a spec file, so the two agree),
    and **`--set schema=…` is refused**: overrides apply after the upgrade, so a schema there would
    be accepted and never read.
18. **targetSdk and compileSdk are capped at the newest level in `API_LEVELS`** (37): beyond it
    there is no SDK platform, and the first build fails. A new Android release means a new row in
    `API_LEVELS`.
19. **No `androidx.room3` entry in `check_versions.REPOSITORIES_BY_GROUP`**, although the WP names
    it: the `androidx` prefix already maps it to Google's repository, so a separate entry only
    suggested it publishes elsewhere.
20. **Swift `Borders.hairlinePx` is an `Int` of device pixels** (as Kotlin's `const val`), not a
    `CGFloat` of points: draw it as `hairlinePx / displayScale`.
21. **The wizard bounds each answer with the validator's own constants rather than re-running
    `validate_android` on the assembled block.** A failed block check could only re-ask the whole
    block, since one `SpecError` names one field; per-question bounds re-ask just the wrong answer.
    Drift is caught by `test_prompts`, which sends the wizard's highest and lowest accepted answers
    through `read_spec` and checks that one past each bound is asked again.
22. **Display names are counted in code points and refuse only Cc, Cs, Zl, Zp and U+FFFE/U+FFFF.**
    A1.3 promises any Unicode; `isprintable()` refused ZWNJ (Persian), ZWJ emoji and no-break
    spaces. Surrogates cannot be written as UTF-8, and U+FFFE/U+FFFF are not XML characters. WP10's
    TypeScript validator must count code points (`[...name].length`), not `.length`:
    `validation_cases.json` has a 30-emoji name that is valid and a 31-emoji one that is not.
23. **`UNUSED-RES` scope**: resources declared in `src/main/res/values/` (string, plurals, color,
    dimen, string-array/integer-array/array) and `src/main/res/{drawable,raw,xml,font}*/`; references
    from Kotlin (comments stripped), Gradle and every XML file outside `values*` folders. Styles,
    attributes and other values tags are not checked and everything they name counts as used; a
    tracked values resource's own references count only once it is used, which keeps the
    font-certificate arrays (named by their parent array) clean. Any `…R.kind.name` counts, since
    modules import each other's `R` under an alias. The scratch check's `app_name` exception is
    gone: the manifest references it.

## Rules and gotchas the docs must state

- Every pattern is matched in full; spec strings are not trimmed.
- A v2 spec with an unknown field is refused; schema-1 specs keep working, with notes.
- Generated lines are final text: never write template tokens (`com.base.app`) into `regions()`
  output expecting them to be renamed.
- A region's default lines are template text: they are renamed, and they are what the template
  compiles with.
- `[regions] required` lists every name; a target may not supply anything else.
- Markers inside JSON are an error; use `owns` or a generated file.
- New strings need a line in every language's module file, or generation fails.
- After touching tokens, an emitter, a feature TOML, presets or rules: run both `--write` commands
  and commit the emitted files; resolve conflicts in them by re-running `--write`, never by hand.
- `python3 -m tests.consistency --quick` before declaring a template change done.
- Repository docs (root `AGENTS.md`, `README.md`, `web/README.md`) still describe `genkit/spec.py`,
  `genkit/catalogue.py`, `tests/spec_full.json` and `translations/<lang>.json` (WP12).
