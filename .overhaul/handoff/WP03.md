layout), swipe down to dismiss, the same message again restarts the one showing, time counts only while the
lifecycle is STARTED, `Success`/`Error` tones play `Confirm`/`Reject`. The overlay layers expose test tags as
resource ids themselves (they are siblings of the app root). `AppMenu` is a `Popup` (its own window).

## Press feedback as built (A4.1)

| Control | Feedback |
|---|---|
| `AppButton` Filled, Tinted, Destructive; `AppChip`; clickable `AppCard`; `AppStatTile` with onClick; `AppRating` stars; date cells | `Scale` (0.96; 0.98 for anything 80 dp tall or more; 0.90 for controls 56 dp or smaller) |
| `AppButton` Plain, `AppIconButton`, `AppLinkButton` (top-bar back and actions, toast action, sheet close), date and time pills, swipe-action buttons, a chip's remove button | `Dim` (alpha 0.45, `ModulateAlpha`) |
| `AppRow`, `AppMenuItem` (so `AppSelectField`'s options), action-sheet rows, alert buttons, `AppDisclosure` header, `AppDataTable` rows | `Highlight` |
| `AppSwitch`, `AppCheckbox`, `AppRadio`, `AppToggleRow`, `AppSegmentedControl`, `AppTabRow`, page dots, bar items; `AppSelectField`'s field (its menu answers) | `None` (`indication = null` passed to `selectable`/`toggleable`) |

Rules as built: the press shows after the tap timeout (a scroll that starts on a control does not flash it); a tap
quicker than that still plays the whole dip (80 ms to full) then the release spring; with reduce motion `Scale`
becomes `Dim`; focus draws a `focusRing` outline; Enter/Space/D-pad centre activate. A checkbox, radio or switch with
a null callback is not clickable, so its row's tap reaches the row.

## Colour roles (A4.5)

Added: `backgroundGrouped, surfaceGrouped, surfaceElevated, fill, separator, outline, accentContent, highlight,
shadow, barIndicator, skeletonHighlight`, status `on`. Removed: `border, borderStrong, divider, surfaceVariant`,
status `border`. `onAccent` and status `on` are computed from luminance (`readableOn`), `accentContent` and status

## Deviations from MASTER-PLAN, with evidence

1. **Frame-time readout uses `Window.OnFrameMetricsAvailableListener`, not JankStats.** JankStats wraps the same
   listener on API 24+ (the template's minimum is above that), so the dependency would add nothing the catalog uses.
2. **The sheet's pinned footer is placed by the sheet's own layout** (at `max(windowBottom - footerHeight,
   sheetTop)` in the placement block) instead of reading a `LocalSheetVisibleHeight` in its own `layout {}`. Same
   property (a drag re-places, never remeasures, `SheetTest`), one fewer composition local.
3. **Back while a sheet is dismissing is consumed, not disabled.** Disabling the handler would hand the second Back
   to the screen beneath and pop it; consuming it is what A3.7's "no double pop" needs (`SheetTest`).
4. **A4.4 "Replaces" column**: names roles the old scale did not have; mapping by size in the table above.
5. **Detent haptic** plays only when a settle lands on a different detent than the drag started from (A4.2 says
   "sheet detent snap"; snapping back to the same detent is not a snap).
6. **Catalog release is signed with the debug key**, so a release build (the only kind whose motion means anything,
   Part D 12) installs directly.
7. **Date cells scale instead of highlighting** (A4.1 lists them under Highlight). `RowHighlight` fills the node's
   rectangle, while a date cell's selection is a circle; a square flash behind a round selection looks broken, and
   the 0.90 compact scale reads as the circle being pressed.
8. **CP1 recorded on the emulator**: the phone is attached but PIN-locked (`dumpsys trust`: `deviceLocked=1`,
   keyguard secure); entering a PIN is not something an agent may do.
9. **No `preloaded_fonts` manifest meta-data** (A4.4 and WP03 phase A step 4 ask for it). In the framework
   (`~/Android/Sdk/sources/android-37.0/android/app/ActivityThread.java:8329-8339`) the meta-data makes
   `handleBindApplication` call `Resources.preloadFonts`, which loads each font of the array through
   `Typeface.createFromResources` -> `FontsContract.getFontSync` (`Typeface.java:399-424`): a provider query on the
   main thread before `Application.onCreate`, waiting up to `SYNC_FONT_FETCH_TIMEOUT_MS = 500` per font when the
   provider has not got it yet. The Typeface it caches is the framework's; Compose's `GoogleFont` goes through
   androidx.core's `FontsContractCompat` and its own cache, so the app would pay on every cold start (5 fonts for the
   Neutral voice) and draw with none of it. The startup gate's bounded `FontFamily.Resolver.preload` already
   starts the provider's download at the same moment, off the main thread.
10. **S10 frame-rate votes: no `preferredFrameRate` added.** Every motion SMOOTHNESS-PLAN S10 names for WP03 (sheet
    drag, pull to refresh, swipe actions, overscroll release) moves its content by placement (`placeWithLayer`,
    `Modifier.offset { }`), and Compose 1.12.1 votes `FrameRateCategory.High` for every placement change on an ARR
    display (`NodeCoordinator.placeAt`, `GraphicsLayerOwnerLayer.move`); only layer-property changes vote the
    layer's own rate, 0 unless set. A permanent `preferredFrameRate(High)` would add nothing to these, and on the
    refresh spinner (redrawn every 125 ms) it would hold 120 Hz for an 8 fps animation. The Redmi has no ARR, so
    there is nothing to measure here either.
11. **S11: no cache window on the design system's lists.** The plan allows one only behind a scroll trace that shows
    prefetch running out of time; WP04's scroll gate passes (0.15 % janky, GPU p90 6 ms). The design system's mixed
    list (`AppDataTable`: header, rows, totals) passes `contentType`; the others hold one kind of item. R14's
    identity-compared `resetKey` went with the `AppSwipeActionsState` holder.
12. **No Kotlin ABI dump of the sheet package (SHEET-SPEC §19.1 item 10).** KGP 2.4.20's `abiValidation` finds no
    class files in an Android library built with AGP 9.4.1's built-in Kotlin: `internalDumpKotlinAbi` runs and
    leaves `build/kotlin/abi` empty (UP-TO-DATE on the next run), and `updateKotlinAbi` fails with
    `MissingValueException: Cannot query the value of this provider` in a provider-backed file collection
    (`$O/logs/r16-t2.log`, `r16-t3.log` with the stack trace, `r16-t4.log`), with the default
    `binariesSource = MAIN_COMPILATION` and with `NON_TEST_COMPILATIONS` alike. The plugin's
    `JvmOrAndroidKt.finalizeAndroidVariant` takes the classes of the "release" compilation of the
    `KotlinAndroidProjectExtension` target (read from the 2.4.20 jar with `javap`), and no compilation output reaches
    it in this setup. Since `check` would run `checkKotlinAbi` and fail, the block is not in the build file. The
    public surface stays guarded by `SheetApiShapeTest`, which compiles SHEET-SPEC §4.1's blocks against it and checks
    names, parameter order and defaults. Revisit when KGP's ABI validation supports AGP's built-in Kotlin (or when
    the template applies `org.jetbrains.kotlin.android` again).
13. **No status-bar tap to scroll to the top (REQUIREMENTS 41).** On Android the status bar is SystemUI's own window
    above the app's: a touch in it goes to SystemUI (a swipe opens the shade, a tap does nothing the app can see), and
    an edge-to-edge app draws under that window without receiving its input. There is no platform callback either
    (`ios-motion-catalogue.md`: "There is no Android equivalent, so the tab re-tap is the substitute"). A tap target in
    the app's own top bar would be a different gesture that iOS does not have and that competes with the bar's
    buttons, so none was added. The re-tapped tab (WP04's `ScrollToTopOnReselect`) scrolls to the top, on
    `animateScrollToTop()` after the merge.
14. **The iOS fling is named at each container, not installed once.** Compose 1.12 has no composition local for the
    default fling (`ScrollableDefaults.flingBehavior()` builds the platform's spline fling; foundation 1.12.1 has no
    `LocalFlingBehavior`, checked with `javap`), unlike the edge, which `LocalOverscrollFactory` sets for a whole
    subtree. A design-system wrapper for every lazy layout would fork Compose's API for one argument, so each container
    names `AppScrollDefaults.flingBehavior()`, and the sweep's `--check` (in `accept.sh`) and the `scroll-fling` code
    rule (in generated projects) keep it that way.

## Rules and gotchas the docs must state

- Every control states its feedback: `Modifier.pressable(onClick, feedback = …)`; a bare `clickable` under
  `NoIndication` gives no feedback at all. Foundation's `selectable`/`toggleable` take `indication = null` explicitly.
- Haptics are silent unless the moment is in A4.2's table; `rememberAppHaptics().perform(AppHaptic.X)`.
- Springs come from `AppTheme.springs` (`.unit`, `.pixels`, `.offset`, `.dp`); fades from `fadeIn()/fadeOut()`;
  never `tween(300)`.
- Overlays called from a screen render in the window's layers; a screen never draws an alert or toast itself. Show a
  toast with `LocalOverlayHost.current?.toasts?.show(ToastMessage(…))`.
- Fonts: the startup gate runs `AppFontPreload.run(resolver)`; `AppTheme` draws with `AppFontPreload.fonts`, decided
  once per process. A preview or test passes `fonts = PlatformFonts`.
- Never add `<meta-data android:name="preloaded_fonts">` to a Compose app: the framework fetches each listed font
  synchronously on the main thread before `Application.onCreate` (up to 500 ms per font when the provider does not
  have it yet), into a cache Compose's `GoogleFont` never reads. It only slows cold start.
- Text fields take the ViewModel's `TextFieldState` (A6.1); nothing mirrors the text into `UiState`.
- The catalog: `adb shell am start -n <pkg>.catalog/.CatalogActivity --es section Feel`; extras `theme`
  (`light`/`dark`), `style`, `motion` (enum names), `rtl`, `reduceMotion` (booleans), `fontScale` (float). A new public
  `App*` composable fails `tests.test_catalog_coverage` until it has a catalog entry.
- Robolectric tests use `TEST_SDK = 35` and `setThemed { }` (light, motion on).
- A `Modifier.Node` that implements a node kind itself (`DrawModifierNode`, `SemanticsModifierNode`, …) is the only
  node of that kind Compose visits; delegates of the same kind are skipped. Draw everything from the node, or keep
  the node itself out of that kind. Rendering bugs like this pass semantics tests: check pixels with
  `@GraphicsMode(GraphicsMode.Mode.NATIVE)` and `captureToImage()` (see `RowHighlightTest`).
- `AnimatedContent` measures its children with its own constraints; under `fillMaxSize()` a child that should wrap
  becomes window-sized. Wrap the child in a full-size `Box` with an alignment, and animate it with
  `animateEnterExit` so slide distances are its own size (see `ToastLayer`).
- `fillMaxHeight()` inside a `BoxWithConstraints` in a scrolling column has no height to fill; size an indicator to
  its siblings with `matchParentSize()` (see `AppSegmentedControl`).
- Sheets (REQUIREMENTS 33): keep `AppSheet` composed and drive `visible` (or `item`); never put it in an `if`, a `when`
  or a lazy item, which removes it without its exit. A sheet called in a loop needs `key(…)` around it: its saved
  state is keyed by call site.
- A sheet's content brings one root, a lazy list or `SheetColumn`, that takes `contentPadding` (or
  `sheetContentPadding()`): it keeps the gutter while the sheet floats and the last row above the footer, the
  navigation bar and the keyboard. Never add `imePadding()` or `windowInsetsPadding(WindowInsets.ime)` inside a sheet:
  the sheet already consumed them, and `fitInside(WindowInsetsRulers.Ime…)` re-measures on every keyboard frame.
- `AppSheet(modifier = …)` is for test tags, semantics and focus. The caller's test tag wins over the default
  `sheet_surface`; the sheet's own pane title wins over a caller's semantics (the outer semantics on a node wins).
- A `SheetDetent.Custom` resolver runs in measure and must read no state: capture values (`val f = fraction`) and
  remember the detent by what it captured.
- A `when` over `SheetDetent`, `SheetModality`, `SheetDismissSource` or `SheetMaterial` needs an `else`: they gain
  values. The shell seams (`@ShellSeamApi`) are for the shell, navigation and glass, never a feature.
- Ask before closing a dirty form with `SheetDismissConfirmation(enabled = changed, onDiscard = …)`; Done after a save
  calls `scope.dismiss()`, which asks nothing. `onDismissRequest` runs once per close by the person, `onHidden` once
  the sheet has gone, whoever closed it.
- Android 14 and later scale large text far less than body text (34 sp stays 34 sp at 1.5x). A display title that
  should still follow the person's setting grows linearly to a cap (`AppLargeTitleTopBar`: 1.3x, iOS's large title at
  its first accessibility size); a glyph beside text scales as that text does (`AppSearchField`'s magnifier).
- A screen that themes itself apart from the system (the catalog's `--es theme dark`, an app set to Dark) sets the
  system bar icons from its own theme with `enableEdgeToEdge(SystemBarStyle.…)`; `ComponentActivity.enableEdgeToEdge()`
  alone follows the system's dark mode.
- A component that keeps its parameters in a controller written from `SideEffect` must not read them back in the same
  composition: the first composition sees the defaults and composes twice (a backwards write, jetpack-compose-performance
  §1). Pass what composition knows (modality, placement, pane title, the surface, the content width) down as parameters
  or composition locals; keep the controller for layout, draw and callbacks.
- Padding that only makes room to scroll (a sheet's reach at a partial detent) must never count toward a height the
  layout derives from the content (FitContent, a fitted custom detent): the derived height moves the rest, which moves
  the padding, every pass. Subtract it in the content's own whole pixels, or a sub-pixel remainder still loops.
- Compose UI tests on the v2 rules with `mainClock.autoAdvance = false`: a state write in `runOnIdle` reaches the
  recomposer only after `Snapshot.sendApplyNotifications()`; without it `advanceTimeByFrame()` recomposes nothing.
- A `Modifier.Node` reads composition locals (`currentValueOf`) in measure, layout or draw, never in `onAttach`: a
  value read there goes stale on rotation or a display change, and lint fails the build on it
  (`SuspiciousCompositionLocalModifierRead`).
- `ComposeContentTestRule.setContent` runs once per test: a helper that shoots several cases composes them under one
  `setContent`, each inside `key(case)` so no state carries over (`SheetShots`).
- `FontFamily.Resolver.preload` throws `IllegalStateException("Unable to load font …")` for every font it could not
  fetch: no font provider on the device (no Play services), no network, and its caller's own timeout or cancellation,
  which it catches and wraps (`FontListFontFamilyTypefaceAdapter`, ui-text 1.12.1). A preload under
  `withTimeoutOrNull` therefore crashes the launch whenever the provider is slow; catch the `IllegalStateException`,
  then `currentCoroutineContext().ensureActive()` so a real cancellation still propagates (`FontPreload.run`).
- A bar pinned above the navigation bar while content scrolls beneath it must carry its background through the
  strip below it, or the content shows between the bar and the screen's edge. Outside a sheet `AppBottomActionBar`
  pads the inset inside its background; as a sheet's footer it draws the strip (`sheetFooterBacking`).
- A fling built on `exponentialDecay` needs an `absVelocityThreshold` in pixels a second that means "at rest" (the
  design system's is 30, a quarter pixel a frame at 120 Hz): at the default 0.1 a slow release keeps the scrollable
  in progress for four seconds and more after it visibly stopped, and every tap in that time is taken as "stop
  scrolling", so taps seem to do nothing: foundation 1.12.1's `DragGestureNode` consumes the down on the initial
  pass when `startDragImmediately()`, which the scrollable answers with `ScrollingLogic.shouldScrollImmediately()`
  = `isScrollInProgress || overscrollEffect.isInProgress` (read from the bytecode with `javap`).
- An on-screen frame-time readout judges a frame late against `FrameMetrics.DEADLINE` (API 31+), not one refresh
  period: with a buffer queued a frame may take longer than a refresh and still be shown on time. Only `perf.sh`
  numbers from a release build are results.
- Compose learns a window's insets only after a composition reads `WindowInsets`: foundation-layout 1.12.1 creates
  the view's holder empty and installs its listener in that composition's effect, and the insets arrive a traversal
  later. A screen that composes nothing while it waits (for fonts, for data) and then composes its content lays that
  content out once without the status bar and jumps on the next frame. Compose the real content under the splash (the
  app's startup gate does), or read the insets in the placeholder (`CatalogActivity`).
- A value a sibling writes during measure (the top bar's height into `LocalTopChrome`) and a container reads in
  composition (`contentPadding` built from it) is a frame late whenever it changes. Read it where it is laid out: a
  `PaddingValues` whose `calculateTopPadding()` reads the holder (WP04's `chromeContentPadding`).
- Button labels wrap rather than truncate: at 200 % text a long label must still read whole (WCAG 1.4.4); keep labels
  short instead of relying on an ellipsis. Identifiers shown in narrow tiles (token or icon names) get a zero-width
  break before each inner word, or they break mid-word.
- Robolectric measures text with real font metrics only under `@GraphicsMode(GraphicsMode.Mode.NATIVE)`; a test of
  line breaking or text width in legacy mode passes or fails for the wrong reason (`AppButtonTest`).
- **iOS scrolling is the default, and it has to be named (REQUIREMENTS 41).** Compose has no composition local for a
  default fling: a `LazyColumn`, `LazyRow`, grid, `verticalScroll` or `horizontalScroll` that names no `flingBehavior`
  gets Android's spline fling, and nothing in a preview shows the difference. Every container passes
  `flingBehavior = AppScrollDefaults.flingBehavior()` (a pager `AppScrollDefaults.pagerFlingBehavior(state)`); a list
  the person cannot scroll (`userScrollEnabled = false`, a placeholder) needs none. The code rule `scroll-fling`
  (`$O/code-rules/ScrollRules.kt`, for `verifyCodeRules`) fails a feature, `core/ui` or `app` container without it;
  `// allow(scroll-fling): <why>` on the line above keeps the platform's fling on purpose.
- The fling is UIScrollView's normal deceleration (0.998 of the speed kept per millisecond, a continuous rate of
  2.002 a second): a release at v travels v / 2.002 and its speed halves every 346 ms. It ends at 30 px/s, where the
  content no longer visibly moves; that costs 15 px of the iOS distance and keeps a tap after a gentle scroll from
  only stopping an invisible fling (`AppFlingCurveTest`, `AppFlingTest`). A second flick in the same direction within
  500 ms carries part of the first one's speed, as iOS's momentum does.
- The edge needs nothing per container: `AppTheme` installs the rubber band (`AppOverscroll`, iOS's
  `(1 − 1/(x·0.55/d + 1))·d`) for every scrolling container below it, and a fling that reaches the end carries up to
  5000 px/s past it into the band and springs back on `bounceBack` (`AppOverscrollTest`). A screen that wants
  Android's stretch provides `rememberPlatformOverscrollFactory()` around that container.
- An `OverscrollEffect`'s `applyToFling` gets a `performFling` that returns the velocity the content and its parents
  *used*, not what is left (foundation 1.12.1, `ScrollingLogic`): the leftover is `velocity - performFling(velocity)`.
  A fling that rests by itself still reports its decay's resting speed, so a leftover below the release minimum is not
  a throw into the end (`ScrollDirectionTest`).
- In an `OverscrollEffect`'s `applyToScroll`, the part of a delta that heads back towards the content eases the band
  first: it carries the delta's sign, so the pull shrinks by adding it (`pull += relaxed`). With the sign turned, a
  finger going back makes pulled content move on away from it, and a finger landing on a band still springing back
  meets the same; the user saw exactly this in the carousel and in lists (`bugs/BUG-2026-10-18-scroll-direction.md`,
  `ScrollDirectionTest`).
- Let go with the band stretched and moving back towards the content (a quick flick back after a pull), a spring
  started that fast crosses rest and swings the content past its place and back, against the flick. The band springs
  only until it reaches rest, stops there and hands the speed it still has to `performFling`, so the content scrolls on
  the flick's way at the content's speed, as `UIScrollView` keeps the velocity past the edge (`ScrollDirectionTest`'s
  catch and flick-back cases). Letting the fling's deltas eat the stretch in finger units instead would jump the
  content's speed by about 1.8x where the band ends.
- Nested scrolling hands velocity on: a flick up through a refreshing list's gap closes the gap and carries straight
  into the list (`PullToRefreshTest`); a sheet takes a scroll up until its top detent before the list moves
  (`SheetNestedScrollTest`); the large title collapses from the list's offset, so it never takes velocity.
- Scroll to the top with `LazyListState.animateScrollToTop()` / `ScrollState.animateScrollToTop()`: a list more than two
  screens down jumps to two screens first, so the trip is short and composes only those rows (`ScrollToTopTest`).
  Android delivers no status-bar tap to an app (the status bar is SystemUI's window and takes the touch), so the
  re-tapped tab is the way to the top; `animateScrollToItem(0)` alone animates through every row in between up to
  100 items, composing each.
- Fields set side by side align by `FieldBoxTop`, the alignment line at the top of every field's box
  (`Modifier.alignBy(FieldBoxTop)` in a `Row`): their boxes stay level when one label wraps at large text, only one
  has a label, or one shows an error beneath it. Aligning a row of fields by `Top` or `Bottom` breaks in each of those.
- A control inside a field, beside its text (a reveal, a clear button, a chevron), grows with the field's text
  (`FieldIconButton`, `scaledLike`); a bar's icon buttons keep their size.
- (Generator, for the repository's AGENTS.md.) A test of an optional group's component lives in that group's own test
  package, which the feature's TOML `owns` beside its main package (`pickers`, `formfields`, `datadisplay`,
  `collections`). A shared test that imports one (a recomposition journey, a posture case) compiles in the template,
  where every feature is on, and breaks `./gradlew build` in every project generated without it.
  `OrphanedTestTest` catches a test left in a removed package's mirror, not an import from elsewhere.
