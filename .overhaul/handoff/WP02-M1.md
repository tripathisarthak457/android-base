## Public APIs added, changed, removed (signatures)

### MviViewModel (`:core:mvi`, package `com.base.app.core.mvi`)

```kotlin
abstract class MviViewModel<S : UiState, E : UiEvent, F : UiEffect>(initial: S) : ViewModel() {
    val state: StateFlow<S>
    val effects: Flow<F>                  // Channel.BUFFERED
    val messages: Flow<UiMessage>         // Channel.BUFFERED
    fun onEvent(event: E)                 // = handleEvent(event), main thread, never suspends
    protected abstract fun handleEvent(event: E)
    protected val current: S
    protected fun setState(reduce: S.() -> S)
    protected fun emit(effect: F)
    protected fun showMessage(text: UiText, title: UiText? = null, kind: MessageKind = Info,
                              durationMillis: Long = UiMessage.DEFAULT_DURATION_MILLIS, action: MessageAction? = null)
    protected fun launchLatest(key: Any, debounce: Duration = Duration.ZERO, block: suspend CoroutineScope.() -> Unit): Job
    protected fun launchExclusive(key: Any, block: suspend CoroutineScope.() -> Unit): Job?   // null when ignored
    protected fun cancel(key: Any)
    protected fun <T> observe(flow: Flow<T>, reduce: S.(T) -> S)   // collects while `state` has subscribers, 5 s grace
    protected open fun onUnexpected(error: AppError.Unexpected) {}  // after Log.e; default does nothing
}
data class UiMessage(text: UiText, title: UiText?, kind: MessageKind, durationMillis: Long, action: MessageAction?, id: Long = unique)
sealed interface UiText { Dynamic(value); Resource(@StringRes id, args); Plural(@PluralsRes id, count, args); fun resolve(Context) }
```

Renamed from the old base: `updateState` → `setState`, `emitEffect` → `emit`, `currentState` →
`current`, `launchWork` → gone (use a keyed launch), `persistState` → gone (use
`SavedStateHandle.saveable` / `SavedStateHandle` directly), `showMessage(String)` → gone,
`Failure.toLoadState()` → `LoadState.Error(result.error)`, `Failure.userMessage()` →
`AppError.toUiText(fallback)` in `:core:ui`.

Implementation notes the docs should state: the jobs map is touched only on the main thread; each
keyed job is started lazily so it is in the map before its body runs, and removes itself in its own
`finally` only if it is still the mapped job; `observe` uses
`SharingStarted.WhileSubscribed(5_000).command(state.subscriptionCount)`, so in a unit test the
state must be collected (`viewModel.state.launchIn(backgroundScope)`) for an observed flow to run.

Failures map to: device offline → `AppError.Offline`; online, no answer → `AppError.Timeout`

## The three contracts other packages build on

### Dispatcher and scope injection (WP03, WP04, WP06, WP07)

```kotlin
class Foo @Inject constructor(private val dispatchers: AppDispatchers, private val appScope: ApplicationScope)
withContext(dispatchers.io) { … }        // never Dispatchers.IO inside a class
appScope.launch { … }                   // work that must outlive the screen that started it
```

`:app` provides both in `app/di/CoroutinesModule.kt`: `io = Dispatchers.IO`, `default =
Dispatchers.Default`, `main = Dispatchers.Main.immediate`; the application scope is
`SupervisorJob() + default + CoroutineExceptionHandler { Log.e(...) }`. In tests:
`AppDispatchers(d, d, d)` and `ApplicationScope(backgroundScope)`. The multiplatform template
provides the same two types from Koin.

### Text-field contract (WP03 `AppTextField(state = …)`, WP12 docs)

- The ViewModel owns one `TextFieldState` per field:
  `@OptIn(SavedStateHandleSaveableApi::class) val email: TextFieldState = savedStateHandle.saveable(KEY, saver = TextFieldState.Saver) { TextFieldState() }`.
  The argument must be named `saver =`: positionally it is ambiguous with the `MutableState` overload.
- Passwords are plain `TextFieldState()`, deliberately not saved (they do not belong in a bundle the
  system writes to disk).
- Validation reads `snapshotFlow { field.text.toString() }` inside `observe` (or a keyed launch);
  errors stay quiet until the first submit, then follow the text (`errorFor(text, shown)` in
  `feature/auth/AuthMessages.kt`).
- `UiState` holds only field errors (`UiText?`), `canSubmit`, `submitting` and a banner `error:
  UiText?`. Nothing mirrors the text into `UiState`. The route passes the fields to the screen next
  to `state` (`SignInScreen(state, email = viewModel.email, password = viewModel.password, onEvent)`);
  previews use `rememberTextFieldState()`.
- Until WP03's `AppTextField(state = …)` exists, screens bridge with
  `AppTextField(value = field.text.toString(), onValueChange = field::setTextAndPlaceCursorAtEnd, …)`.
  This is synchronous snapshot state, not a state-flow round trip, so it does not cause caret jumps;
  WP03's sweep replaces every bridge with `state = field`. Bridges: sample list search, search,
  sign-in, sign-up, password reset, profile name and bio.
- A field rule observes `snapshotFlow { field.text.toString() }.drop(1)`: it runs only when the text
  changes. `observe` restarts after 5 s unobserved, and the restart's first value is the text
  already judged; judging it again would replace the error the server returned for that field
  (`SignInViewModelTest` "the server's message on a field outlasts the screen going away").
  `canSubmit` observes without `drop`, since it must be right from the first frame.
- Tests drive fields with `field.edit { replace(0, length, "…") }` followed by
  `Snapshot.sendApplyNotifications()` (outside Compose nothing sends apply notifications, so
  `snapshotFlow` would not see the edit), and collect `state` so `observe` runs.
- Process death: `feature/auth/.../SignInViewModelTest.kt` `SignInProcessDeathTest` (Robolectric,
  SDK 35) round-trips `SavedStateHandle.savedStateProvider().saveState()` →
  `SavedStateHandle.createHandle(…)`: the email comes back, the password does not.

### Shared-key rule (WP04, WP07, WP14, WP02-M2 `modes.py`)

- A key only its own feature opens lives in `<pkg>.feature.<name>.api` inside the feature module
  (`feature/<name>/src/main/kotlin/<pkg path>/feature/<name>/api/<Name>Keys.kt`).
- A key another feature opens keeps the owner's package `<pkg>.feature.<owner>.api` but its file lives
  in `core/navigation/src/main/kotlin/<pkg path>/feature/<owner>/api/`. No template key is opened
  across features today, so no shared-key folder exists yet (git keeps no empty directories); M2's
  crossnav patch creates the first.
- Keys carry only primitives, `@Serializable` value classes from the same api package, or
  `:core:common` types; never `data:*:api` types. `verifyApiPurity` enforces this for files in any
  `…feature|data.<name>.api` package, wherever the file lives.
- Things `:app` must construct for a feature (`AuthDestination`, `OnboardingDestination`,
  `SettingsAppInfo`) are in the feature's api package too.

## Deviations from MASTER-PLAN, with evidence

1. **Submit state is `submitting: Boolean` plus a banner `error: UiText?`, not a submit `LoadState`.**
   The auth tests the WP asks for assert the message the person sees ("401 maps to the
   wrong-credentials message"), and that mapping is screen-specific (`authMessage` in
   `feature/auth`), so the ViewModel resolves the `AppError` to `UiText` and `LoadState.Error`
   would only duplicate it. Field errors and `canSubmit` are as planned.
2. **`MviViewModel` keeps `messages` and `showMessage`.** A6.1's sketch omits them, but A6.1's own
   bullets (unique `UiMessage` ids, lifecycle-aware `MessageHost`) need the channel.
3. **The search field watcher is a keyed launch started on `Appeared`, not `observe`.** Typing
   must trigger `launchLatest` (a side effect), and `observe` takes a pure reducer. The watcher lives
   as long as the ViewModel (for example while the search tab is kept); between keystrokes it only
   checks each global snapshot apply against the one field it reads. The repository flow
   (`recent`) does go through `observe`. A subscription-gated side-effect variant of `observe` in
   `MviViewModel` would remove the difference; it was not added in M1 (one user).
4. **The sample list's "showing saved data" banner is gone** with `AppResult`'s freshness fields
   (A6.2). M3 shows "Updated N min ago" once WP06's repositories expose when data was fetched
   (device-baseline F13); string `sample_showing_cached` and its translations removed.
5. **Onboarding writes its completion flag in `ApplicationScope`** after emitting `Finished`: emitted
   first per F18, and in the application scope because leaving the screen clears its ViewModel and
   would cancel the write.
6. **`common_error_*` keep their names** in `:core:ui` (no `ui_` prefix), so translations moved
   without renames.
7. **`AppTextField` bridge** (see the text-field contract): WP03 owns the component; screens use the
   String API with the ViewModel-owned state until WP03's sweep.
8. **`MviTestScope` is deleted, not ported** (A2.2 lists it in `:core:testing`). Nothing used it,
   and with `observe` gated on `state` subscribers a helper would only wrap two lines that each
   test states plainly: `MainDispatcherRule()` and `viewModel.state.launchIn(backgroundScope)`
   (plus `runCurrent()`/`advanceUntilIdle()`). `:core:testing` also no longer exposes
   `api(libs.mockk)` (A2.2 forbids it; nothing in the template imports `io.mockk`).

## Rules and gotchas the docs must state

- `handleEvent` never suspends; I/O only through `launchLatest`/`launchExclusive`; repository flows
  through `observe`; initial loads from an `Appeared` event the route sends from
  `LaunchedEffect(Unit)` (guard with `if (current.loadState == LoadState.Idle)`, because the entry
  can be recomposed).
- Emit navigation before persistence; a write that must survive the screen goes in
  `ApplicationScope`.
- `saveable(KEY, saver = TextFieldState.Saver)`: the named argument is required.
- In tests, collect `state` for `observe` to run (`viewModel.state.launchIn(backgroundScope)`
  followed by `runCurrent()`), and call `Snapshot.sendApplyNotifications()` after editing a
  `TextFieldState`. `advanceUntilIdle()` returns as soon as only background work is queued, so it
  can return before a `backgroundScope` collector has subscribed; a test that relies on the
  subscription uses `runCurrent()` (found when the restart test passed on the unfixed code).
- A write keyed with `launchLatest` must be idempotent under its key: two different writes under one
  key cancel each other (DataStore drops a cancelled edit). Key a write by its argument
  (`launchLatest(FORGET to query)`), or use an absolute value as settings does.
- `:core:common` must stay free of Android, DI and `java.*` imports (it compiles as plain JVM; the
  acceptance greps for it).
- Everything outside `api/` is `internal`, including Hilt modules that bind internal classes
  (`internal interface SampleDataModule`).
- The template's `AGENTS.md`, `docs/**` and `generator/genkit/readme.py` still describe the old MVI
  (`updateState`, `emitEffect`, `persistState`, queued events, `failure.userMessage`); they are WP12's
  (and WP01's README conversion) to rewrite from this note.
