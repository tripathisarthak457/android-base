## Rules and gotchas the docs must state

Build guards (every generated Android project; all wired into `check`):
- **`verifyCodeRules`** runs per Kotlin module (rule table above). A justified exception is
  `// allow(<rule-id>): <reason>` on the line above the finding; a marker without a reason fails. Scopes follow the
  file's path from the project root, so a modular `feature/x/impl` is held to the same rules as `feature/x`.
- **Adding a rule** (WP03's sheet rules, SHEET-SPEC §19.1 item 9; WP05's `kyant`): a `Rule(id, advice, applies,
  lines)` in the object of `buildlogic/guard/` that fits (`ComposeRules`, `KotlinRules`, `StructureRules`,
  `AdaptiveRules`), plus one `Fixture` line in `CodeRulesTest` with `/*!*/` on the line that must fire (the same
  table proves the allow marker silences it), and the less obvious cases in `CodeRuleCasesTest`. `KotlinSource` gives
  code lines with comments and strings blanked, so a rule never matches inside either. A rule scoped to a lambda's
  body (the sheet's IME rules) finds the call and its balanced braces in `codeLines`, as `LazyScopes.kt` does for
  lazy scopes.
- **`config/code-rules-baseline.txt` only shrinks.** An entry higher than what its file breaks fails the build, so a
  package that fixes code also lowers or deletes the line. New code never goes there. Moving a file drops its entry's
  match: the findings at the new path fail until the line is re-pathed. After merging WP02-M2, every package runs
  `./gradlew verifyCodeRules --continue` once and adjusts the lines for its own files.
- **Resources are prefixed by module.** The library convention sets `resourcePrefix` to the namespace's last segment
  plus `_` (`:core:ui` → `ui_`, `:feature:orders` → `orders_`), and lint's `ResourceName` is an error. Android merges
  every module's resources into one namespace, so an unprefixed `error_generic` in two modules silently resolves to
  one of them. Names a third party documents (Play services' font certificates) keep theirs under
  `tools:ignore="ResourceName"`.
- **Compose lint is an error** in Compose modules (the list in `android/Compose.kt`, checked against the lint jars;
  lint ignores an unknown id without a word). `UseOfNonLambdaOffsetOverload` and `FrequentlyChangingValue` are the ones
  agents hit first: read animated values in `offset { }`/`graphicsLayer { }`, never `offset(x = animated)`.
- **`checkComposeStability`** reads the compiler's report of `:core:designsystem`, `:core:ui` and `:core:navigation`
  (written in every build) and fails on a parameter the compiler compares by identity. With strong skipping such a
  composable is still skippable, but it reruns whenever a caller passes a new instance. Fix the type, list a truly
  immutable external type in `config/compose-stability.conf`, or add `fqName(param)  # reason` to
  `config/compose-stability-baseline.txt` (`recordComposeStability` writes entries without the reason, which then
  fail until one is added). Full reports and metrics for any module: `-PcomposeReports`.
- **`verifyManifestRules`** reads each variant's merged manifest, libraries included: no orientation or aspect-ratio
  locks, no `resizeableActivity="false"`, `configChanges` covering size, layout, orientation and keyboard on the
  launcher activity, the multi-instance property, an explicit `exported` on every component, and
  `enableOnBackInvokedCallback="true"`. A library component that breaks one is named in `config/manifest-allow.txt`
  with a reason.
- **Screenshot tests come from previews.** `<pkg>.android.screenshots` (applied by every feature, the design system and
  the catalog) turns each preview in the module's own package into a Robolectric test at the sizes its annotation
  lists (`@AppScreenPreviews`: the six PR sizes). Without goldens they still render every preview, so a crash at one
  size fails `check`. Record with `./gradlew recordRoborazziDebug`, commit `src/test/screenshots/`; CI then runs
  `verifyRoborazziDebug`.
- **Compose tests use the v2 rules** (`androidx.compose.ui.test.junit4.v2.createComposeRule`): effects run on a
  `StandardTestDispatcher`, so a test advances the clock (`mainClock.advanceTimeBy`, `waitForIdle`) instead of relying
  on effects running immediately.
- **Unit tests run once:** only in modules with `src/test` (or the screenshot convention), debug only, and in the app
  only for `devDebug`. The tasks are `testDebugUnitTest` (libraries) and `testDevDebugUnitTest` (app).
- **Fakes live in the test fixtures of the module that owns the interface** (CODE-STANDARDS T-2):
  `data/<n>/src/testFixtures/kotlin/<pkg>/data/<n>/api/Fake<X>Repository.kt`, used from another module's tests with
  `testImplementation(testFixtures(project(":data:<n>")))`. The conventions switch fixtures on when
  `src/testFixtures` exists. Keep a fake in the `api` package and on `api` types only: the modular split moves it
  into `:data:<n>:api` with the interface, and rewrites the dependency to `testFixtures(project(":data:<n>:api"))`.

Build switches: `-PabiSplits=true` (per-ABI APKs plus universal), `-PapiBaseUrl=<url>` (dev and staging only; the
shipped flavours ignore it), `-PcomposeReports`. Variants: dev, staging, prod × debug, release, plus
`devBenchmarkRelease`, `devNonMinifiedRelease` and `playstoreRelease` (9, was 15). The APK ships only the languages
the app ships (`localeFilters`, filled by the generator), no LICENSE files and no `.kotlin_builtins`.

R8: kotlinx-serialization's consumer rules keep every `@Serializable` serializer, and AGP's
`proguard-android-optimize.txt` keeps enum `values()`/`valueOf()`; do not repeat them. Navigation keys need no keep
rule either: their serial names are strings the serialization plugin writes into each serializer, and every key is
registered with `subclass(…)`, so R8 renaming the class changes nothing a saved back stack holds. The analyzer is
`./gradlew :app:analyzeProdReleaseR8Config` (one task per variant). Never add
`-assumenosideeffects` for Compose's `traceEventStart`: the recomposition harness and `runtime-tracing` read those
markers. `runtime-tracing` is a dev-only dependency, so a Perfetto trace of a dev build names the composables in a slow
frame.

Generator:
- **Modular projects** (`"architecture": "modular"`, or `python3 -m genkit.targets.android.modes <project>` on a
  compact one): each `feature/<n>` and `data/<n>` splits into a pure-Kotlin `:api` (its `api/` package) and `:impl`;
  shared keys in `core/navigation/src/main/kotlin/<pkg>/feature/<owner>/api/` move to the owner's `:api`. Files move
  without a text change, so a key another feature navigates to belongs in its owner's `api/` package from day one.
  `add_feature.py --domain <name>` writes a pure-Kotlin `:domain:<name>` and is refused in compact projects.
- **Tabs:** at most five in the compact bar. Order: Home, the modules in spec order, Feed, Search, Profile, Settings;
  past five, a phone's bar shows four and More (Settings goes first), a rail holds seven (six and More past that)
  and a large window's sidebar lists every tab; the generator warns in `--dry-run` and the headless JSON, and the
  website's preview draws the same bar.
  Each module tab gets a distinct glyph from its name, with its filled form when selected.
- **Scaffolded modules** (`feature_modules`) come in the reference shape: `api/<P>Keys.kt`,
  `navigation/<P>Navigation.kt` (`NavPane.List/Detail`), `list/` and `detail/` (Contract, ViewModel, Route, Screen), a
  ViewModel test using `Fake<P>Repository` from the data module's test fixtures, `<P>RecompositionTest`, and with
  network a DTO decoding a JSON fixture.
- **Vendored Android skills** live in `.agents/skills/` byte for byte (`[files] verbatim` in `template.toml`: no
  rename, no marker parsing) with `MANIFEST.sha256`; `.claude/skills/<name>/SKILL.md` are pointers. Every project gets
  navigation-3, navigation-event, adaptive, edge-to-edge, testing-setup, android-profiler, r8-analyzer, the two
  security skills, agp-9-upgrade, jetpack-compose-performance and android-cli; `auth` adds restore-credentials and
  verified-email, `media` adds camerax (the feature's TOML `owns` both folders). Refresh only with
  `tools/update_android_skills.py <checkout> --tag vX.Y.Z` from a checkout git did not convert to CRLF (the tool
  refuses one, naming the first file: on Windows clone with `-c core.autocrlf=false`); `test_vendored_skills.py`
  fails on a hand edit. Where a skill and `AGENTS.md` disagree, `AGENTS.md` wins.
- **The Compose performance audit is part of "done".** Generated `AGENTS.md` §9 item 3: a change to Compose UI goes
  through Google's jetpack-compose-performance audit (all seven categories, the category's `references/*.md` read
  before each fix). The code rules that encode one of its rules end their message with the page to read
  (`(read .agents/skills/jetpack-compose-performance/references/<page>.md)`); a rule given a `reference` must name a
  page of a skill every project ships (`test_vendored_skills.py` checks). Where the project departs from the skill:
  Compose 1.12 (`derivedStateOf`, not `computedStateOf`), ViewModel state on `collectAsStateWithLifecycle()`
  (Deviation 13), and the collection lines in `config/compose-stability.conf` (its comment gives the reasoning).
- **`formatting`:** Spotless with ktlint's `android_studio` style at 100 columns, read from `.editorconfig`, so the IDE
  and the check agree. Run `./gradlew spotlessApply` before committing.
- **Imports are sorted after generation.** The template orders imports for `com.base.app` with every feature on; in a
  project named `io.acme.app` that package belongs after `dagger`, and dropping a feature's fenced imports leaves the
  rest out of order. The generator re-sorts every `src/**/*.kt` import block in ASCII order by path (ktlint's `*`
  layout, the same as Android Studio's Optimize Imports), drops blank lines and duplicates, and moves a `//` comment
  line with the import below it. Anything else between imports (a block comment) leaves that file as written.
- **Scaffolded code is already in ktlint's layout at every module-name length** (1 to 30), so `spotlessApply` leaves
  a new module untouched. ktlint's `android_studio` style puts a signature, class header or call on one line exactly
  when it fits in 100 columns, so the layout depends on the name: a snippet lists ktlint's layouts, most compact
  first, between `__FIT__`, `__ELSE__` and `__END_FIT__` lines, and the generator keeps the first whose lines all
  fit. Editing a snippet: write each layout the way `spotlessApply` leaves it, and when a line's length depends on
  the name, run `spotlessApply` on projects scaffolded at every name length with and without network (outside the
  repository: `$O/r10-fit.sh`); `test_android_scaffold.py` checks only the 100 columns.
- **`scroll-chrome`:** in a feature, every lazy list takes `contentPadding = chromeContentPadding(…)` and every
  `verticalScroll` chain goes on to `.padding(chromeContentPadding(…))`, so content runs under the floating bars and
  the large title and comes to rest clear of them. Padding the container or its parent instead clips the content at
  the bars (`qa/shimmer/AUDIT.md` C-1). A list that takes its caller's `contentPadding` passes and leaves the chrome
  to the caller; a scroll that is not a screen's (a dialog's text) takes an allow marker with its reason.
- **Scaffolded screens clear the chrome:** every scrolling container takes `chromeContentPadding(...)` as its
  `contentPadding` (a `verticalScroll` column pads inside the scroll), never padding on the parent, so content scrolls
  under the floating bars and rests clear of them. A loading placeholder is the row's own card with a bone sized by a
  transparent line of the text style it stands for, so the rows replace it in place at any font scale, and with a
  text line's corners (`shapes.xs`, as `AppSkeletonLine`). Not the style's `lineHeight`: with
  `LineHeightStyle.Trim.Both` a single line is shorter than that (`titleMedium`, 20 sp line height, lays out 16 dp
  tall at font scale 1), so a bone of `lineHeight` makes every row jump by 4 dp. A one-line bone still stands for one
  line: a title that wraps arrives taller, which only redaction (the real row drawn with placeholder data) avoids.
- **Measure sizes in Compose tests with `fetchSemanticsNode().size`,** not `getBoundsInRoot()`: bounds are clipped to
  the root, and Robolectric's default screen is 320 × 470 dp, so anything laid out past 470 dp in a scrolling column
  reports a clipped height (run 9's one-off test read a 33 dp bone as 3 dp).
