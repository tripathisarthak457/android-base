### The network client and auth flow as built

1. Every request goes through one Ktor client on the shared `OkHttpClient`. An `HttpSend` interceptor reads the
   tokens from `AuthTokenStore` for each request to the API host (never another host, never a request marked
   `requiresAuth = false`), so no client holds a token that can outlive its session.
2. On a 401, `SessionTokens.refresh(stale)` runs under a mutex: if another caller already replaced the pair, the
   stored pair is returned without a call; otherwise the refresher's plain client asks the server. Success
   swaps tokens with `replace(expected, new)` (compare-and-set), so a refresh that lands after a sign-out or a
   different sign-in changes nothing. Tokens of another owner are never handed back: a request refused in one
   person's session is not sent again in someone else's. Only a 401 from the refresh endpoint clears the tokens and fires
   `SessionEvents.expired`; 408, 429, 5xx and no answer keep the session.
3. Failures are values: `Offline` (no network per the monitor), `Timeout`, `Http(status, code, message,
   fieldErrors, retryAfterSeconds)` parsed once by the bound `ResponseUnwrapper`, `Decode`. Bodies are read
   once; an empty body (204) decodes as `{}`. Request headers replace the client's defaults.
4. `ConnectivityNetworkMonitor` registers one callback shared by every collector (`WhileSubscribed(5_000, 0)`),
   counts `NET_CAPABILITY_INTERNET`, and never gates a request.

### Session teardown list (`SessionScopedStore`, cleared once per session end)

Tokens (by the coordinator), `AppDatabase.clearAllTables()`, the OkHttp cache, in-flight shared GETs, the
WebSocket, the push registration (FCM `unregister()` + its file), flag overrides, the analytics and crash user
ids, recent searches, the profile file and avatar directory. The offline queue (`queue.db`) is deliberately not
cleared: its entries carry their owner and wait for that person.

### Offline queue policy

Owner-scoped entries; one pass at a time (mutex); oldest first; success deletes; a 4xx other than 401, 408, 426,
429 marks the entry refused with the server's status, code and message and the pass moves on; anything else
counts an attempt and ends the pass; a change of session during the pass ends it before the next entry
(requests read the token as they go); entries older than 7 days or with 20 attempts are given up (marked refused
with no status). One `ReplayWorker` (`CoroutineWorker`, `NetworkType.CONNECTED`, exponential backoff from
30 s, unique work `APPEND_OR_REPLACE`) returns `retry` while entries remain. Started on enqueue, on requeue and
when the owner of waiting entries signs back in; WorkManager initialises on demand.

### Devtools badge fix as a portable patch (PeriFlow WP11, VitFleet upgrade guide)

Cause: `DraggableBadge` computed `x`/`y` in composition and the `pointerInput(bounds, badge)` gesture coroutine
captured them once; each drag event wrote `stale x + delta`, so the badge never left its start. Patch:
1. Keep the position in a state holder (`BadgePosition`) and accumulate inside the drag callback from the live
   value (`freeX = (freeX + dx).coerceIn(...)`); never close over a value computed in composition. The gesture
   is keyed on the holder alone, so whatever else it reads (the clamp bounds, the layout direction, the settle
   spec) goes through `rememberUpdatedState`.
2. Read the offset only in `Modifier.offset { }`; compute the clamp bounds there too (from
   `WindowInsets.systemBars ∪ displayCutout`, the top bar height and the bottom chrome), so rotation and
   resizes re-clamp without recomposition.
3. Dock to the trailing edge at 55 % of the free height; on release, settle to the side the throw projects to
   (`x + v·0.2 s`) with a spring; store side and height fraction (`rememberSaveable`), not pixels.
4. 48 dp touch target (no `minTouchTarget = 0.dp`), `warning.subtle` background with `warning.content` text,
   alpha 0.85 at rest, hidden while the IME is up, `testTag("devtools_badge")` with `testTagsAsResourceId`.
5. Panel: `DialogProperties(decorFitsSystemWindows = false)`, background behind the bars and
   `safeDrawingPadding()` inside; a side panel from Expanded width.
6. `Modifier.systemGestureExclusion()` on the badge, after its `offset { }`: docked flush with an edge it lies in
   the back-gesture zone (about 24 dp, more with a higher back sensitivity), and with gesture navigation the
   system takes a drag that starts there: on the emulator, a swipe from the badge's centre failed or lost its
   horizontal part on some tries, while the same swipe 16 dp further in always worked. The rect follows the badge
   on every placement; Back keeps the rest of the edge.

## Rules and gotchas the docs must state

- Per-person data: a table in `:core:database` or a Preferences file of its own (`DataStoreFiles.preferences`,
  one call per file, from a `@Singleton` provider), plus a `SessionScopedStore` bound `@IntoSet` that empties it.
  Never one shared file: every DataStore write rewrites the whole file.
- `SessionCoordinator` is the only place a session ends; screens call `SessionController.signOut()`. Hosts reset
  on `SessionState.SignedOut`; never `resetTo()` by hand.
- Tokens are read per request; never cache a token in a client, a plugin or a ViewModel. A full `https://` URL
  to another host never gets the token. Mark sign-in/sign-up calls `carriesCredentials = true`. A request
  refused in one person's session is never retried with another person's token (`AuthTokens.owner`).
- Only a 401 from the refresh endpoint ends a session. Never sign out on 408/429/5xx or no answer.
- The network monitor is a hint for the UI and the queue, never a gate: always attempt the request.
- Repositories: `Flow` for data that changes, `suspend` returning `AppResult` for one-shots, `peek(id)` for a
  synchronous in-memory read so a pushed screen's first frame is final (S3.3). No `runCatching` around suspend
  calls: catch `CancellationException` first and rethrow.
- Offline-first = the database is the source of truth: UI observes the table, `refresh()` writes into it, a
  failed refresh keeps the rows. GETs otherwise rely on the HTTP cache; there is no second cache.
- Read your writes: expose the DAO's `Flow` itself, never one `stateIn` copy of it shared by every screen. Room
  tells a shared copy about a write only after the write returns, so `items.first()` right after `refresh()`
  hands back the list from before (on the Redmi, every time: an empty list under a 200). A synchronous snapshot
  for `peek` lives only while someone reads the flow.
- `enqueueOnFailure = true` only for idempotent-keyed JSON mutations; the queue is owner-scoped and survives
  sign-out; refusals are kept for the UI to show (`OfflineQueue.entries`, `requeue`, `discard`).
- WorkManager must never self-initialise (the manifest removal lives in the app's manifest, next to the
  Application that implements `Configuration.Provider`, where lint looks for it); add workers to the app's
  factory. Keep `-keepnames` on any worker class (WorkManager persists the class name).
- Room 3: `androidx.room3` imports, `@Upsert`, `@Transaction` default methods on DAO interfaces, schemas in
  `core/database/schemas/`; the database stays at version 1 until a release ships, then every change needs a
  migration and a test against the previous schema.
- Firebase: each SDK is its own feature; `firebase` alone adds no SDK. Crashlytics mapping upload only with
  `-PcrashlyticsUpload=true`. `AppLogger.e` is a breadcrumb; `recordException` is for what nothing handled.
- The analytics opt-out is applied in `Application.onCreate` to both collectors before anything is sent.
- Notifications: ask for `POST_NOTIFICATIONS` in context (`rememberNotificationPermission`), never at launch;
  `PendingIntent`s are `FLAG_IMMUTABLE` and explicit (package and component set); a tap with a link uses
  `NEW_TASK | CLEAR_TOP | SINGLE_TOP`, so the running `MainActivity` takes it in `onNewIntent` and the resolver
  checks it like any other link (no second activity, no new task); lock-screen text goes through a public
  version; channels are created off the main thread.
- Exported components: only `MainActivity` (launcher and links). Services and providers are `exported="false"`;
  the `FileProvider` shares `captures/` and `uploads/` under the cache, never the whole cache.
- Media: photo picker and `TakePicture`, no storage or camera permission; never declare `CAMERA` (it makes
  `ACTION_IMAGE_CAPTURE` require it). Copy what must outlive the picker grant; FileProvider paths are scoped
  (`captures/`, `uploads/`), never the whole cache.
- Devtools cost nothing per frame: drag state in plain state read in `offset { }`; nothing recorded in
  production (no `NetworkObserver` bound). Redaction happens on the way in.
- Anything dragged from a screen edge (a docked badge, a drawer handle, an edge slider) claims its own bounds
  with `Modifier.systemGestureExclusion()`; under gesture navigation the system otherwise takes a drag that starts
  in the back-gesture zone. Claim only the control, never a whole edge: the system honours at most 200 dp per edge.
- App lock: decided synchronously before the first frame; overlay, never a separate Activity (a separate
  Activity is bypassed by Home + back); the content stays composed under it, cleared from semantics and closed to
  keyboard focus (`focusProperties { onEnter = { cancelFocusChange() } }`), while the cover takes focus and, once
  a keyboard is on Unlock, keeps it there (`onExit` cancelled: Compose runs `onExit` only for a node focus is
  inside, never for the focused node itself), so Tab, Enter and typing cannot reach the app through it and the
  content's own `clearFocus()` cannot strand a keyboard user; `MainActivity` is a `FragmentActivity` only for
  BiometricPrompt.
