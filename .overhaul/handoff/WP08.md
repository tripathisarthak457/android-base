## Deviations from MASTER-PLAN, with evidence

1. **No Swift compiler, so nothing here was compiled** (WP file, "no Swift compiler on this machine"). The optional
   `swiftc -parse` in Docker was **not run**: only `golang:1.27-alpine` and `python:3.12-alpine` pulls are granted,
   and `docker images` has no `swift` image. The CI `ios-swiftui` job (WP13) is the first compile.
2. **Info.plist key lives in `project.yml`**, not a checked-in `BaseApp/Info.plist`: a plist inside a synced folder is
   copied into the bundle as a resource too, so XcodeGen writes it to `Config/Info.plist` (git-ignored).
   `test_target_ios` asserts the key's exact place; `accept.sh` greps `project.yml` and says why in a comment.
3. **`accept.sh` asserts the absence of `@MainActor` with an explicit `if grep …; then exit 1`**, not `! grep`, which
   cannot fail under `set -e` (Part D 14b).
4. **`SWIFT_VERSION: "6.0"`** in `project.yml` is the language mode (Swift 6); the packages use tools 6.2 for
   `.defaultIsolation` and `@concurrent`, so Xcode 26 or later is required.
5. **Plan items documented in `AGENTS.md` but not exercised in code**, because the template has nothing they fit, and
   the rule is not to ship speculative API (Part D 6, 8):
   - `navigationTransition(.zoom)` + `matchedTransitionSource`: HIG reserves zoom for a visual item (a photo, a card)
     opening into its detail; the template's lists are text rows, which push.
   - `.swipeActions`: the sample API is read-only, and a swipe action must do something real.
   - `.scrollTransition` / `.onScrollGeometryChange`: no carousel or scroll-linked header in the template.
   - `.dropDestination`: rows are `.draggable` (text out to other apps), but the template has no drop target.
   - `.onKeyPress`: screen keys come from `.keyboardShortcut` instead (⌘I details, Esc skip, Return next, ⌘1…9
     tabs), which work without first giving a view keyboard focus.
   - `TabSection`: no tab is grouped, so a `section` on `ShellTab` would be an unused parameter. iOS 18's
     `sidebarAdaptable` and `tabViewCustomization` (persisted with `@AppStorage`) are in.
   - `NavigationSplitView(columnVisibility:preferredCompactColumn:)`: neither is bound. The list's selection, which
     is the router's, decides the collapsed column on a phone; a `preferredCompactColumn` binding nothing else
     writes left the phone on the wrong column after a reselect or a deep link (review r1 finding 2, `99a6a09`).
     Nothing in the template changes column visibility, and the system's sidebar button covers the rest.
   - `withAnimation` around list changes: the views use `.animation(theme.springs.layout, value: …)` on the list
     instead, which keeps SwiftUI out of the stores and animates every change of that value the same way.
6. **`AppSprings` has no `thumb` or `dialog`** (MOTION-PLAN §5 names them). They are not on the integration branch
   yet (WP03, unmerged), and the SwiftUI template draws no custom thumb or dialog: segmented controls, toggles,
   alerts and confirmation dialogs are the system's, with the system's motion. The emitter is generic, so after
   WP03 merges `DesignTokens.MotionStyle` carries `thumb`, `dialog` and the rest; a custom control that needs one adds
   a line to `AppSprings`. Checked: WP03's `tokens/*.json` and resolver on a copy of this branch emit cleanly and
   `tests.test_target_ios` passes (22/22 at the time); only `DesignTokens.swift` must be re-emitted (`--write`).
7. **Snapshot tests (ADAPTIVE §14.8) are not added.** `swift-snapshot-testing` fails every test whose reference
   image is missing ("No reference was found on disk. Automatically recorded snapshot"), and references can only be
   recorded on a Mac. Shipping them would make every generated project's `xcodebuild test` fail until someone
   records them. The iPad layout is held instead by the static check that every feature view has a
   `.fixedLayout` `#Preview` at least 744 pt wide. Recording them belongs with the first macOS CI run (WP13).
8. **`AppLayout` constants are Swift, not tokens.** `tokens/foundation.json` has no layout widths; the Android values
   live in WP03's `AppLayout` (ADAPTIVE-PLAN §3.4), and the iOS ones match them (720 readable, 480 form) plus the
   320 pt window minimum width.
9. **The window minimum is 320 pt wide with no minimum height** (ADAPTIVE §14.6 asks for 320 × 400). SwiftUI
   gives `.windowResizability(.contentMinSize)` its minimum from a `.frame(minWidth:minHeight:)` on the window's
   root (Apple's `windowResizability(_:)` page), and that frame also constrains layout inside every window. The
   root is laid out in the safe area: 393 − 21 = 372 pt tall on a Face ID iPhone in landscape, 375 pt on an
   iPhone SE in landscape, and about 744 − 24 − 390 = 330 pt above the keyboard on an iPad mini in landscape. A
   400 pt minimum makes the content taller than its window in all three, so the bars are pushed off screen (from
   the layout rules; there is no device here to show it). Widths never fall below 320 pt (Slide Over and the
   narrowest split are 320), so the width minimum stays. A height floor for resizable windows alone would need
   `UIWindowScene.sizeRestrictions` from a scene delegate, more machinery than one number is worth.

10. **A8.2's `rowTapped → router.push` is not how the stores navigate.** A list-detail screen is a
    `NavigationSplitView` whose `List(selection:)` is bound to the tab router's `selection`; that binding is what lets
    the split view collapse to a push on a phone and keep both columns in a wide window, and what a deep link sets. A
    store that pushed on a tap would fight the split view. Stores take the `Router` only when their own work decides
    where to go (after a submit). AGENTS.md says so; the Router's documentation too (`99a6a09`, `5cbcd9b`).
11. **`--target` is passed explicitly in `accept.sh`.** The WP's acceptance runs `create_project.py --spec` without
    `--target`, which needs the CLI to infer the target from the spec's `platform`. That is new behaviour in WP01's
    `create_project.py` (and WP07's branch changes the same lines another way), so it is not landed here (review r1
    finding 6); `create_project.py` is the integration branch's, and Open issues 6 routes the change to WP01.
12. **`AppTesting`, a Core library for test targets**, is not in A8.1. One `waitUntil` was copied into every feature
    test target, and the settings test still polled the clock; Android's template has `core:testing` for the same
    reason. The checks fail if a source target or the app links it.
13. **The iOS icon needs Pillow unless the source is already App Store-ready.** Converting an image without Pillow
    would mean a PNG encoder and a resampler in the generator, which stays standard-library only; the Android icons
    make the same choice. The Pillow path is untested on this machine (no Pillow; installing it is not a granted
    download).
14. **`database` without `sample` warns instead of persisting scaffolded modules.** Neither the Android scaffolder nor
    the feature's description promise that scaffolded modules keep data on the device; building that (records, a
    `@ModelActor`, offline-first repositories, a generated model list for the app's container) without a compiler
    is more risk than the warning, which says what to add when a module needs it.

16. **Titles and labels are `Text`, not `LocalizedStringKey`** (§18 writes `LocalizedStringKey` for `appSheetHeader`,
    `appSheetDismissConfirmation` and `appActionSheet`). A `LocalizedStringKey` handed to a function in `DesignSystem`
    is resolved by `Text(_:)` in the main bundle, but every feature keeps its strings in its own package
    (`Text("…", bundle: .module)`), so a feature's title would never be translated. SwiftUI's own `navigationTitle(_:)`
    and `confirmationDialog(_:isPresented:…)` take a `Text` for the same reason. `AGENTS.md` and `docs/SHEETS.md` state
    the rule.
17. **Fitted sheets have no header or footer, and the choice sheet does not fit.** `.fitContent` measures the content's
    ideal height (`fixedSize`), and a `NavigationStack`, `List` or `Form` has none to measure. So the header (a stack)
    and the choice sheet (a `List` with `.searchable`, which needs a stack) cannot sit in a fitted sheet, and the
    footer's `safeAreaInset` is not part of the measured content. The fitted §4.1 form is one plain stack, title first
    and Save last; the choice sheet rests at `.medium` and grows to `.large` (Android: fit up to 60 %, then grow).
18. **The close button shows only on a dismissible sheet.** Android's also shows when a guard is enabled on a sheet
    people cannot close. Here that would make the close button observe the guards, which change on every update of the
    guarded view; a sheet that people cannot close has no close button, and one that should still ask passes its own
    items.
19. **Beyond §18's signatures, for Android parity:** `AppSheetCloseButton` is public (Android's `AppSheetCloseButton`
    is, and a header with items of its own needs it); `appSheetDismissConfirmation(isEnabled:onDiscard:)` carries
    Android's default question; `appActionSheet` takes `message:`. `AppSheetGuards` is internal.
20. **The SwiftUI shimmer differs from the orchestrator note's sketch** (the shimmer report's §4.2) where the sketch
    would not have done what it says:
    - **A layer effect that draws the token colours, not a colour effect over the placeholder's colour.** The sketch
      sets `.foregroundStyle(theme.colors.skeleton)` around the redacted row and mixes the pixel toward
      `highlight × alpha`. SwiftUI draws a placeholder in the text's own foreground style at an opacity of its own,
      and the row's `.foregroundStyle(contentPrimary)` wins over an outer one, so the bones would have been the
      text's colour at that opacity and the band's highlight, mixed at the same alpha, faint or inverted: the dark
      defect again. The layer effect samples four neighbours one point away to recover each pixel's coverage, then
      draws `skeleton`→`skeletonHighlight` at that coverage (Rule 53). It costs four extra samples per pixel of a
      placeholder only.
    - **`appRedacted(_:)`, a modifier, replaces the `AppSkeleton` container**, because it goes on each row's or
      card's content (the note's call-site rule), takes a Bool as SwiftUI's `redacted(reason:)` and Android's
      `AppRedacted(active)` do, and keeps the content's identity when toggled. The one "Loading" label moves to
      `appLoadingRegion()`, applied once per region; per row, VoiceOver would hear "Loading" twelve times.
    - **The shader's arguments are the band's axis and the placeholder's offset** rather than the origin, band start,
      width and tilt: the offset is computed in Swift (`SkeletonBand.offset(forOriginAt:)`), so the unit tests cover
      the same arithmetic the shader receives, and the shader does one dot product.
    - **`.metal` in `Resources/`**, not beside the Swift: only a `.process` resource is documented to compile into
      `default.metallib` (Rule 54).
    - **Swift Testing, not XCTest** (the report says XCTest): the template's tests are all Swift Testing.
    - **No Reduce Motion preview**: `accessibilityReduceMotion` is read-only in `EnvironmentValues`; the canvas's
      device settings switch it. The previews cover light and dark, right to left, and the largest text size.
    - **The clock is the outermost `appTheme()`'s**, as Android's is the outermost `AppTheme`'s, so a themed subtree
      shares the window's band.

## Rules and gotchas the docs must state

For WP12 (the iOS `AGENTS.md` already carries most of these; `docs/` should explain them):

1. **Default isolation per target.** Interface targets (`DesignSystem`, `Navigation`, every `<X>Feature`, the app)
   use `.defaultIsolation(MainActor.self)`; `AppCore`, `Networking`, `Persistence` and every `<X>Data` stay
   nonisolated, and `@MainActor` in them fails the generator's checks. Reason: JSON decoding and SwiftData work never
   queue behind a frame.
2. **`nonisolated` value types in main-actor targets.** A struct or enum that nonisolated code reads (an
   `EnvironmentKey` default, an `onGeometryChange` transform, anything that must be `Sendable`) is declared
   `nonisolated`, or its initialisers belong to the main actor and those callers do not compile. Shapes are views,
   so the one member that builds one (`AppShapes.button`) is `@MainActor`.
3. **`@concurrent` for heavy async work.** With `NonisolatedNonsendingByDefault`, an async function runs on its
   caller's actor; `APIClient.decode` is `@concurrent` so a large payload parses off the main actor. SwiftData goes
   through a `@ModelActor` per domain, never a `ModelContext` on the main actor.
4. **`CADisableMinimumFrameDurationOnPhone = true`** or ProMotion iPhones cap custom SwiftUI and `CADisplayLink`
   animations at 60 Hz. It lives in `project.yml`'s `info.properties`.
5. **Info.plist outside the synced folder**: a plist inside `BaseApp/` (a `syncedFolder`) is also copied into the
   bundle as a resource.
6. **xcconfig URLs**: `//` starts a comment in an xcconfig, so URLs are written `https:/$()/host`.
7. **Width class from geometry, not `horizontalSizeClass`**: an iPhone app in a resizable iPad or Mac window stays
   `.compact` in size class at any width. `measuresWindowWidth()` publishes `\.appWindowWidth` (600/840/1200/1600 pt,
   the Android thresholds) and, on iOS 26, holds a new class until an interactive resize ends
   (`onInteractiveResizeChange`), so the layout changes once per drag.
8. **Readable widths**: cap content with `AppLayout.readableMaxWidth` (720) or `formMaxWidth` (480) and centre it;
   the scroll view stays window-wide. No fixed or minimum width ≥ 320 in a feature (checked).
9. **Reselect detection**: SwiftUI reports a tap on the selected tab only by setting the selection binding to the
   same value; `TabShell` turns that into `onReselect` (pop to root and clear the split view's selection).
10. **Tabs**: iOS 18 `sidebarAdaptable` (bar on iPhone, top bar ⇄ sidebar on iPad) with customization persisted in
    `@AppStorage`; iOS 17 `.tabItem`; more than five tabs on iPhone go under the system's More; iOS 26 tab bar
    minimizes on scroll (`tabBarMinimizeBehavior(.onScrollDown)`), and iOS 26 bars and sheets are glass by
    themselves. Every tab needs its own SF Symbol (tested).
11. **Glass** (`liquidglass`): `appGlass(in:)` only on floating chrome (toasts), never on scrolling rows; neighbours
    share one `AppGlassGroup` (`GlassEffectContainer`); below iOS 26 it is `.ultraThinMaterial`; with Reduce
    Transparency it is the solid `surfaceElevated`.
12. **Press feedback and haptics**: scale for filled controls (press spring in, release spring with the style's
    bounce out; Reduce Motion dims instead), dim for plain buttons, highlight for rows outside a `List`; no haptic on
    plain taps, `.selection` on segment/page changes, `.success`/`.error` from toasts.
13. **Stores**: `send(_:)` never awaits; `TaskBag.latest` replaces (loads, search with `debounce`), `exclusive`
    ignores (submit, pay); releasing the store cancels its work; `.refreshable` awaits the store's own task.
14. **Toasts** queue one at a time (3 s info/success, 5 s error), announce themselves to VoiceOver, swipe up to
    dismiss.
15. **Per-app language**: the Language row opens the app's page in Settings, where iOS keeps the choice; the app
    stores nothing.
16. **Strings**: every catalog key is translated for every shipped language at generation (a gap fails generation);
    names the user typed (scaffolded tab titles) stay as typed.
17. **What the static checks cannot catch**: type errors, wrong argument labels, availability mistakes (an iOS 18
    API outside `#available`), Swift 6 isolation diagnostics, and runtime layout. Only the macOS CI build and tests
    catch those; until `ios-swiftui` is green the target stays "coming soon".
18. **Measuring smoothness on iOS**: Release build on a device, Instruments' SwiftUI and Animation Hitches templates;
    `let _ = Self._printChanges()` while debugging body evaluations, then remove it.
19. **No minimum height on the window's root.** `.frame(minHeight:)` there constrains layout as well as the
    window: iPhone landscape (372 pt in the safe area) and any window with the keyboard up are shorter than a
    useful minimum, and the content is pushed off screen. Only the 320 pt width is set (Deviation 9).
20. **`@Observable` invalidates on every assignment, equal or not.** A loop that copies a stream into state
    (`AppModel.followSettings`, `SettingsStore`) compares before assigning; the settings stream starts with the
    current value, and assigning it re-evaluated every window's root at launch.
21. **`TaskBag.exclusive` for streams a screen follows** (connectivity, settings): `.appeared` fires again after
    a pop or a tab switch, and `latest` would tear the subscription down and rebuild it each time.
22. **View initialisers run whenever the parent's body does.** `@State` keeps the first store, but the
    expression that builds a replacement still runs and is thrown away; keep initialisers to cheap
    construction. The sample tab's root builds its repository there; with the guard in 20 that happens only
    when a setting changes.
23. **No UIKit-backed content (`List`, `ScrollView`, `TextField`) as a `.mask`.** SwiftUI composes a mask from
    its own display list, and Apple does not document that UIKit-backed views draw into one (for `drawingGroup`
    it documents that they do not). Placeholders shimmer per row through a layer shader instead (Rule 51).
24. **Privacy manifest.** `<App>/PrivacyInfo.xcprivacy` declares `NSPrivacyAccessedAPICategoryUserDefaults`
    with `CA92.1` (`SettingsRepository`, `@AppStorage`). App Store Connect refuses builds that call a
    required-reason API (user defaults, file timestamps, system boot time, disk space, active keyboards)
    without declaring it; the generator's checks enforce the UserDefaults entry.
25. **`AccentColor` is generated** from the tokens with `DesignTokens.swift`; it is the app's default tint for
    whatever the themed root does not reach. A new brand colour changes both.
26. **Per-app language needs a second language.** iOS shows the language choice on the app's Settings page only
    when the app ships more than one localisation; the generator warns when `language` is on without one.
27. **Swift 6.2's default isolation and `Sendable` types.** Under the accepted SE-0466 amendment, a type whose
    primary declaration conforms to `Sendable` (or another `SendableMetatype` protocol) is not inferred
    `@MainActor`, and a nested type takes its parent's isolation. The template still writes `nonisolated` on
    public value types that nonisolated code uses, which states the intent and does not depend on the amendment.
28. **A cancelled request is `AppError.cancelled`, not a bug.** `URLError.cancelled` and `CancellationError` (a
    newer load replaced the old one, or the screen went away) map to it; no repository answers it with saved data,
    and a store's `guard !Task.isCancelled` keeps it off screen.
29. **A refresh reports its failure.** An offline-first repository answers an *unforced* load that fails with the
    saved data, but a pull to refresh returns the failure, so the screen keeps its list and says it is not newer.
    Answering a failed refresh with saved data makes it look like it worked.
30. **Yield a stream's first value under the lock that guards its listeners**, as changes are yielded, and read the
    value under it too. Yielding the snapshot after releasing the lock lets a change that landed in between arrive
    first, and the consumer ends on the stale snapshot (`NetworkMonitor.updates()`, `SettingsRepository.changes()`).
31. **Map DTOs in `@concurrent` functions.** Under `NonisolatedNonsendingByDefault` a repository's `async` method
    runs on the calling store's actor, the main one; only the decode inside `APIClient` was off it. Each data
    target's `Remote/<Name>API.swift` is `@concurrent`, so decode and mapping both leave the main actor.
32. **Preview data is debug-only.** A feature's `Previews/` files and every `#Preview` of a feature that has them are
    inside `#if DEBUG`: `#Preview` bodies compile in every configuration, so otherwise the sample data ships in the
    app. Swift packages get `DEBUG` in Xcode's Debug configuration. A preview must never build a live
    `NetworkMonitor` (it starts an `NWPathMonitor`); pass a connectivity stream that never changes.
33. **No raw values in features** (checked): no `Color(`, `.system(size:)`, numeric `spacing:`/`.padding(`,
    numeric frame sizes, `duration:`, `.easeIn…`/`.linear`, `.spring(`. Constants that are not tokens live in the
    design system (`AppLayout`, `AppSizes.heroSymbol`). The SwiftUI side of Android's raw-color/raw-dp/raw-tween.
34. **One press feedback per kind.** `ScalePressStyle`, `DimPressStyle` and `AppButtonStyle` share `PressFeedback`;
    a new style that draws a whole control applies it rather than copying the effects.
35. **Store tests wait on the state, never the clock**: `waitUntil` from `AppTesting` (Observation tracking) under
    `@Suite(.timeLimit(.minutes(1)))`. `AppTesting` is for test targets only; the checks fail if the app or a source
    target links it.
36. **Branch on the width class only for a width decision.** SwiftUI's containers (`NavigationSplitView`,
    `sidebarAdaptable`, `.inspector`) adapt the template's screens; the sample's inspector opens by default from
    `.large` up (Android shows its supporting pane at that width) until the person opens or closes it. Never branch
    inside a split view's column on the window's width: the column is narrower than the window.
37. **A form drives focus from outside a custom field**: `.focused($field, equals: .x)`, `.submitLabel`, `.onSubmit`
    on `AppTextField`, as on a `TextField`. A field's error is its accessibility hint, so VoiceOver reads it with
    the field.
38. **Module names that are members of the tab enum are refused**: `id`, `title`, `system_image`, `root`,
    `raw_value`, `all_cases`, `hash_value` (and Swift keywords), since each becomes a case of `AppTab`.
39. **`--icon` on iOS**: one 1024 × 1024 PNG with no alpha; App Store Connect refuses an icon with an alpha channel.
    The generator copies such a file as is, converts anything else with Pillow, or keeps the placeholder and warns.
40. **Agent docs follow the features.** A root `.md` file names no type, target, folder or file that the project
    does not have; feature-specific lines sit behind `<!-- <opt:x> -->` markers with neutral `opt-else` wording, and
    `test_target_ios` enforces it.
41. **Tests never touch the app's data.** App-level tests build `AppServices` with their own `UserDefaults` suite and
    an in-memory database; the path monitor is lazy, so a test that builds no screen starts none.
42. **One sheet system** (checked): every sheet is `appSheet(isPresented:/item:options:selection:onDismiss:)`, and
    content another API presents as a sheet (an `.inspector` on a phone) takes `appSheetPresentation(_:)`. A feature
    never calls `.sheet`, `.presentationDetents` or `.interactiveDismissDisabled`. It is the system's sheet, so the
    card stack, detent projection, rubber band, interactive dismissal, keyboard and VoiceOver are Apple's; the design
    style gives the surface and, before iOS 26, the corner radius.
43. **Sheet options map to Apple's modifiers**: detents → `presentationDetents(_:selection:)`; `.fitContent` → a
    `.height` of the content's ideal height (a plain stack with its title in it; a `NavigationStack` or `List` has
    no height to fit); `.nonModal(upThrough:)` → `presentationBackgroundInteraction(.enabled(upThrough:))`, and
    `.nonModal()` → `.enabled` at every detent; `contentInteraction: .automatic` scrolls a non-modal sheet's content
    first (UIKit's advice for non-modal sheets) and resizes a modal one; `dismissible: false` →
    `interactiveDismissDisabled()`; `material` → `presentationBackground` (none on iOS 26 for `.automatic` and
    `.glass`, since any background replaces the system's glass, which turns opaque at full height); `placement`
    `.leading`/`.trailing`/`.center` → iOS 27 `presentationPlacement`, compiled only by Swift 6.4 or later.
44. **Sheet anatomy**: header = `.appSheetHeader(Text(…))`, applied last to the sheet's root content (a
    `NavigationStack` with an inline title and the close button in `.cancellationAction`; `items:` for Cancel and
    Done, glass on iOS 26 by themselves); sticky actions = `.appSheetFooter { … }` (iOS 26 `safeAreaBar`, which
    softens content scrolling under it; `safeAreaInset` on the bar material before); move a detent from code inside
    `withAnimation(theme.springs.sheet)`. No haptics at detents (iOS plays none), no drag gesture of the app's own on
    a sheet, one sheet at a time from the main interface (a sheet from a sheet stacks). The ready-made forms are
    `appActionSheet` (the system's confirmation dialog: an action sheet on a phone, a popover from its source on an
    iPad, so apply it to the control that opens it) and `appChoiceSheet` (a checked list, search from six choices).
45. **Unsaved changes in a sheet**: `.appSheetDismissConfirmation(isEnabled: hasChanges) { close }` on the view that
    owns them asks "Discard changes?" before a swipe, a tap outside or the header's close button closes the sheet;
    `.appSheetDismissGuard(enabled:onAttempt:)` for a question of the app's own. Not `dismissible: !hasChanges`,
    which gives no hook to ask from. Before iOS 27 UIKit tells only the presentation controller's delegate about a
    refused swipe, and SwiftUI owns that delegate (it resets the binding and follows the detent through it), so the
    guard puts a forwarder in front of it that passes every call on and gives its place back when the view leaves.
    Replacing the delegate outright breaks `isPresented` after a swipe. iOS 27's `dismissalConfirmationDialog` asks
    only before a dismissal the person starts, never one from code, so the close button keeps asking through the
    app's own dialog there too.
46. **Platform symbols newer than the SDK**: `#available` does not stop an older SDK from failing to compile a call
    it has no declaration for. iOS 27 calls sit inside `#if compiler(>=6.4)` as well (`AppSheetPlacementModifier`).
47. **Titles and labels handed to the design system are `Text("…", bundle: .module)`.** A `LocalizedStringKey`
    crosses a package boundary as a key and is looked up in the app's bundle, where a feature's strings are not.
48. **A fitted sheet (`.fitContent`) is one plain stack**: its title first, its action last. A `NavigationStack`,
    `List` or `Form` has no ideal height to fit, so a fitted sheet has no `appSheetHeader` and no `appSheetFooter`;
    the keyboard lifts the whole sheet anyway.
49. **SwiftUI opens a sheet at its smallest detent, Android at the first listed.** A feature on both platforms sets
    `initialDetent`; a `selection` binding decides where a sheet opens when there is one.
50. **A close button inside a toolbar cannot see a guard deeper in the content**: environment values flow only down,
    and a preference would need an `Equatable` closure and a state write per change. The sheet hands its content one
    `AppSheetGuards`; each guard
    registers its latest `onAttempt` there from its representable's update, and the close button asks it before it
    dismisses. It is not `@Observable`, since it changes on every update and nothing draws from it.
51. **Loading placeholders are the real view, redacted, with one band per window** (checked): `.appRedacted()` on a
    row's or a card's content, never on a `List`, `ScrollView`, `Form` or lazy stack (the shader would redraw all of
    the scrolling content each frame, and draw backgrounds as bones), and never SwiftUI's `.redacted(reason:)` in a
    feature. The loading list is the loaded list's twin (same row view, list style and insets) and the swap is one
    step with no animation, so nothing moves. `.appLoadingRegion()` once per region gives VoiceOver one "Loading".
52. **How the SwiftUI band stays one band**: every placeholder reads its origin in `.global` space inside
    `visualEffect` (no geometry state, so scrolling writes nothing) and passes the shader the band's offset at that
    origin; a point's phase is then the same whichever view draws it. The phase runs from the leading edge, so the
    band mirrors in right to left. One `SkeletonClock` per window (the outermost `appTheme()`) holds the sweep: it
    changes twice per period, and a placeholder's own `TimelineView(.animation(paused:))` ticks only during a sweep,
    re-evaluating the shader's arguments and never the placeholder's body. The pause draws no frames; with Reduce
    Motion or no placeholder on screen the clock does not run. The sweep slows on large windows to keep a phone's
    speed (`skeletonReferenceTravel`, `skeletonMaxSlowdown`). The same geometry and timing as Android's
    `SkeletonNode`/`ShimmerClock`.
53. **SwiftUI's placeholder colour is not the skeleton token.** `redacted(reason: .placeholder)` draws each bone in
    the text's own foreground style at an opacity SwiftUI picks, and an outer `.foregroundStyle` loses to the text's
    own. The shader therefore draws the token colour itself and takes only coverage from the placeholder: a pixel's
    alpha divided by the strongest alpha one point around it, which keeps antialiased edges whatever that opacity is.
54. **SwiftUI shaders in a Swift package**: the `.metal` file goes under a `.process` resource folder, so Xcode
    compiles it into the package's `default.metallib`, and Swift loads it with `ShaderLibrary.bundle(.module)`.
    `swift build` does not compile Metal; build with `xcodebuild`. SwiftUI matches the arguments to the Metal
    parameters only when the shader first draws, so a mismatch shows on a device and nowhere before it;
    `test_target_ios` compares them.
